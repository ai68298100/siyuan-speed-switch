### 关键技术点（可复用）
1. **自律线棘轮效应**：548 KiB 这条线四天内被"按真实增量"校准 82 次（296→548 KiB，+85%）。名义叫"自律信号"（D-008），实现却是 `assert.ok` 硬失败——所以每次逼近就必须改数字，676 bytes 余量是机制产物而非真实约束。
2. **PNG 无损压缩到指定字节数**（本项目唯一可行路径）：
   - BILINEAR 降采样 + Pillow `optimize=True` → 20059 bytes，仍超 421
   - zlib 5 种 strategy × memLevel 重压 IDAT → **无增益**（Pillow 已接近最优）
   - 清理 alpha=0 区杂色 RGB → **无收益**（该图 alpha 只有 1 个取值，无透明区）
   - **zopfli 重压 IDAT → 18376 bytes，达标** ✅ 且未做调色板量化，RGBA 全彩 + alpha 完全保留
   - 对照：调色板量化（255 色 + Floyd–Steinberg）可到 2718 bytes，但 RGB rms 5.75、max 25，会有可见抖动；因归档空间已放宽，选了无损方案
3. **无法看图时的替代验证**：用逐像素 RMS/max 误差做数值评估（alpha rms=0 证明量化不损 alpha），代替视觉检查。

## 恒真断言审计：两处"永远不会失败"的断言（D-359）

继续 D-354 的审计线——**找"看起来在守护什么、实际从不触发"的门禁**。这次直接扫断言本身，命中两处：

### ① re-export 链守卫做的恰好与注释相反

`tests/workspace-diagnostics-wiring.test.cjs`：

```js
assert.equal(typeof rt[name],
    'function' === typeof rt[name] ? 'function'
    : typeof rt[name] === 'object' ? 'object' : 'undefined')
```

三元式化简后，**右侧恒等于 `typeof rt[name]` 自身** → `function`/`object`/`undefined` 三种情况全通过。而它上方的注释写着"若未来有人把导出改名或让 re-export 断链，**这里先失败**"。

**实现与声明的意图完全相反。**

### ② "审计只读"断言恒真

`tests/host/final-package-audit.test.cjs`：`assert.equal(typeof fs.readFileSync, 'function')`——凡有 fs 模块必过，零覆盖。

### 修复中踩到的自指陷阱（值得记住）

我把只读检查改成"扫描本审计源码不含写操作"，禁用词直接写成完整字面量 → **列表自身出现在被测源码里 → `includes` 恒为真 → 断言又退化回恒真**。

解法：禁用词按"**词根 + 后缀**"拼接构造（`stem + ['Sy','nc'].join('')`），使完整串不出现在源码中。

> **通用教训：任何"扫描自身源码"的断言都要防自指——被查找的模式不能以完整形态出现在断言所在文件里。**

### 实证方法：前后对比，而非只跑"改后仍通过"

改完通过**不能证明**修复有价值。我用**同条件注入 + 按失败项名称判定**：

| 注入违规 | 修复前 | 修复后 |
|---|---|---|
| 移除 runtime 导出 | 目标断言**从未触发**（仅 3 项其它测试报警） | 触发 ✓ |
| 审计文件加写操作 | 旧断言下**整个文件零失败** | 触发 ✓ |

顺带发现：案例一说明该导出并非完全无覆盖（另有 3 项测试直接用它），但那条自我标榜的"防御性自检"确实从未生效。

**另一个教训：对比脚本自身要防"两次写入互相覆盖"。** 首版脚本对"注入目标=测试文件自身"的场景先写旧版再写注入版，后者覆盖前者，导致"修复前"实际跑的是新版，差点得出错误结论。

### 审计到此的有效模式清单

1. `assert.equal(typeof X, '...')` 内嵌条件表达式 → 大概率恒真
2. 遍历集合后断言其子集为空 → 集合为空时恒真（D-354）
3. `if (!fs.existsSync(X)) return;` → 产物缺失即静默跳过（**本仓库属有意设计**：`verify:release` 含 build，CI 用 `SW_REQUIRE_PACKAGE=1` 且有 `ci-gate-consistency` 守护该设置，非缺陷）
4. 扫描自身源码的断言 → 必须防自指

## 宿主发布门禁全量审查：4 处断言什么都不检查（D-360）

### 核心发现：4 处"自造数据再断言自造数据"

| 文件 | 断言 |
|---|---|
| `release-dry-run` | `const assets = ['package.zip']` → 断言它等于 `['package.zip']`、长度 ≤ 4 |

## UI 动效语言令牌化（D-362，用户要求按 Apple 流体 / Impeccable / 前端 UI 工程三技能优化界面）

### 评估结论：不要推倒重来

`src/index.scss` **6382 行**，开头就写明设计原则：

> 紧凑、克制的现代工作界面。所有层级继续取自思源主题变量，**避免形成与宿主割裂的第二套设计语言**。

这解答了 impeccable 要求的"设计上下文"，也划定了边界——**思源用户装各种主题，硬编码配色会破坏适配**。实测基础扎实：

- 38 处 `:focus-visible`、7 处 `prefers-reduced-motion`、`contain`/`content-visibility` 各 3 处
- 过渡仅 2 处涉及布局属性

**真正的短板在动效语言**：40 处过渡声明散落成 **34 种写法**；时长分 **7 档**（0.12/0.15/0.18/0.2/0.25/0.3/0.35s）且 `.15s` 与 `0.15s` 混写；缓动**全部是浏览器默认 `ease`**（37 处）——该曲线启动偏钝，与 Apple 强调的"即时响应"相悖。

### 改动

- 4 档时长令牌（120/160/200/260ms）+ 2 条曲线（快启动平滑停止 / 对称）
- 替换 43 处过渡声明
- 消除 2 处 `transition: all`（会监听含布局属性的全部变化、无法按属性优化），按真实交互态改显式属性
- `linear` 只留给旋转加载（匀速是正确语义）

**刻意用 SCSS 变量而非 CSS 自定义属性**：颜色/圆角需随主题运行时变化故用 `--sw-*`；动效常量是固定设计值，编译期展开零运行时开销且不增体积。

### 一处有据的拒绝

进度条 `width` 过渡**保留**（会触发重排）：宽度只在渲染时一次性设置（`home-view.js:323`）、非逐帧、单元素成本可忽略；而 `transform: scaleX` 会把 3px 圆角一起拉伸变形，视觉收益为负。**已就地注释**，防止后人盲目"消除反模式"。

### 两个技术教训

1. **正则 `\b` 陷阱**：`/\b0?\.12s\b/` 匹配不到 `.12s`——`\b` 在「空格 + `.`」之间不成立（两侧都非单词字符）。改用 `(?<![\d.])` 前缀断言。**首轮替换因此漏掉 6 处省略零写法。**
2. **重跑脚本会二次替换**：`$sw-ease` 含 `ease` 子串，若不排除会被改成 `$sw-$sw-ease`。修正为 `(?<![\w-])ease(?![\w-])`。

## T-6263~T-6264 手机端三处 UI 缺陷修复（D-389）

用户给三张真机截图，三处根因互不相同：

1. **裸 SVG 尺寸失控（"刚进去大图标"）** —— 代码里看不出异常，是时序问题：插件 index.css 未作用到新插入节点时，裸 `<svg>` 退回浏览器默认 **300×150**。判定关键对照：同一帧里带 `b3-button` 类的图标有思源基础样式兜底故正常，只有裸图标（放大镜/筛选/关闭/星标/齿轮/时钟/排序）失控。
   修复：模板补显式 width/height 属性（属性优先级低于作者样式 → 正常路径零视觉变化）+ `util.js` 新增 `clampOversizedIcons()` 兜底扫描（只改实测 >32px 的；jsdom 实测恒 0 故不误触发）+ `renderModuleIcon` 同因加固。

2. **顶栏芯片文字被裁（"收藏/设置"只剩单字）** —— 真凶是 **CSS 特异性**不是缺规则：旧版纯图标规则 `.speed-switch.sw__mobile .sw__mobile-toolbar .sw__mobile-fav-btn{width:34px;padding:0}`（4 类、源码更靠前）压住后写的 3 类芯片规则。实测标签可用宽 18px，而"收藏"需 24px。
   修复：同级更后的 4 类选择器接管尺寸（`width:auto` + `min-width:34px` 保住纯图标下限 + `padding:0 10px` + `> svg{flex:none}`），**不用 !important**。

3. **组件面板卡片高度塌陷** —— 手机端单列后 gridRow 归零，但网格仍是 `.sw-home .sw-home__grid{grid-auto-rows:40px}`，每卡只剩 40px 行单元，叠加 `overflow:hidden` 内容被整片裁掉。
   修复：`grid-auto-rows:auto !important` + min-height:112px + max-height:68vh。单列下宽度档位本就无意义，高度随内容变化 = 用户要的"多尺寸"。

**方法论（可复用）**：
- 门禁要**成对**：Chromium 布局门禁能量真实布局量，但其 HTML 与生产模板是两份、会漂移 → 配一份源码契约锁模板。
- "样式未就绪"类时序缺陷用**同页因果对照**验证：`sheet.disabled = true` 后带属性 svg 必须 14×14、裸 svg 必须 300×150；若两者相同即判定对照失效并让断言失败 → 排除"门禁假绿"。
- 负向验证 4 轮全部先确认注入真的发生，均 md5 校验字节级还原。
