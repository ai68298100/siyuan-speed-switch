# 用户数据位置与设备范围（2026-10-06）

这份说明对应 T-7147，按当前代码盘点插件保存的数据边界。它描述“插件能读写什么、保存在哪里、配置包能覆盖什么”；它不承诺思源同步、跨设备冲突解决或真实升级后的宿主行为。插件持久化 key 由 `src/constants.ts` 登记，实际由思源插件存储 API 读写，目录语义为 `storage/petal/<插件名>/`。

## 数据范围

| 数据 | key/来源 | 保存内容 | 范围与设备语义 | 删除/清理 |
| --- | --- | --- | --- | --- |
| 最近使用、最近打开、最近关闭 | `sw_mru`、`sw_open_history`、`sw_closed_history` | 文档 root ID、页签/关闭记录及有界元数据 | 当前工作区的插件存储；不保存正文快照作为历史正文 | 设置或清理对应历史；容量达到上限时淘汰旧项 |
| 置顶、收藏与分组 | `sw_pinned`、`sw_favorites`、`sw_fav_groups`、`sw_fav_collapsed` | root ID、收藏分组名和折叠状态 | 当前工作区；root ID 可跨会话稳定，跨设备效果取决于宿主是否同步插件存储 | 可在设置/入口中逐项取消、删除分组或清空 |
| 快捷入口 | `sw_quick_actions`、`sw_quick_actions_defaults` | 用户排序/启用的快捷动作和默认值迁移版本 | 当前工作区设置；版本标记不是用户内容 | 恢复默认或清理插件数据；迁移版本标记由插件维护 |
| 文档集 | `sw_document_sets` | 文档 root ID、保存顺序、名称、恢复历史和场景信息 | 当前工作区插件存储；恢复时重新向宿主打开文档，不能保证目标在另一设备存在 | 设置页可删除单个文档集；配置包可导出/导入文档集 |
| 工作台布局 | `sw_home_state` | 组件实例、配置和 desktop/sidebar/mobile 三份布局 | 布局按表面分开保存；设备间是否同步由宿主工作区同步策略决定，插件不自建云同步 | 工作台重置/删除实例会清理对应实例和布局条目 |
| 缩略图缓存 | `sw_thumb_cache` | root ID 到有界 HTML 快照的缓存 | 当前工作区的本地缓存；不是正文真源，不用于跨设备恢复 | 设置中的清空缩略图只删除该缓存 key；达到容量/年龄限制会淘汰 |
| RSS 已读和关联内容缓存 | `sw_rss_read`、`sw_related_swr` | 已读标记和有界、带年龄的关联内容投影 | 当前工作区缓存；网络源本身不由插件托管 | 清空对应来源/缓存或自动按数量、年龄清理 |
| 片段回收站与分组元数据 | `sw_snippet_recycle`、`sw_snippet_groups` | 片段删除前快照、分组、别名、标签和视图偏好 | 当前插件存储；原生片段正文仍由思源原生片段保存，回收站有数量、时间和字节上限 | 回收站可清空/永久删除；分组删除不会删除原生片段 |
| 设置与 Gist 配置 | `sw_settings` | 外观、快捷键、端侧布局、组件设置以及 Gist Token/链接等设置 | 当前工作区插件存储；Gist Token 按当前实现以设置值保存，发布/读取时仅向 GitHub API 请求头发送 | 设置页清除 Token、重置设置或卸载插件；撤销 GitHub Token 需在 GitHub 侧完成 |
| 存储版本 | `sw_schema_version` | 插件存储 schema 版本整数 | 仅迁移元数据，不是用户内容 | 由插件迁移流程维护，不应手工编辑 |

## 配置包、备份和恢复边界

- 配置包是白名单导出，覆盖设置白名单和文档集；它不是 18 个存储 key 的完整镜像，也不包含缩略图、最近历史、回收站、工作台全部运行时状态或 Gist Token。
- 原生片段备份由片段实验室单独导出，并按“预览 → 选择 → 恢复”的路径处理；恢复可能只写入部分条目，界面会显示成功、失败、已打开跳过和缺失跳过计数。原生片段仍是唯一保存来源。
- 片段回收站是插件侧的有界恢复层；清空回收站是不可逆的。恢复为新草稿后保持停用，必须由用户另行保存和启用。
- 思源宿主的工作区同步、导出、回收站或备份可能覆盖部分插件目录，也可能不覆盖；当前仓库没有把它们当成已验证的插件全量备份。跨设备冲突和多 key 非原子写入仍需按 T-7118 演练。
- 配置包或片段备份的导入会先做结构、大小和版本校验；失败、取消、冲突或未核验响应保留原状态，不把“可能已写入”当作已确认成功。

## 用户可执行的清理路径

1. 在设置中重置对应设置、清空缩略图、清理历史或重置工作台布局。
2. 在片段实验室分别清空回收站、删除分组或清除 Gist Token；删除分组不会删除原生片段。
3. 需要完全停用时先关闭快捷入口和端侧布局，再按思源插件管理器停用/卸载；卸载前导出设置/文档集与原生片段备份，避免把插件存储目录是否随宿主清理当成保证。
4. 要撤销 GitHub 访问时，先在插件内清除 Token，再到 GitHub 撤销对应 Token；已发布的 Gist 需要在 GitHub 侧单独删除。

## 尚未宣称的能力

- 尚未完成真实宿主的干净安装、升级、卸载和跨设备同步矩阵；不能把本地迁移测试写成用户数据已安全迁移。
- `sw_settings` 与 `sw_home_state` 在迁移演练中仍属于 inspect，深度清洗由宿主读取路径负责；这不是“所有字段都可由配置包恢复”的证明。
- 真实思源版本、同步策略、操作系统和 WebView 可能改变目录清理、下载或恢复表现。用户反馈应附插件版本、思源版本、端侧和操作步骤，不要提交正文、完整路径、Token 或完整 API 响应。
