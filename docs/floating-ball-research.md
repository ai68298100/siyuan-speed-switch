# 悬浮球改造调研报告（FV 式可拖拽 + 弹出动作）

> T-6754 · 2026-09-21 · 状态：调研完成，待实施
> 需求来源：用户——把悬浮窗改成类似 FV 悬浮窗或手机桌面悬浮球的交互：点击打开主功能，拖动气泡时弹出可自定义的按键，拖到按键上执行。

## 1. 需求描述

将现有手机端悬浮按钮（sw__fab，单功能：点击打开页签切换器）改造为 FV/AssistiveTouch 式的悬浮球：

- **单击** → 打开页签切换器（保留现状）；
- **拖动** → 自由移动，松手吸附最近左右边缘并记忆位置；
- **拖动中** → 气泡周围弹出可自定义的动作按键，拖到按键上松手执行；
- **按键自定义** → 复用现有快捷动作配置体系（图标/标签/排序/导入导出均已有）。

### 2.2 跨产品收敛的最佳实践（标配）

1. 触摸位移阈值（约 8-10px）区分点击与拖动，抬手按位移决定是否触发点击；
2. 松手自动吸附左右边缘（上下不停靠），带回弹动画，位置持久化；
3. 贴边后半隐藏（小条/半圆），点击或轻拨唤回；
4. 闲置 3-5 秒降透明度（至约 40%，不低于 10%，不做全透），交互立即恢复；
5. 菜单展开后点击外部关闭；
6. 按键可自定义（增删排序），菜单精简为高频 3-6 项，其余走命令面板；
7. 悬浮球永远是快捷方式而非唯一路径（提供等效快捷键/命令入口）。

### 2.3 常见坑（用户抱怨收敛）

1. 误触点击 vs 拖动判定不清——拖动中球半透明 + 位移阈值；
2. 常驻球挡正文/字幕——停靠限定左右边、闲置渐隐、全屏/沉浸模式自动缩小或隐藏；
3. 移动端滚动冲突——滚动时降透明度，避开 safe-area 与底栏；
4. 穿透/锁定后找不到解锁入口——解锁必须显性；
5. 透明度 100% 全透后"球消失"——上限 90%；
6. 微信 8.0 取消可拖动浮窗被大量吐槽——不可取消"球留在原地"；
7. 无障碍：提供命令面板/快捷键等效路径，球可聚焦可 Tab 触达，标签语义完整；
8. 功能堆叠质疑——菜单只放高频 3-6 项。

### 2.4 相对系统级浮球方案的结构性优势

思源插件内嵌悬浮球**天然免疫**系统浮窗的三大顽疾：权限申请/被 ROM 后台清理杀掉/遮挡其他应用。代价是只能浮在思源窗口内——桌面端思源通常全屏使用，窗口内悬浮正是需求场景。

## 3. 思源源码分析

### 3.1 弹层层级体系（决定性机制）

- 思源使用**运行时递增计数器** `window.siyuan.zIndex` 为弹层动态分层：菜单/对话框/消息每次打开执行 `++window.siyuan.zIndex` 并写入元素（`app/src/menus/Menu.ts`、`app/src/dialog/index.ts`）；
- 静态 scss 的 z-index 很小（主要内容 0-2，全高面板 8，标题栏拖拽区 502）；
- 菜单带全屏 scrim（遮罩），scrim 的 z-index 同样来自递增计数器；
- 移动端同构（`window.siyuan.zIndex` 在 mobile 侧同样存在）。

**结论**：悬浮球必须采用**双层策略**——

1. 默认层级：**低于弹层递增计数器**（如固定 z-index 8，与思源全高面板同级），弹窗/菜单打开时自然覆盖悬浮球（符合市场调研"弹层打开时让位"的最佳实践）；
2. 不做"始终置顶"模式：递增计数器无上限，追踪它会造成层级的军备竞赛；若用户要求始终可见，提供可选的"置顶重同步"（读取 `window.siyuan.zIndex` 并 +1），但默认关闭。

### 3.2 全屏/沉浸场景

思源块全屏（protyle fullscreen）、禅模式等场景下，悬浮球应自动隐藏或缩为最小态。实现：MutationObserver 观察编辑器容器的 fullscreen 类（`fn__flex-1.fn__flex-column.fullscreen` 等），或直接监听 `document.fullscreenElement` 变化。

### 3.3 传输与 CORS（与夹具验证同源结论）

插件的浏览器上下文拉取跨源地址需要响应带 CORS 头（已实证：T-6747b 伺服器脚本带 Access-Control-Allow-Origin 才能被夹具加载器读取）。悬浮球本体不发起网络请求，无此约束；但弹出按键若包含联网类动作（如"刷新 RSS"），走既有 loader 链路即可，与悬浮球无关。

### 3.4 与现有 FAB 的关系

现手机端 FAB（`sw__fab`，index.ts:8430-8446）已具备：创建/销毁生命周期、设置开关（fabEnabled，默认关）、弹窗避让（suspendFABForDialog/ fabModalDepth 计数）、滚动显隐手势（上滑隐/下滑现）、键盘支持（Enter/Space）。悬浮球是 FAB 的**超集改造**（加拖动/弹出菜单/位置记忆/桌面端可用），不是从零新建。

## 4. 可行性结论

**可行**，全部为 DOM/CSS/Pointer Events 范畴的实现，无内核 API 依赖、无权限依赖。关键边界：

1. 只能浮在思源窗口内（不能跨应用——FV 是系统级方案）；
2. 弹层层级采用"低于弹层"策略（见 3.1），不做无条件置顶；
3. 桌面/手机均可启用（桌面为新增能力，设置独立开关，默认关）。

## 5. 风险清单

| # | 风险 | 缓解 |
| --- | --- | --- |
| R1 | 点击 vs 拖动误判 | 位移阈值 8-10px；抬手按总位移决定触发点击；拖动中球半透明 |
| R2 | 移动端与内容滚动冲突 | 球体自身 touch-action: none；页面滚动时降透明度（既有滚动手势保留） |
| R3 | 弹窗打开时球挡确认按钮 | 默认层级低于弹层（3.1 策略）；弹窗打开时球降透明度（复用 fabModalDepth 避让机制） |
| R4 | 全屏/演示模式遮挡 | 监听 fullscreen 类自动隐藏（3.2） |
| R5 | 焦点丢失（整卡重建时代遗留） | 补丁快路径天然保留焦点（不销毁节点）；整卡重建路径保留既有补偿机制 |
| R6 | 快捷动作配置为空时的空菜单 | 回退默认动作集（打开切换器 + 打开第二面板），并提示可自定义 |
| R7 | 无障碍 | 球可聚焦，Enter/Space = 单击语义，方向键微调位置（可选），等效命令面板入口常在 |
| R8 | 多窗口（思源多窗口）位置记忆冲突 | 位置按窗口尺寸比例存储（0-1 归一化），跨窗口/跨尺寸可用 |

## 7. 明确不做

- 不做系统级跨应用悬浮窗（无权限，见 §4）；
- 不做 FV 式全功能海（截图/录屏/手写搜索——超范围）；
- 不做无条件置顶模式（层级军备竞赛，见 §3.1）；
- 不做透明度 100% 全透（丢失找回问题，见 §2.3.5）。

| 参考项目做法 | 对悬浮球的吸收方式 | 边界 |

| 顶部/底部/侧边胶囊三种布局 | 悬浮球提供“边缘停靠态”和“展开态”，但不改写思源原生工具栏布局 | 悬浮球是独立快捷入口，不变成第二套编辑器工具栏 |

| 按钮拖拽排序、启用开关、预览/恢复默认 | 动作集支持启用、排序、默认预设、预览与一键恢复 | 首版不引入复杂可视化编辑器 |
| 配置导入导出与版本迁移 | 悬浮球设置随快捷动作配置统一导入导出，并带 schema/version/容量边界 | 不把临时位置、运行时展开状态写入导出文件 |
| 点击外部关闭、零按钮时仍保留导航入口 | 面板外点击关闭；动作集为空时保留“打开切换器”和“更多动作”两个安全入口 | 永远保留等效主入口，避免悬浮球被配置成不可用 |

### 9.2 不直接吸收的做法

- 复杂的自动点击序列、付费工具箱、内置业务功能集合与本项目定位不符；悬浮球只负责入口和编排。
- 直接提高固定 `z-index` 的做法不适合思源运行时递增层级；继续采用“默认让位、可选置顶”的研究结论。
- 依赖大量 CSS 覆盖思源原生工具栏的方案不纳入悬浮球，避免主题和版本耦合。

### 9.3 路线增补结论

悬浮球应被定义为“共享动作注册表的空间入口”，而不是一个独立功能集合。实施顺序调整为：先建立动作能力/可用性模型与单例生命周期，再做拖动与停靠，随后做动作面板，最后接入配置导入导出、上下文过滤、恢复默认和真机验收。
