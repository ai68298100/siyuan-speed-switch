# 小驴雷切 · 隐私政策与数据治理说明 (Privacy & Security Policy)

- 更新日期：2026-10-17
- 对应任务：T-7164（关联 T-7150 数据流清单与 T-7147 存储矩阵）
- 适用版本：v0.47.3 及以上

---

## 一、 核心隐私原则与底线承诺

小驴雷切（LvSpeed Switch）定位为**本地优先（Local-First）的思源笔记工作上下文入口层**。我们坚持以下原则：

1. **零第三方遥测与行为打点**：插件内部**绝无任何用户行为埋点、匿名统计上传或第三方数据追踪代码**。
2. **不自建云同步服务器**：插件不维护任何中间服务器，跨设备连续性完全依赖思源笔记官方的同步机制。
3. **数据流完全透明可审计**：所有网络请求仅针对明确公开的只读数据源或用户填写的自建服务地址，禁止在后台隐式静默外发。

---

## 二、 四层数据隔离与生命周期管理

插件对运行时产生和接触的数据进行严格的四层分级与物理隔离：

```text
┌────────────────────────────────────────────────────────┐
│  第一层：笔记正文与文档结构 (Note Content & Documents)  │
│  - 纯本地只读分发，绝不作为任何外部组件请求入参        │
├────────────────────────────────────────────────────────┤
│  第二层：CSS / JS 代码片段 (Code Snippets)             │
│  - 沙箱隔离，禁止 JS 自动静默执行；Gist 导出二次确认   │
├────────────────────────────────────────────────────────┤
│  第三层：外部凭据与 Token (Credentials & API Keys)     │
│  - 仅保存在本地设备；配置包导出白名单严格排除 Token     │
├────────────────────────────────────────────────────────┤
│  第四层：临时与有界内存缓存 (Bounded Runtime Caches)   │
│  - LRU 容量硬顶；会话销毁即释放，陈旧缓存可一键清空    │
└────────────────────────────────────────────────────────┘
```

### 1. 第一层：笔记正文与文档结构（Note Content）
- **处理方式**：
  - 切换器检索与大纲查看完全通过思源同源内核接口（`/api/query/sql`、`/api/outline`）读取；
  - 检索命中的正文高亮片段仅在当前前端内存视图中展示，**插件绝不将全文片段持久化写入插件存储**；
- **外发隔离**：
  - 生活小组件（天气、时钟、汇率等）发起的请求中，**严格禁止携带任何文档 ID、笔记本名称或正文内容**；
  - 片段 AI 功能调用的是思源原生 `/api/ai/editor/chat` 接口，仅在用户显式勾选“附带当前片段代码”时才提交草稿内容，不抓取全库正文。

### 2. 第二层：代码片段（Code Snippets）
- **安全沙箱**：
  - 片段实验室管理的是思源原生代码片段；CSS 仅在局部应用；
  - **JS 代码片段默认受限**，禁止在用户未审查、未显式启用的情况下自动在后台静默运行；
- **Gist 导出边界**：
  - Gist 导出功能默认将可见性设为 `public: false`（即 GitHub 的 unlisted 隐秘分享模式：仅知道 URL 可访问）；
  - 导出前会弹出完整预览，用户确认后才会发起 HTTPS 请求。

### 3. 第三层：外部凭据与 API Key（Credentials）
- **本地存储与脱敏呈现**：
  - 用户配置的 GitHub Personal Access Token 或 Miniflux API Token 仅存储在思源本地的插件设置中；
  - 界面输入框采用密码遮蔽显示（`type="password"`），设置卡片仅显示末四位字符；
- **配置导出绝对排除**：
  - 当用户使用“配置包导出（Config Pack Export）”分享自己的工作台布局时，**插件白名单机制严格剔除所有 Token 字段**，防止用户分享布局时意外泄漏私钥。

### 4. 第四层：临时与有界内存缓存（Runtime Caches）
- **有界容量控制（Bounded Buffer）**：
  - 缩略图缓存（上限 32~64 条）、外部组件响应（上限 30 分钟 TTL）、搜索防抖会话均受限于有界内存；
  - 面板关闭、切换或插件重载时，相关的计时器、AbortController 与事件监听器均被完整注销与回收。

## 三、 用户自主治理与数据清除路径

用户拥有对自己数据的 100% 控制权，随时可以审查、停止或彻底销毁数据：

| 目标操作 | 操作路径与手段 |
| :--- | :--- |
| **停止所有外部网络请求** | 在工作台（第二面板）进入“编辑布局”，移除或禁用天气、RSS、Bangumi、GitHub 贡献等外部组件；清空对应组件配置中的 URL 或城市。 |
| **清除本地已配置的 Token** | 进入插件设置 ➔ 片段实验室 / 外部组件设置 ➔ 点击 Token 输入框旁边的“清空”按钮并保存。 |
| **撤销外部已授权的密钥** | 建议前往对应的服务商控制台（如 GitHub ➔ Settings ➔ Developer settings ➔ Personal access tokens）显式点击 `Revoke` 撤销私钥。 |
| **清除所有历史与缓存数据** | 进入插件设置 ➔ 数据与存储 ➔ 点击“清除搜索历史与缓存”；或在思源数据目录中安全删除 `data/plugins/siyuan-speed-switch/`。 |
| **查看脱敏诊断（不含敏感项）** | 在第二面板底部点击“查看详情” ➔ “复制脱敏诊断”，可查看所有即将用于排障的技术元信息。 |

## 四、 安全漏洞与安全问题处理

若您在插件中发现了潜在的安全漏洞（如 XSS 注入风险、不安全的正则执行、沙箱逃逸等）：

- **请勿在公开 GitHub Issue 或论坛公开发帖披露漏洞细节**；
- 请参阅仓库专用的安全政策文件：[`.github/SECURITY.md`](../.github/SECURITY.md)，使用 GitHub 官方的 **Private Vulnerability Reporting（私密漏洞报告）** 通道直接向维护者提交私密报告。
