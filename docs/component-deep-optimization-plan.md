# 组件商店深度优化项目

状态：进行中（2026-09-18 起，31/58 已完成）

目标不是继续增加组件数量，而是逐个提升现有组件的配置、显示、交互、空态、错误恢复和移动端体验。
每个组件验收都覆盖：配置可发现性、数据范围、卡片密度、点击行为、刷新/失败、桌面/侧栏/手机。

## 统一优化维度

每个组件按同一张评分卡逐项检查，避免只改样式或只堆设置：

1. **设置与可发现性**：默认值是否合理、字段是否按内容/来源/范围/显示分组，能否用选择器替代内部 ID，敏感字段是否隐藏。
2. **数据正确性**：优先官方只读端点；明确排序、去重、时区、范围、缺字段回退和旧配置兼容。
3. **信息层级**：标题、主指标、辅助信息和来源各司其职；用户可关闭非必要路径、排名、封面或元数据。
4. **尺寸适配**：逐一检查 xs/small/medium/tall/wide/large/full，避免同一密度机械铺到全部尺寸。
5. **交互反馈**：点击目标、键盘焦点、触控热区、刷新、保存后即时更新和外链行为明确。
6. **状态恢复**：加载、空数据、超时、离线、权限不足和陈旧缓存均有确定表现，单组件失败不拖累面板。
7. **性能与生命周期**：请求有界、缓存时效符合数据变化速度、并发去重、旧请求隔离，卸载/重绘释放监听与定时器。
8. **三端、无障碍与隐私**：桌面/侧栏/手机语义一致；ARIA、对比度、reduced-motion 可用；凭据不进入日志、URL、Agent 或错误信息。

单组件完成至少需要：模型测试、生产接线证据、配置迁移/边界测试、三端结构 smoke；改动契约门禁时必须做负向注入。真实宿主才能证明的项目单独记入验收清单。

## 执行顺序

1. 数据与文档组件：数据库表格、最近文档、随机回顾、已存筛选、文档集。
2. 高频生活组件：天气、空气质量、日历、RSS/iCal、资讯榜单。
3. 统计与媒体组件：GitHub 热力图、打卡、ActivityWatch、Bangumi。
4. 基础组件：时间、电量、引言、倒数日等轻量组件。

## 第一批（首轮已交付）

- 数据库表格：搜索词与已绑定 ID 分离，显示“已选择”摘要并可清除；展示内容明确限制为主列加两项详情；
  兼容旧版 `view.table`、新版扁平视图和分组行，支持格式化数字/日期、链接、邮箱、电话、
  复选框、资源、模板、创建/更新时间、关联与汇总字段；显示字段名、可选行号及“已显示/总行”反馈。
- 最近文档：统一使用思源官方 `/api/storage/getRecentDocs`；可配置路径/序号，保留官方顺序，
  重复记录合并时不丢有效标题与路径，显示唯一文档总数并使用 1 秒短缓存。
- 随机回顾：父文档支持按全库标题/路径搜索选择；精确父文档范围优先于笔记本范围；可设置
  每批 1–6 篇和路径显示，卡片展示候选总数、范围空态，并通过“刷新全部”强制换批。
- 通用 UI：巨型 SVG 图标防护、配置表单移动端布局、刷新反馈。

## 单组件验收模板

- 设置：字段有明确名称、默认值、选择器和安全边界；无需用户手抄内部 ID。
- 显示：小/中/宽尺寸信息密度合理；超长文本、空数据和暗色主题不破版。
