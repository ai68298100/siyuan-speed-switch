## 1. 竞品与生态更新

### 1.1 Raycast v2（2026-08-25 转正，v2.1 2026-09-01）— 对切换器/命令模式最有参照价值

来源：raycast.com/changelog。

- **File Search v2 独立索引引擎**：文件名/文件夹直接进 Root Search 混排，不再需要单独命令；索引支持压缩检查点（disk 空间治理）、"深目录不再压过浅而新的文件"（**排序权重修正**——与我们"最近使用优先于路径深度"的直觉一致）。
- **Window Management 布局捕获**：`Create Layout From Current Windows` 一键把当前窗口布局存为可复放布局——与文档集"保存当前现场"同构，其"布局编辑器可补充任意可见窗口、同应用多窗"的细节值得文档集借鉴（当前文档集只记根文档，不记布局）。
- **Root Search 语义收窄**：Tab 键行为可配置；"未匹配命令时回退 Quick AI"——对应我们"`>` 进命令模式"的反向设计（无前缀时智能回退），可作候补。
- **Skills/Agents/Memory 个性化**：Agent=可复用配置、Skill=任务指令包、Profile+Memory 跨会话携带上下文。思源 3.8.3 同步支持"加载内置 Skill 资源文件"（见 §3.1），两者方向一致。
- **BYOAI 收费化**：自定义 provider/Ollama/OpenRouter 全部进 Pro。警示：本地插件不宜把"接任意模型"当卖点核心，宿主（思源）自带 AI 配置是正确边界。

### 1.2 Obsidian 生态（2026-09 周更 + 4 月 AI-native 浪潮）

来源：obsidianstats.com 周更（2026-09-13~19）、forum.obsidian.md plugin-release、blakecrosley.com 2026 指南。

- **VaultSearch / Hybrid Search MCP**：local-first 混合检索（BM25+语义+模糊）。我们的三层搜索已覆盖 BM25（受限全文）与标题层，语义层由宿主 embedding 承担（P3-3 已交付）——**架构上不落后**；但 VaultSearch 的"全本地零网络"定位提示：语义搜索失败降级链文案可强调"本地能力仍在"。
- **Similarity（全本地语义找笔记）**：同上，语义检索在 Obsidian 生态已从"联网 embedding"转向"本地模型"，佐证我们依赖宿主配置而非自带模型的选择。
- **Spaces 插件**：文件浏览器变多视图（curated 空间 / 固定文件夹空间），**每个空间记忆自己的页签与侧栏**，桌面专属。与文档集+固定槽高度同构；其"空间外笔记以暗色 visitor 显示"的过渡态设计值得文档集预检 UI 借鉴。
- **Vertical Tabs / Main Tab Commands / Tab Multi Select**：页签垂直化与页签批量操作仍是高频需求赛道。我们已covered（卡片网格+批量开关），无需动作。
- **Note Snapshots（单笔记版本控制）**：与文档集版本历史（覆盖保存留 3 版）同类；其"处理附件"的范围划分提示我们：版本历史只覆盖文档集恢复，不覆盖文档内容版本——边界声明已在 README，维持。
- **Daily Echoes（往年今日）**：我们组件面板已有「往年今日」组件，**已covered**，防重复立项。
- **Drift（AI 编辑的 VS Code 式 diff 查看器）**：AI 改动先出 diff 再人工应用——直接对应片段实验室 AI 的"手动接受"边界（见 §4.2）。
- **AI 建议"引用验证"模式**（Why/Mapa neuronal 插件）：每条 AI 建议必须通过"引用可回溯原文"的确定性验证 + 人工批准才能落库。**这是 T-6906"接受前确定性审查器"结论的生态佐证**，且给出了具体可抄的验收形态：引用核对→审查器→人工批准，三段缺一不可。
- **Dataview 停滞（0.5.70，2025-04 后无发布）→ Obsidian 1.9+ 内置 Bases 接位**：警示——重度依赖单一第三方查询引擎的生态位会被宿主收编。我们的数据库组件直接走宿主 av 端点（ADR 0058），**方向正确且已免疫此风险**。

### 1.3 浏览器工作区格局（Arc 维护模式后的世界）

来源：browser.horse、supasidebar.com、Reddit 汇总（2026）。

- **Arc 进入维护模式**（The Browser Company 被 Atlassian 收购约一年，转向 Dia）；继任格局：Zen（Firefox 系，垂直标签+工作区+Mods）、Edge（Chromium 最佳垂直标签+Workspaces+分屏）、Vivaldi（工作区+平铺+命令链）、Dia（AI 中心）。
- **"Little Arc 速览窗"无等价原生实现**：Orion 预览页签 / Vivaldi 面板只是部分替代。**我们 v0.36 的"预览打开（Alt+点击只读页签）"恰好命中这个生态空位**，README 叙事可用"peek"语言对外表达（T-6898 已完成 README 重写，此项为措辞级候补）。
- **Zen 命令面板被普遍差评**（r/ArcBrowser 迁移贴最高频抱怨）：说明"命令面板质量"是启动器类产品的护城河而非装饰——支撑我们继续投入 `>` 命令模式与键盘链路（已固化，无需新增）。
- **Boosts（按站点 CSS）没有任何浏览器原生接位**，一律靠 Stylus 扩展——印证 CSS 定制是持久独立需求（对片段实验室的定位支撑，见 §4.1）。

## 2. 悬浮球专项更新

来源：appsrethink.com、floatifyapp.com、grokipedia（2026）、switchingtomac/applealmond（iOS 26）。

### 2.1 Android 17 原生 App Bubbles（2026 最大变量）

- 任意应用（不只聊天）可创建系统级气泡：点击展开、**Pause point 可冻结气泡状态稍后恢复**、多气泡堆叠、平板桌面多任务模式。
- 限制：需应用主动实现 Bubbles API、多数场景由通知触发、无常驻侧边栏、无 AI。
- **对雷切含义**：思源 Android WebView 内的插件悬浮球不受 OS bubbles 影响（我们不在 OS 层），但"Pause point 冻结状态"的交互概念与悬浮球"恢复上次表面"（T-6869 已交付）互为印证——**无需动作，仅记账**。
- **Android 17 收紧 overlay 权限**：老悬浮应用可能失效需重新授权。雷切走宿主 WebView 内渲染不申请 overlay 权限，**天然免疫**；但"某些第三方插件快捷动作若依赖 overlay 类能力会失效"值得写进兼容矩阵的观察项。

### 2.2 第三方悬浮生态（竞品分类学增量）

- **Arc AI Screen Assistant**（28k 安装）：边缘侧滑 AI 侧栏，屏幕感知（Accessibility 读屏）→ 六工具（摘要/提取/写作/聊天/闪卡/通话）；**per-app 可见性与银行 App 屏蔽**、自动收起计时、250+ 社区动作。对我们的候补点：**"per-app 隐藏悬浮球"**（当前只有场景让位与滚动显隐；按宿主前台文档/插件页自动隐藏是同构扩展，候补池）。
- **Floatify**（2026 年最活跃）：单击/双击/长按三手势独立映射动作；长按菜单**放射/垂直/网格/面板四种布局**——我们已有 arc/vertical/grid+fits 降级链（T-6785 方向感知已完成），四种布局中"panel"形态未覆盖，属低优候选；闲置透明度我们已有。
- **Overlays - Floating Launcher**：**按屏幕方向分别记忆尺寸/位置/透明度/点击穿透/Z 序** + Tasker 自动化触发。我们的 xRatio 比例恢复已覆盖旋转，但"按方向记忆不同停靠位置"未做——真机旋转验收（B-004）后如用户反馈需要再立项（候补池，P3）。
- **Floatee**（50 万安装，2026-02 仍更新）："裁剪屏幕内容→发 AI 浮窗回答"模式。与快速捕获+AI 是两个方向，不符合"只读组件+受控写"边界，**不采纳**。
- **FV fooView** 仍是品类标杆（500+ 功能，4.4★，500 万安装）——前序报告已深读，无新情报。

### 2.3 iOS 26 AssistiveTouch（设计语言层面情报）

- **Liquid Glass 设计语言全面铺开**；iOS 26.4 新增 Reduce Bright Effects（交互元素点击高光刺眼的减光开关）。**直接支撑皮肤层 T-6797"苹果液态玻璃"原型的时代正确性**——原型已出（`docs/design/skin-prototypes.html`），本轮情报确认其参照系仍是 2026 主流，无过时风险。
- AssistiveTouch 手势自定义大幅扩展（自记录手势回放）；**闲置透明度社区共识值约 30%**——我们闲置降透明度默认值可对照复核（当前值待查证，属参数级候补）。
- 头部追踪/表情控制为无障碍方向：超出插件边界，**不采纳**。

## 4. 统一平台与片段实验室专项

### 4.1 Stylus 2026 现状（CSS 片段管理的最大参照）

来源：Chrome/Firefox 商店镜像、extspot 评价分析（2026-08 数据）。

- 仍活跃：Chrome 稳定版 2.3.28（2026-05）、Firefox beta 3.4.11（2026-08，**MV3 迁移完成**：declarativeNetRequest、sidePanel 权限）；社区仓库 userstyles.world 持续供给主题。
- **功能面**（片段实验室可对照）：usercss 格式安装/导出、**整库备份且与其他管理器互通**、自动更新开关、双代码验证器（Stylelint/CSSLint-mod，规则可配置）。
- **用户痛点 Top**：① 崩溃与存储不稳定致**数据丢失/损坏**；② UI 不直观；③ **无元素选择器**（新手难定位要改的选择器）；④ 旧样式霸榜难找可用样式。
- **对片段实验室的直接映射**（多数可进 T-6896 收口或候补）：
  1. **存储损坏=头号差评**——我们的 storage 版本戳+消毒不动点（PERSISTENT_KEYS 体系）是差异化卖点，应写进实验室能力说明（T-6896 的"可见能力说明"项）。
  2. **备份/导出互通**：片段导出格式若兼容 usercss 的元数据头（`/* ==UserStyle== */`）可获得现成生态——**候补立项（低优）**：导出 usercss 头注释，纯增量、零宿主依赖。
  3. **验证器可配置**：T-6906"接受前确定性审查器"可直接采用 Stylelint 规则子集作审查器内核（MIT 许可，允许 vendor 或声明依赖）。
  4. 元素选择器缺失是全行业痛点——思源 DOM 稳定性高于任意网页，**不做的理由也成立**（范围纪律），记入未采纳清单。
  5. "旧样式霸榜"→ 实验室片段目录排序按更新时间而非创建时间，防同样问题（参数级小任务，候补）。

### 4.2 AI 代码助手审查 UX（T-6862 多轮体验的形态依据）

来源：aitoolskit.io 2026 榜单、digitalocean Cursor 实测、Copilot 文档类来源。

- 2026 年已分化为两类：**编辑时内联审查**（Copilot inline/Cursor）与**合并时异步审查**（CodeRabbit 等）。共同形态要件：
  1. **结构化逐文件摘要 + 变更走查图**（CodeRabbit walkthrough）——对应片段 AI 多轮时**每轮输出"改动摘要+影响点"而非只给代码**。
  2. **✔/✗ 逐条接受拒绝**（Cursor 实测形态）——我们的"手动接受"已有，可细化到"逐片段/逐规则粒度接受"。
  3. **上下文边界诚实声明**：Copilot review 只看 diff 不看全库（breadth over depth），Cursor 看全库索引——对应片段 AI 的上下文窗口=当前片段+目录摘要，**不承诺理解全库片段**，该边界应写进能力说明（与 §4.1 第 1 点同批）。
  4. 噪声治理：CodeRabbit 需配置抑制自动生成文件的评论——对应 AI 迭代对"已禁用 JS 片段"不做无效建议（规则层短路）。
- **与前序报告衔接**：T-6906 已定"本地短规则+接受前确定性审查器，不新增宿主端点"；本轮新增生态佐证两条——Obsidian Why 插件的"引用验证+人工批准"三段式（§1.2）、Cursor/Copilot 的逐条 accept/reject 形态。**T-6862 的多轮体验设计建议采用：每轮=摘要+diff 块+逐条 ✔/✗，审查器在批准前跑**。

## 5. 搜索与交互机制（跨类补充）

- **速览/peek 是普遍缺口**：浏览器生态无 Little Arc 等价物（§1.3）；Capacities hover 预览成熟但经历多轮修复（§3.2）。我们的第一面板预览（T-6895）+ Alt 预览打开组合在同类中处于第一梯队；补一条失效回执负向验证即可（§3.2）。

- **CJK/拼音检索**：本轮无新情报（R2 已深读 tiny-pinyin 等）；Obsidian VaultSearch 的 BM25+模糊混合与 R2 结论一致，无翻案证据。
- **垂直标签/工作区**：浏览器战场验证"分组折叠+密度+视图模式+排序"四件套（组件面板已交付 T-6851 持久化）是收敛解，无新增维度值得抄。

## 7. 未采纳清单（防反复）

| 项 | 理由 |
| --- | --- |
| Floatee 式"裁屏→AI 浮窗" | 越出只读组件+受控写边界；依赖读屏权限 |
| iOS 头部追踪/表情控制 | 无障碍系统级能力，插件不可达 |
| Raycast BYOAI 式自定义模型接入 | 宿主 AI 配置已承担；插件自建模型面违反资源自律 |
| Stylus 式元素选择器 | 思源 DOM 稳定且实验室已有目录定位；维护成本大于收益 |
| 语义检索改插件自带本地模型 | 宿主 embedding 配置已是正解（P3-3）；自带模型体积与维护不可承受 |
| 悬浮球接入 OS 级 Bubbles API | 思源插件无 OS 层入口；WebView 内悬浮球已覆盖需求 |
