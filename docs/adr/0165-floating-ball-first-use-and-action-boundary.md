# ADR 0165：悬浮球首次使用引导与动作扩展边界

- 日期：2026-10-10
- 状态：accepted
- 关联任务：T-7238
- 关联： [ADR 0163](0163-first-use-guide.md)、[悬浮球 UI 规格](../floating-ball-ui-spec.md)、[悬浮球竞品调研](../floating-ball-competitor-research-2026-09-22.md)

## 背景

悬浮球已经具备端侧开关、位置记忆、拖动命中、更多动作、数字槽、快滑、双击/长按、预设和导入导出。功能完整并不代表用户知道第一步：悬浮球默认关闭，轻触、拖动、半隐藏和更多面板分别有不同语义，设置页还同时包含端侧独立字段与三端共享字段。继续增加动作而不补齐上手路径，会让用户把“没有显示”“没有反应”和“动作不可用”混为一谈。

本任务只收口首次使用和动作发现边界，不把悬浮球改造成系统级启动器，也不通过强制教程打断搜索或编辑现场。

## 决策

### 1. 首次使用入口

1. 悬浮球仍默认关闭；旧版 `fabEnabled` 迁移后保持原值。设置页在桌面和手机端均关闭时显示内联的“第一次使用悬浮球？”卡片，提供“开启桌面悬浮球”和“开启手机悬浮球”两个明确按钮。
2. 启用按钮只写入对应端侧的 `enabled`，不重置位置、动作、手势或共享外观；成功后刷新运行中的 portal、预览和设置控件，并把焦点放回对应开关。
3. 引导保持可跳过、可重复打开和离线可用。平台“快速开始”增加悬浮球步骤；更多动作面板和悬浮球设置保留帮助/管理入口。首次启用不自动打开动作面板，不强制弹窗，不请求网络。
4. 引导文案必须说明当前端侧，而不是暗示桌面和手机共用一个开关；设置页将端侧字段与“桌面和手机共用”的行为字段分组。

### 2. 必须说明的操作语义

引导和悬浮球设置至少说明下列可复现行为：

| 操作 | 结果 | 失败或恢复路径 |
| --- | --- | --- |
| 轻触、Enter 或 Space | 执行当前端主点击动作，默认打开切换器 | 主动作失效时安全回退切换器 |
| 拖动超过 8 px | 进入首层目标选择；球体跟随指针，目标保持稳定 | 取消、失焦或捕获丢失回到原停靠位置 |
| 拖到动作目标松手 | 执行动作，球体回到拖动前位置 | 不支持、提供方缺失或失败显示原因，不改变已保存位置 |
| 空白处松手 | 保存新位置；吸附开启时贴最近左右边缘 | 位置始终限制在可视区、安全区和宿主边界内 |
| 右键或 Shift+F10 | 打开“更多动作” | Escape 或点击面板外关闭并恢复球体焦点 |
| 贴边后半隐藏 | 点击、聚焦或边缘恢复把手唤回 | 全屏、弹层让位和宿主不可见原因优先，不能误显示 |
| 手机端向下/向上滚动 | 向下滚动隐藏、向上滚动恢复悬浮球（开启滚动隐藏时） | 更多面板自身仍可滚动；`data-prevent-swipe` 保证拖球不触发思源侧滑 |
| 已绑定双击或长按 | 双击在约 300 ms 窗口内执行绑定动作；长按约 550 ms 执行绑定动作 | 未绑定时单击保持零延迟；拖动和长按互斥 |

引导不把未启用的双击、长按或快滑写成默认能力。当前默认主点击为 `switcher`；默认双击和长按为空；快滑默认上滑打开“更多动作”、下滑快速记录、左滑上一个页签、右滑下一个页签；手机离边停靠默认关闭。上述默认值必须与运行时真实语义一致。若上滑固定打开“更多动作”，设置页必须显示为固定语义或禁止选择其他动作，不能保存一个运行时永远不会执行的值。

### 3. 配置边界与保存反馈

- **端侧独立**：`enabled`、`position`、`clickAction`、`actions`、`digitSlots`。切换“编辑端侧”只刷新这些字段；位置导入导出不跨设备覆盖。
- **共享行为**：尺寸、边距、闲置透明度与延迟、半隐藏、吸附、滚动/全屏/弹层让位、拖动阈值及手势策略。控件旁明确“桌面和手机共用”，手机专属的侧滑避让单独标明适用端。
- 滑杆拖动只更新预览，释放或 `change` 才写入；开关、主点击、动作启停、排序和手势选择写入后立即刷新 portal，并给出“已应用到桌面/手机”的轻量回执。
- 预览只模拟动作，不打开文档、不写入笔记；预览应显示当前端、停靠边、首层动作数、更多动作数和不可用原因。
- “恢复当前端侧默认动作”只改当前端动作；“恢复共享外观与行为”必须确认并明确影响桌面和手机；导入配置保留本机位置，旧版纯动作文件不改悬浮球配置。
- 能力状态使用 `可用 / 待验证 / 不可用 / 不支持`。提供方缺失、宿主版本不足、未声明移动端能力和用户停用都保留原因及恢复入口，不静默删除配置。

### 4. 动作扩展边界

1. 首层最多 5 个配置动作，固定保留“更多动作”；默认只放已有稳定内建动作，低频和未知动作进入更多面板。动作目录继续复用 quick-action registry 和统一 executor，不复制第二套 handler。
2. 下一小版本优先补高价值、可能力检测的思源命令（大纲、书签、标签、收集箱、反链、最近文档、全局搜索等）以及已有同步、模板、快速记录动作的前置条件和回执；不抬高最低思源版本，缺失能力显示原因。
3. 后续可增加“阅读 / 写作 / 整理 / 导航 / 手机”预设、最近使用和固定排序，但预设只覆盖明确选择的端侧，并提供预览、取消和恢复默认；已有自定义动作不被静默覆盖。
4. 对象先选后操作、批量打开/关闭/收藏和可取消的逐项回执列入后续评估，不塞入拖动环的热路径。动作别名、动作级快捷键、深链接和 CLI 等待稳定 command ID 与焦点回归契约后再做。
5. 不新增系统级跨应用覆盖层、剪贴板历史、自动点击脚本、截图/录屏或无稳定 API 的护眼/全屏动作；这些能力超出思源插件边界或缺少可验证宿主合同。

## 验收与证据边界

- 设置契约覆盖：两端默认关闭时首用卡片出现；点击启用只改目标端；切换端不污染另一端；共享字段的文案与保存范围准确。
- 手势契约覆盖：8 px 分流、空白落点保存、动作命中回停、半隐藏恢复、Escape/面板外关闭、双击/长按互斥及默认未绑定。
- 动作契约覆盖：选择器保存的动作引用与运行时按同一稳定 ID 解析；`id` 与 `value` 不同的宿主命令/提供方动作必须可执行；固定上滑语义不能接受永远不会执行的配置。
- 新增或修改门禁按 `docs/gate-audit-checklist.md` 做删除式负向验证，再恢复源码并复跑正向测试。Chromium/模拟视口只证明 DOM 和几何；Android 触控、旋转、键盘、最窄真实桌面和读屏仍按 `BLOCKERS.md` B-004/B-005 后置。

## 后果

首次使用步骤变得可见且可回看，设置不会把端侧字段和共享行为混在一起；同时动作扩展仍受到首层容量、能力检测、统一执行器和真实宿主证据约束。新增动作数量会受这些边界限制，但可用性、失败解释和升级兼容性更容易保持一致。

## 验证记录

- 悬浮球测试文件 180/180，连同内核接线文件的组合回归 217/217；包含稳定 ID 冲突、端侧能力复核、固定上滑、首用启用、刷新回读和快滑选择器随当前端侧筛选。
- 删除 `findFloatingAction` 稳定引用、`select.disabled` 固定语义、桌面能力筛选、首用卡显隐和 edgeAvoid 桌面禁用条件后，目标契约均按门禁预期失败；本轮另外对固定上滑和禁用状态做两轮删除式注入，失败项分别为对应测试名，源码恢复后 SHA-256 一致。
- 浏览器/内存夹具只证明 DOM、模型和接线；真实 Android、读屏、旋转和最窄桌面仍不标记为已验收。
