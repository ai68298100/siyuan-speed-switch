# ADR 0161：第一面板预览栏填充可用高度

- 日期：2026-10-10
- 状态：accepted
- 关联任务：T-7234
- 关联基线：T-6938、T-7222、T-7233、ADR 0082

## 背景

第一面板桌面截图中，右侧文档预览在内容较短时只保持固定的阅读卡高度，卡片下方直到工作台之间留下大片空白。现有预览正文已经具备独立滚动、固定头部、固定和窗内查找，不需要再引入无关统计或装饰模块；问题是预览列没有消费滚动区的剩余高度。

## 决策

1. 桌面宽容器继续使用单一文档预览窗格，右侧列延伸到当前滚动区的可用底部；短文档也保持完整的表面边界。
2. 预览高度使用 `.sw__scroll` 的尺寸查询高度（`100cqh`），这样高度随弹窗/面板变化，不新增设置、不持久化状态，也不改变 34% / 280～480px 的列宽。
3. 左侧结果列表变长时，预览不跟随结果列表无限增长；通过 `max-height: 100cqh` 保留固定可用阅读高度，正文 `.sw__doc-preview-body` 继续独立滚动。
4. 680px 以下容器、侧栏和移动端继续沿用既有单列/隐藏预览策略；非文档对象、加载、失败和空内容回执不变。

## 取舍

不在空白区域增加无真实数据来源的统计、推荐或操作卡片。预览是“看清再行动”的连续阅读表面，已有固定和查找入口足以覆盖当前对象的操作需求；未来若要展示文档元信息或相关操作，应另立任务并复用真实数据与现有动作回执。

## 验证

- `tests/e2e/doc-preview-layout.spec.mjs` 覆盖短内容铺满底部、长结果列表不拉长窗格、正文独立滚动、主题、窄容器和短窗边界。
- `tests/panel1-urgent-fix.test.cjs` 锁定右栏填充规则；删除 `min-height: 100%` 或 `height: 100cqh` 的负向注入会精确失败，并在验证后按 SHA-256 恢复源码。
- 现有 `doc-preview-behavior`、`doc-preview-find`、TypeScript、构建和完整测试继续通过。
