# ADR 0215：工作上下文入口层定位与三阶段路线

- 日期：2026-10-16
- 状态：accepted
- 任务：T-7290

## 背景

小驴雷切已经包含切换器、工作台、片段实验室、悬浮球、组件商店、Agent 和多个可选数据源。继续横向增加能力会弱化主路径，也无法解决第二面板体量过大、真实用户证据不足和对外说明漂移的问题。

## 决策

1. 产品主语固定为“思源的工作上下文入口层”，核心闭环为找到、预览、打开、执行和恢复。
2. 第一面板是核心入口；第二面板定位为轻量 compact glance board，查看态与编辑态分离；第三面板和悬浮球继续遵守各自的安全边界。
3. 近期路线按“可信核心路径 → 工作台价值密度与生态 → 受控智能与可信交付”推进。现有 T-7163、T-7168、T-7144、T-7115～T-7118 复用原任务；T-7291 只承接 compact visual parity，不为相同能力重复编号。
4. 第二面板视觉小批只调整已有组件的尺寸层次、壳层显露和状态标记；不新增数据源、自由画布、归档、小地图或任意查询语法。
5. 组件数量、AI 范围和外部服务数量不作为进度指标。真实用户、真实宿主、真实 provider 和升级回退证据优先于原型或受控响应。对 Agent 既有动作不改写为“尚未实现”，新增或扩展动作才按真实确认、权限、取消和失败回执证据放量。
6. 自由画布、AI 推荐/自动写入、云同步、遥测、任意 SQL/JS 和系统级跨应用浮窗继续后置，未来若重开必须有独立用户任务、权限边界和回滚方案。

## 后果

- 下一版以高频路径、compact 工作台和可信材料为主，减少功能堆叠。
- 默认七组件保留为默认组合，但不宣传为七项全部首屏可见。
- T-7144 只有在真实频率或问题记录成立后继续组件精修；没有缺口则以证据销号。
- 对外 README、截图、商店说明和支持文档统一使用工作上下文平台叙事。
