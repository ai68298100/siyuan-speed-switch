# ADR 0050：样式切片覆盖门禁（P1-3）

- 日期：2026-09-17
- 状态：已接受（T-6293）
- 范围：新增 `tests/style-slice-coverage.test.cjs`

## 背景（由实测数据导出，非凭感觉立项）

P1-2 的覆盖审计发现一个真实缺口：逐个从清单删除样式切片，**10/10 全部零失败**。
删掉 `03-chunk`（**1940 行，约占样式 30%**）后 5872 项测试照样全绿；
只有清空到只剩 tokens 才触发 128 项失败。

结论：**没有任何单一切片被独占锚定**，样式断言分布稀薄，门禁拦不住"整段样式被删"。
这不否定 P1-2 本身（产物 CSS 逐字节未变、行为零漂移），但必须补上。

## 决定

新增数据驱动的切片覆盖门禁，为每个切片动态求取**独占锚点**——只出现在该切片、
不出现在其它任何切片中的行——并要求这些锚点确实存在于组合视图中。
于是删除任一整段切片，其独占锚点必然从组合视图消失，门禁精确拦截。

锚点候选两类：

1. **顶层选择器行**（列 0 起始、以 `{` 结尾）；
2. **SCSS 变量声明** —— `00-tokens` 不产出任何 CSS、没有选择器，它的"内容存在"
   只能靠 6 条动效令牌声明来锚定；令牌被删同样必须被拦下。

实测各切片独占锚点数：`00-tokens:6, 01:53, 02:37, 03:121, 04:22, 05:54, 06:48,
07:30, 08:23, 09:47`。

## 遵循的门禁方法论（`docs/gate-audit-checklist.md`）

- **数据驱动**：锚点由源码动态求得，不硬编码切片清单，后续重命名/增删切片无需改本文件。
- **非空自检**：先断言切片数 ≥5、锚点总量 ≥20，防止"正则失效导致恒绿"。
- **下限不钉死进度**：只要求每切片 ≥3 条独占锚点，不用 `>=35` 这类会随进度腐烂的阈值。
- 另加一条**删除模拟**用例，直接证明"锚点当前确实在组合视图里"（门禁已上膛）。

## 验证（用 P1-2 那把尺子复测，确认缺口真的闭合）

- 新增 3 项测试全绿；"删除模拟"用例证明门禁已上膛。
- **负向验证**：复用 P1-2 的 `.tmp/scss-coverage-audit.py`，逐个删除切片后跑全量套件：

| | P1-2 时 | 本批之后 |
|---|---|---|
| 逐个删除切片触发的失败数 | **10/10 全部 0** | **10/10 全部 1**（精确命中本门禁） |

同一把尺子、同一批切片，从"全绿"变成"全红"，缺口闭合得到实证而非声称。

- 计数同步：测试 5872 → 5875、测试文件 171 → 172（双语 README 与 release-readiness）。
- `verify:release` 全链绿。

## 边界

本门禁只保证"整段切片不会被静默删除"，**不保证样式语义被正确断言**——
单个声明被改（如颜色写错）仍不在其职责内，那属于既有 store-* 系列契约与真机验收。
