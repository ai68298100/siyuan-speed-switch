# ADR 0149：T-7151 宿主规模性能证据边界

- 日期：2026-10-07
- 状态：已采纳
- 任务：T-7195

## 背景

T-7151 原计划把 100/500 页签规模纳入真实思源 E2E。仓库现有首开用例仅创建两篇临时文档；插件公开测试入口只有 `whenReady` 与 `openSwitcher`，没有公开页签创建 API。思源移动端前端将页签数截在 32，桌面设置控件上限也是 32；隔离桌面探针随后实测 `maxOpenTabCount` 请求/回读为 `1→1`、`32→32`、`500→32`。`scripts/e2e/lib.mjs` 的 loopback 检查只能确认本机地址，不能区分 E2E 内核和用户个人内核。

## 决策

1. 不把 100/500 篇文档、搜索结果或合成 DOM 称为 100/500 个真实页签。
2. 先在受标记保护的隔离工作区和本轮专属端口中验证桌面 `maxOpenTabCount` 的运行时/API上限及真实已打开页签数量；确认 port listener 属于本轮启动进程后才能发写请求。该配置探针已确认桌面有效上限为 32。
3. 改用宿主允许的 32 页签上限做真实页签 p50/p95 观测；100/500 仅可作为单独标注的文档搜索/结果规模场景。
4. 不修改插件生产代码暴露额外测试钩子来绕过宿主行为；测试通过真实 UI 与宿主 `openTab` 路径执行，并在 `finally` 中清理隔离笔记本。
5. 用户个人工作区与 6806 等个人内核端口一律不得作为规模测试目标。

当前仓库提供 `scripts/e2e/host-scale-probe.mjs` 作为显式 opt-in 的配置探针。它要求预先存在带 `swss-e2e.json` 的工作区，启动前检查端口为空，启动后核对监听 PID，再执行配置回读；它不创建文档或页签。

## 后果

T-7151 的验收名称和报告必须区分页签规模与文档搜索规模。桌面和移动端当前均按 32 个打开页签上限记录；隔离桌面 UI 基准已完成 32 次连续打开，并独立完成过滤与激活各 32 个样本（综合打开 p95 2536ms、过滤 p95 496ms、激活 p95 526ms、页面异常 0）。该决策避免产生宿主不支持或没有实际执行的性能证据。
