# ADR 0149：T-7151 宿主规模性能证据边界

- 日期：2026-10-07
- 状态：已采纳
- 任务：T-7195

## 背景

T-7151 原计划把 100/500 页签规模纳入真实思源 E2E。仓库现有首开用例仅创建两篇临时文档；插件公开测试入口只有 `whenReady` 与 `openSwitcher`，没有公开页签创建 API。思源移动端前端将页签数截在 32，桌面设置控件上限也是 32，桌面运行时/API是否能突破该值尚未在隔离宿主实测。`scripts/e2e/lib.mjs` 的 loopback 检查只能确认本机地址，不能区分 E2E 内核和用户个人内核。

## 决策

1. 不把 100/500 篇文档、搜索结果或合成 DOM 称为 100/500 个真实页签。
2. 先在受标记保护的隔离工作区和本轮专属端口中验证桌面 `maxOpenTabCount` 的运行时/API上限及真实已打开页签数量；确认 port listener 属于本轮启动进程后才能发写请求。
3. 若宿主有效上限确为 32，改用宿主允许的上限做真实页签 p50/p95 观测；100/500 仅可作为单独标注的文档搜索/结果规模场景。
4. 不修改插件生产代码暴露额外测试钩子来绕过宿主行为；测试通过真实 UI 与宿主 `openTab` 路径执行，并在 `finally` 中清理隔离笔记本。
5. 用户个人工作区与 6806 等个人内核端口一律不得作为规模测试目标。

## 后果

T-7151 的验收名称和报告必须区分页签规模与文档搜索规模。桌面真实上限在隔离实测完成前保持未知；移动端不声称支持超过 32 个打开页签。该决策避免产生宿主不支持或没有实际执行的性能证据。
