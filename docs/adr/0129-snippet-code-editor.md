# ADR 0129：轻量文本编辑器增强，草稿事务保持统一

- 状态：已采纳，轻量路线完成；CodeMirror 暂缓
- 日期：2026-10-04
- 任务：T-6992 / T-6974

## 决策

1. 暂不采用 CodeMirror 6。实际构建显示其完整依赖会产生约 669 KiB 的编辑器动态 chunk，使 `package.zip` 超过现行 576 KiB 硬上限；不放宽上限，也不引入 CDN 或远程运行时依赖。
2. 片段实验室继续使用稳定的 textarea，并在其周边补齐可控的行号 gutter、滚动同步、基础括号诊断和 Cmd/Ctrl+S。编辑内容、撤销重做、查找替换、导入、AI 接受、预览和保存继续共用现有草稿事务。
3. 括号能力只提供轻量提示：识别 CSS/JS 常见括号是否成对，并跳过字符串与注释；结果复用现有诊断状态文案，问题数量复用现有错误状态文案，不伪装成完整语言服务，也不改变保存或预览语义。超大内容沿用现有边界并复用已有超大内容提示。
4. 轻量增强必须可在真实宿主中验证输入、行号更新、快捷保存、窄屏滚动和销毁清理；textarea 始终是可编辑的稳定降级路径。

## 包体与验证

CodeMirror 方案的测量结果保留在当期开发账本：动态 chunk 约 669 KiB，归档约 772 KiB，明确超过 576 KiB 上限。轻量方案不增加运行时依赖，主入口 raw、压缩条目和归档继续独立验收；构建不得产生未登记的自动 vendor chunk。

纯模型测试覆盖行号生成、括号匹配、不平衡诊断、空内容和超大内容边界；真实思源 E2E 验证 textarea 行号、输入更新、快捷保存和销毁清理。JSDOM 不替代真实宿主布局或输入法验收；Android 仍属 B-004。
