# ADR 0066：悬浮球作为共享动作注册表的空间入口

- 日期：2026-09-21
- 状态：已接受
- 关联任务：T-6755、T-6756
- 关联设计：`docs/floating-ball-ui-spec.md`

## 背景

现有悬浮按钮只在手机端显示，使用一个固定右下角的 `div[role=button]` 打开切换器。仓库已经有成熟的快捷动作注册表、端侧能力声明、动作选择器和执行器。若为悬浮球重新建立动作类型、执行器和配置，会产生两套入口语义，并且第三方动作的可用性会漂移。

参考 toolbar-customizer 后，悬浮球还需要处理桌面端、位置记忆、动作溢出、动态宿主重绘、设置迁移、弹层让位和无障碍路径。这些问题不能通过继续扩大现有 FAB 的 CSS 或点击回调解决。

## 决策

### 1. 复用动作定义，独立保存空间入口配置

悬浮球直接消费 `IQuickAction` 与 `createQuickActionRegistry`。动作名称、图标、提供方、支持端和 handler 只有一个来源；悬浮球只保存动作 ID、首层/更多分区、顺序和端侧启用状态。

悬浮球配置放入现有 `SETTINGS_KEY` 的版本化 bounded shape，不新增分散的持久化 key。旧 `fabEnabled` 映射到 `enabled.mobile`，保留旧字段读取兼容。动作导入导出通过现有快捷动作传输流程扩展 `floatingBall` 命名空间，运行时位置和展开状态不导出。

### 2. 采用显式单例控制器和状态机

生产 DOM 使用单例 portal：`.sw-fab-root[data-surface][data-state]`，内部为真正的 `<button>` 触发器、首层目标组和独立的更多动作面板。控制器统一管理 pointer capture、`pointercancel`、窗口失焦、定时器、MutationObserver、弹层深度和销毁。

状态至少包括 `docked`、`collapsed`、`dragging`、`targeting`、`executing`、`more`、`suspended` 和 `hidden`。所有退出路径回到同一个 cleanup/snap 函数，防止重绘或异常后产生重复节点和残留监听器。

### 3. 点击和拖动使用 8~10 px touch slop 分流

位移没有超过 touch slop 时，轻触、Enter 或 Space 永远执行切换器；超过阈值才进入动作环。拖动结束未命中目标只吸附，不执行切换器。Pointer Events 负责鼠标、触摸和笔，球自身使用 `touch-action: none`，页面其他区域不拦截滚动。

### 4. 首层有界，低频动作进入更多面板

首层每个端侧最多 6 项，建议 3~5 项；最后一个槽位固定为“更多动作”。动作目标根据左右边缘和上下安全区自动选择半环、扇形或竖向布局，目标热区至少 44 px。更多面板桌面使用球体内侧卡片，手机使用底部抽屉，二者共享搜索、分组和能力状态。

空配置、provider 注销或能力失效时，必须保留切换器和更多/设置安全入口。不可用动作在更多面板保留禁用态与原因，不静默删除用户配置。

### 5. 默认让位于思源动态弹层

悬浮球基础层级保持低位，继续让位于 `window.siyuan.zIndex` 递增的菜单、对话框和系统遮罩；不通过不断提高固定 `z-index` 竞争置顶。打开插件弹层时沿用 `fabModalDepth` 隐藏/降级，嵌套释放必须幂等。全屏、演示和宿主不可见状态自动隐藏，但必须保留顶栏、命令面板和键盘等效入口。

### 6. 端侧配置独立，领域语义共享

桌面、侧栏和手机共享动作 ID、排序规则、能力和执行器；位置、边缘、尺寸、透明度、展开方向、滚动隐藏等空间设置按端侧保存。侧栏默认继承桌面动作预设，但其位置和可见性独立。

## 被拒绝的方案

- 为悬浮球复制一套动作类型和 handler：会使快捷栏、切换器和悬浮球的可用性与错误处理逐渐分叉。
- 把全部 12 个快捷动作塞进拖动环：会增加命中误差、遮挡内容并破坏动作入口的优先级。
- 用固定 `z-index: 9999` 强制置顶：会遮挡思源确认框和系统菜单，且无法适应动态层级。
- 继续使用 `div[role=button]`：键盘、焦点和屏幕阅读器语义不足，迁移成本低于长期兼容成本。
- 把悬浮球位置和运行时展开状态写进快捷动作导出：跨设备导入会覆盖不适合当前窗口的空间状态。

## 后果

- 现有快捷动作 registry、能力过滤和错误提示成为悬浮球的稳定底座，第三方 provider 无需为悬浮球单独适配。
- 需要扩展快捷动作 surface 映射、settings normalize 和导入导出 schema；这是一次受控的结构演进。
- 需要新增拖动几何、命中、迁移、生命周期和无障碍门禁，并按 `docs/gate-audit-checklist.md` 做负向验证。
- 旧手机 FAB 的默认行为保持可识别：点击仍开切换器，旧开关状态继续有效。
