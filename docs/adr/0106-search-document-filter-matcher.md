# ADR 0106：搜索文档过滤匹配器编译

- 状态：已接受（T-7075）
- 日期：2026-10-02

## 背景

T-7074 收口了搜索结果聚合热路径后，文档范围过滤仍在本地打开卡片、远程标题文档和已打开文档请求中重复执行 notebook/path 解析。重复解析不仅浪费每次键击预算，还让三层过滤语义容易发生漂移。

## 决策

增加 `buildSearchDocumentFilterMatcher(filters)`，在批量遍历前完成一次过滤归一化和 path 前缀预计算。匹配器统一处理 direct notebookId/box 别名、嵌套结果回退、path/hPath/rootPath 别名、斜杠归一化和 notebook-qualified path；批量调用点复用同一个闭包。

保留无筛选时 `filterSearchDocuments` 返回原数组的既有身份契约；保留 `matchesSearchDocumentFilters` 作为兼容入口，但不再让批量调用点逐条重建匹配器。过滤器仍是纯函数，不引入缓存、网络请求或未界定的路径放宽。

## 未采用

- 不在每条记录中重复调用完整过滤归一化，避免把优化写成表面上的函数拆分。
- 不为本地卡片、远程标题文档和已打开请求保留三套谓词，避免范围语义继续分叉。
- 不把缺失 notebook 信号当作“可能匹配”，避免路径过滤在宿主别名缺失时扩大结果集。

## 验证

- `tests/search-document-filter-matrix.test.cjs` 生成 4 种文档形状 × 3 种 notebook 条件 × 3 种 path 条件 × 3 种 path 写法 × 2 个 path 字段 = 216 例，另加 2 个跨层/归一化用例，共 **218/218**。
- 搜索模型、编排及性能定向套件共 **325/325**。
- 同一批 1,200 条记录重复扫描：编译匹配器 CPU 最佳五轮均值 **90.4ms**，兼容包装器 **496.8ms**，CPU 下降 **81.8%**；两者结果计数均为 480。
- 负向验证：在系统临时副本中移除嵌套 notebook 回退，矩阵按预期失败（退出码 1）；仓库生产文件未改写。

## 边界

本 ADR 不替代真实思源桌面窄侧栏视觉证据；该证据仍受 `BLOCKERS.md` 的 B-005 约束。路径语义继续以现有安全归一化为准，未来扩大字段别名必须新增矩阵维度和负向验证。
