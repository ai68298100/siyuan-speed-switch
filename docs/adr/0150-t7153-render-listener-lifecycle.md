# ADR 0150：T-7153 商店重绘监听器生命周期

- 日期：2026-10-07
- 状态：已采纳
- 任务：T-7200

## 背景

T-7153 的真实隔离压力在反复打开工作台和商店时发现，商店 `renderStore()` 会清空目录/详情子树并重新绑定卡片、尺寸和操作监听。旧节点的监听虽然理论上可随 DOM 回收，但没有明确的重绘生命周期；诊断 probe 若强持有 target，还会人为阻止回收，无法区分真实问题与观测副作用。

## 决策

1. 商店在每次 `renderStore()` 开始、替换旧子树前，先通过 render-scoped disposer 移除本轮创建的子节点监听；Dialog 销毁时再次执行 disposer。
2. root 级持久键盘监听仍由现有 `disposeStore()` 管理，与每轮重绘监听分开，避免重复注册和误删。
3. 资源趋势 probe 使用 `WeakRef` 保存 target，并同时报告 connected 与 detached 观察值；不把 detached 计数直接当成泄漏结论。

## 后果

商店重绘不再依赖浏览器 GC 才释放插件创建的子节点监听，搜索、Tab、卡片、尺寸、重试、批量和移动端返回等行为保留原语义。切换器/Dialog 子树的 detached 观察值仍需独立 A/B 归因，不能由本 ADR 推断已存在内存泄漏。
