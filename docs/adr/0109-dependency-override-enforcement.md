# ADR 0109：依赖覆盖必须由当前 pnpm 配置实际读取

- 状态：已接受并完成（T-7079）
- 日期：2026-10-03
- 关联：B-008、v0.44.1 fast-uri 安全修复记录、ADR 0098

## 背景

项目在 `package.json` 的 `pnpm.overrides` 中声明了 `fast-uri >=4.0.0`，但当前工具链为 pnpm `11.4.0`。实际执行任一 pnpm 命令都会警告该字段已不再读取；`pnpm-lock.yaml` 仍解析为 `fast-uri@3.1.8`。因此，当前工作树能够通过测试并不等于依赖安全修复已经由安装配置和锁文件重新兑现。

## 决策

1. 将依赖覆盖迁移到当前 pnpm 读取的 workspace 配置位置，不保留一个会制造错误安全感的失效声明。
2. 重生成并审查锁文件，确认实际解析版本满足目标范围，同时保留可复现安装证据。
3. 增加有效性门禁：既检查配置位置，也检查锁文件最终解析结果；注入失效覆盖或回退版本时必须失败。
4. 在 T-7079 完成前，发布就绪文档只把该项标记为待处理，不把历史 v0.44.1 记录外推为当前候选已验证。

## 不采用

- 不通过删除安全声明、放宽目标版本或只修改文档来消除 pnpm 警告。
- 不把 `pnpm test` 绿作为依赖覆盖生效的替代证据。
- 不在没有锁文件重生成和负向验证的情况下直接发布新的依赖安全声明。

## 验证

T-7079 已提供：pnpm 命令无该配置警告、锁文件中的 `fast-uri` 解析版本为 `4.2.1`、失效 workspace 覆盖和旧锁版本两组注入均以退出码 `1` 击穿门禁；并通过 `tsc`、全量测试 **7809/7809**、可复现构建 **3/3**、只读 Playwright E2E **1/1**、三项审计和发布检查。
