# ADR 0130：平台表面适配路由

- 状态：已采纳
- 日期：2026-10-04
- 任务：T-7089

## 背景

三面板已经分别拥有桌面、侧栏、移动和工作台的 UI 装配模块，领域命令与搜索状态也已共享。平台入口仍在 `index.ts` 中用连续条件分支选择表面，新增入口或返回上下文时容易在某一端漏接，路由边界也无法单独验证。

## 决策

1. 在已有 `platform-surface-model.js` 中增加纯函数 `createPlatformSurfaceAdapter`，以固定的 `switcher`、`workbench`、`studio` 三个 handler 组成一次性路由器。
2. 路由器只转发表面、返回目标和上下文，不持有 DOM、异步状态或持久化数据；具体 DOM 和事件仍由现有表面 UI 装配器负责。
3. 缺失或未知路由返回 `false` 并且不调用任何 handler；通过固定表面白名单拒绝 constructor/toString 等继承属性。合法路由只调用一个对应 handler，避免跨表面重复打开或上下文串线。
4. 不新增运行时 chunk，复用已在生产图中的平台模型，避免在归档余量仅几十字节时增加模块边界。

## 验证

- 新增平台路由组合测试，覆盖 2 个设备 × 3 个表面 × 3 个返回目标 × 12 个上下文，共 **216** 个场景；另有未知/缺失路由负向用例。
- 定向平台测试 **14/14**、TypeScript 检查、生产构建、就绪快照和发布检查通过。
- 初次产物为 `dist/index.js` **1,183,832 B**、`dist/index.css` **303,250 B**、`package.zip` **589,787 B**。T-7090 随后修复继承属性误路由与移动浮球夹具，定向 **25/25**，白名单及表面记录注入精确失败；最新完整验证与压缩后产物见 T-7095/T-7096，不能把初次尺寸当当前快照。
