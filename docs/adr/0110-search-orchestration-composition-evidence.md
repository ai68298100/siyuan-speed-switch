# ADR 0110：搜索模型优化必须在真实编排链复验

- 状态：已接受并完成（T-7080）
- 日期：2026-10-03
- 关联：T-7074、T-7075、ADR 0105、ADR 0106

## 背景

T-7074 的全文命中聚合快路径和 T-7075 的文档范围匹配器分别通过了模型矩阵与性能测试，但搜索界面实际还要经过已打开文档探测、全库回退、结果分页、缓存和请求代际守卫。只验证单个模型函数，无法证明这些层组合后仍保持相同的范围、去重和迟到响应语义。

## 决策

1. 增加 `tests/search-orchestration-composition.test.cjs`，从 `src/doc-search-ui.ts` 提取并执行真实的 `runDocSearchFetch`、`runOpenedDocumentContentSearch` 和 `runFullTextSearchFallback`；只把内核 `fetch`、DOM 渲染和宿主状态作为可控边界注入。
2. 组合链必须同时证明：笔记本/路径筛选在 opened 请求发出前生效，全库结果进入分页前排除已打开根文档，同一筛选缓存命中仍刷新 opened 层，旧代迟到响应不渲染、不写缓存、不追加健康状态。
3. 组合性能沿用 40ms 病态线，并以 600→1200 条原始命中的 CPU 平均增长小于 3 倍作为复杂度门；不通过放宽阈值或只测纯模型函数来消除回归。

## 不采用

- 不用只返回预聚合结果的假编排器替代生产函数。
- 不把缓存命中当作全链路完成：opened 内容仍需重新探测，因为页签状态可能已变化。
- 不把一次浏览器或模拟宿主运行当作 Android 真机或窄侧栏验收；真实宿主证据继续由 B-004/B-005 管理。

## 验证

- 组合行为与性能套件 **3/3** 通过；覆盖 opened/global、范围筛选、分页、缓存刷新和迟到响应。
- 600→1200 命中实链 CPU 平均约 **2.0x**，1200 命中约 **4.3ms**，低于 40ms 病态线。
- 临时向 `aggregateSearchResults` 注入约 45ms CPU 延迟后，目标性能测试以退出码 **1** 击中“1200-hit real composition avg exceeds 40ms pathology line”；注入移除后定向测试恢复通过。
- 本任务只增加组合证据，不改变生产搜索行为。
