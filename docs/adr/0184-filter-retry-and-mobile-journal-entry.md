# ADR 0184：筛选失败可重试与移动端日记入口闭环

日期：2026-10-13
状态：已接受，T-7256

## 背景

移动切换器仍绑定了日记按钮处理器，但模板没有渲染该按钮，导致三端共享的日记入口在移动端不可达。第一面板路径和笔记本筛选在请求失败后只显示禁用文案，用户必须关闭并重新打开菜单才能恢复；最近记录同步和“只看有改动”请求也只设置 `aria-busy`，慢请求期间仍可重复点击。

## 决策

- 移动切换器顶栏补齐日记按钮，沿用现有 `openJournal()` 命令和 44px 触控扩展规则。
- 路径失败菜单增加就地 Retry；笔记本筛选优先使用 `loadNotebooksDetailed()` 区分失败和真实空列表，并提供 Retry。
- 最近记录同步与 changed-only 异步读取在请求期间设置 `disabled`，在成功或失败的 `finally` 中恢复，保留 `aria-busy` 播报。

## 验证

- 移动烟测确认模板、处理器和按钮语义均存在，`pnpm test:smoke` 通过。
- `tests/history-trigger-lock-contract.test.cjs` 2/2 通过，删除锁定语句的负向探针按预期失败。
- 临时删除移动模板的日记按钮后 smoke 按预期失败；临时删除历史同步按钮锁后定向合同按预期失败；恢复后 `src/index.ts` SHA-256 与注入前一致。
- 独立思源内核的移动布局与设置回归 4/4 通过。
- `pnpm exec tsc --noEmit` 通过。

## 边界

路径与笔记本 Retry 仍复用原有查询和代际取消，不改变筛选数据或搜索排序；真实移动宿主和读屏器验收继续按 `BLOCKERS.md` 后置。
