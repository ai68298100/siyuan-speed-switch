# ADR 0101：工作台档位语义统一——七档为唯一产品语义，规格卡字母退役（T-7029）

日期：2026-09-30 · 状态：采纳 · 关联：T-7029、T-6971（58 组件规格卡）、ADR 0091（材质×档位）、T-7037（组件账本校准）

## 背景

审计（feature-audit-2026-09-29 §T-7029）指出两套档位语义并存：58 张规格卡使用 **S=3×2 / M=6×2 / L=6×4 / X=12×3** 的四档字母语言；生产（`constants.ts:218` HomeWidgetSize）自 v0.18 起使用**七档** `xs | small | medium | tall | wide | large | full`，贯穿组件目录 `sizes` 白名单、持久化布局（`sw_home_state`）、商店尺寸瓦片、编辑态与三端样式切片（`_05/_06/_07` 多处 `[data-size]` 选择器）。要求「不得让用户同时看到两套含义」。

## 决策

### D1 七档是唯一产品语义（反向统一，不做持久化迁移）

**生产七档胜出**；规格卡的 S/M/L/X 定性为**设计审查语言**，退役出产品语义。理由：

1. 七档承载真实布局语义且无法被四档 1:1 表达——`tall`（纵向生长）与 `wide`（横向生长）在 S/M/L/X 中没有位置；规格卡自己在批次②~⑨也不断回落到七档词（wide/large/full 反复出现），字母语言事实上已经失效。
2. 七档自 v0.18 起是持久化契约：迁移到新词汇要动 `sw_home_state` 布局、第三方 provider 协议 v2 的 `sizes` 声明、外部组件目录与全部 `[data-size]` CSS 锚点——纯迁移风险，零用户价值。
3. 「用户同时看到两套含义」的实际风险不在持久化层，而在**展示层**：若商店瓦片/编辑角标显示字母。审计证据显示生产 DOM 一直输出七档词（`data-size="small"` 等），字母只存在于设计文档——风险源头是文档，不是代码。

### D2 规格卡补映射注记（T-7029 第二阶段，文档任务）

58 张 `docs/design/component-specs-*.html` 规格卡在批次总表补一行「生产档位」注记：卡面字母 → 七档词的对应（S→small、M→medium、L→large、X→full；卡面出现 tall/wide 处直接保留七档词），并在规格总表声明「字母仅为设计审查速记，产品语义以七档为准」。与 T-7037 账本校准合并施工。

### D3 展示层禁用字母语言（防回归）

商店尺寸瓦片、编辑态尺寸角标、任何新增 UI 一律使用七档词（或其 i18n 显示名），**不得引入 S/M/L/X 字面量**；以契约钉住 `second-panel-ui.ts`/`home-store-ui.ts` 无未映射字母输出。第三方 provider 协议（`widget-protocol.md`）补一句：`sizes` 声明仅接受七档词，未声明回退 plain + medium/首个支持档（既有语义不变，文档显式化）。

### D4 不可逆边界

不做七档词汇的持久化迁移（无新 key、无版本戳 bump）；`HOME_SCHEMA_VERSION` 不变。若未来真需要视觉四档化，须另立 ADR 走 D-401 迁移仪式——本 ADR 明确关闭该方向。

## 后果

- 用户永远只见一套词汇（七档），零迁移风险、零包体增量。
- 规格卡文档与生产的语义映射在文档层闭合（第二阶段随 T-7037 落地）。
- 明确不做：S/M/L/X 持久化、四档化 UI、规格卡重绘。
