# ADR 0155：R17 动作发现与最终状态回执优先级

- 状态：提案
- 日期：2026-10-09
- 关联任务：T-7226
- 依据：[R17 功能强化调研](../research-cycle-r17-2026-10-09.md)

## 背景

三面板已经分别拥有搜索、快捷动作、商店操作、片段保存和悬浮球入口，但这些入口的对象、可用性、失败回退和焦点回归尚未收敛为统一契约。与此同时，配置导入、文档集恢复、片段保存和 provider 操作的“请求完成”并不等于宿主已经达到目标状态。继续增加孤立按钮会扩大行为差异和回归面。

## 决定

1. 下一阶段优先建立共享 Action Panel 适配层，复用现有 quick-action registry、悬浮球 more actions 和卡片上下文菜单；不重造第四套菜单。
2. 动作描述统一包含对象、能力状态、不可用原因、副作用、确认要求、目标表面、回退入口、成功/失败反馈和焦点回归。
3. 写入类操作统一采用“快照 → 应用 → 读回校验 → 分项回执 → 重试/回滚”外壳，回执至少区分 `pending / success / partial / no-op / failed / cancelled`；无法原子回滚时必须公开限制。
4. 在上述契约稳定前，别名、动作级快捷键、深链接和 CLI 只做研究，不进入默认产品入口。
5. 保留现有 MRU、收藏、保存搜索、文档集、组件健康与商店预览实现，不因竞品对照重复建设第二套搜索或历史系统。

## 取舍与验证

- 统一的是领域动作和回执，不要求桌面、侧栏、手机和悬浮球使用相同的视觉布局。
- P0 先选择导航、刷新、重试、复制诊断和跨面板打开等低副作用动作，避免把高风险批量写入与菜单重构绑定发布。
- 实施时必须为动作可用性、失败原因、焦点回归和回执状态增加正向与负向契约测试；真实 Android、读屏和第三方服务仍按 `BLOCKERS.md` 单独取证。
