# ADR 0059 组件深度优化优先与资源预算放宽

日期：2026-09-18　状态：已采纳　关联：T-6352、T-6356、T-6357

## 背景

组件商店已形成较完整的目录，但不同组件在配置、空态、交互和长时间运行稳定性上仍有
明显差异。继续追求组件数量会放大体验不一致。同时，数据库搜索、官方最近文档和动态
图标防护使 `index.js` 的 zip 压缩条目略超 180 KiB 自律线；这不是思源官方限制，也未
触及 512 KiB 的归档上限。

## 决策

1. 下一阶段以 `docs/component-deep-optimization-plan.md` 为主账本，逐组件审查配置、显示、
   交互、空态/失败态、移动端和暗色主题，不以新增组件数量作为主要目标。
2. 体积只保留防失控门禁，不作为正常功能与体验改进的阻断条件。zip 单条目压缩预算从
   180 KiB 调整为 192 KiB，归档总上限仍为 512 KiB。
3. 长时间运行的 UI 必须同时具备 CSS 尺寸硬兜底和动态 DOM 实测钳制；观察器按动画帧
   合并扫描，并在面板销毁时释放，避免用稳定性换取持续性能开销。
4. 修改资源门禁必须按 `docs/gate-audit-checklist.md` 做负向验证。本次将预算临时回退到
   180 KiB，`release archive reports bounded per-entry resource sizes` 对超限的 `index.js`
   精确失败；恢复 192 KiB 后通过，测试文件 SHA-256 恢复一致。

## 后果

- 数据库配置、最近文档、随机回顾和分组可以优先改善真实使用体验，不需要为几 KiB 的
  合理增量反复压缩样式或删除可读代码。
- 192 KiB 仍是评审线而不是无限放行；超过时必须重新说明增量来源，并保留 512 KiB
  归档硬上限和资源基线漂移诊断。

## 2026-09-18 补充：第四批组件后的评审线

完成前 15 个组件的深度优化后，`index.js` 压缩条目为 195019 bytes，距 192 KiB 仅余
1589 bytes。继续按本 ADR 的产品优先级，将单条目内部评审线调整为 224 KiB；512 KiB
整包硬上限不变。该调整不把体积当成交付目标，只保留对异常、无解释膨胀的预警能力。
