# ADR 0064 minAppVersion 从 3.1.20 抬到 3.8.x

日期：2026-09-19　状态：已采纳　关联：D-398、ADR 0063、T-6477、ROADMAP §8.0.5

## 背景

`plugin.json` 声明 `minAppVersion: 3.1.20`，但代码实际消费 3.8.x 内核端点与
Agent 子系统：内核端点契约门（T-6477）钉住 25 条端点的请求/响应形状，Agent 能力
依赖 `addAgentCapability`/`actionEffects`（3.8.x 才具备）。官方语义是"低于下限
的宿主静默自动禁用插件"（`kernel/bazaar/plugin.go:59`、
`kernel/model/plugin.go:237-242`），而非能力门控。

维持 3.1.20 的代价：3.1~3.7 宿主行为从未测试、无从保证；"未探测即降级"代码层
必须持续维护；各版本退出条件里"旧版宿主无报错"的验收范围无法收敛。

## 决策

用户决断（2026-09-19）：

1. `minAppVersion` 抬到 **3.8.0**，随 v0.24.0 发布。
2. 发布后分批简化"未探测即降级"层：每批保持 3.8.x 行为不变、附回归测试与门禁
   负向验证，不以简化为名改变已验收语义。
3. "旧版宿主无报错"类退出条件统一改写为 ≥3.8.x 范围。
4. README、i18n 与集市文案同步下限说明；若集市出现旧宿主用户的强诉求，回滚
   方式是恢复 `plugin.json` 声明并复核降级层（git 可逆）。

被否决的备选：保持 3.1.20（老宿主可继续安装，但未测试范围与降级层维护成本
持续存在，且 Agent/执行链能力本就不可用）。

## 后果

- 3.1~3.7 宿主用户升级插件后将被静默禁用，需先升级思源本体；发布说明中明示。
- 降级层简化是分批重构，不是一次性删除；每批独立提交、独立验收、可单独回滚。
- 与 ADR 0063 联动：执行链宿主确认卡的可用性假设获得版本下限背书。
