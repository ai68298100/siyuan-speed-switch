# ADR 0164：首屏打开与组件商店筛选性能

- 日期：2026-10-10
- 状态：accepted
- 关联任务：T-7237

## 背景

切换器会在打开时同步挂载全部页签卡片；大工作区中，卡片本身和缩略图虽已懒加载，但可视区外节点仍会参与布局与绘制。组件商店的输入筛选则在每次按键时重复查询整棵目录树，卡片数量增加后会放大输入延迟。

## 决策

1. 桌面切换器和桌面侧栏卡片使用 `content-visibility: auto` 及固定的 `contain-intrinsic-size`，让浏览器跳过可视区外布局与绘制，同时保留完整 DOM、滚动、焦点、预览和缩略图观察器；手机端不启用该规则，以保持旧 WebView 的触控与焦点兼容性。
2. 组件商店在每轮渲染完成后缓存卡片、分组、分区和 `dataset` 索引；输入筛选只更新已有节点的可见性、摘要和 ARIA 状态，不改变筛选模型或排序语义。
3. 只有启用“按最近编辑排序”或“显示改动标记”时才请求 `blocks.updated` 元数据；默认 MRU 首屏跳过无消费者的内核 SQL。启动期持久化清洗/迁移仍不拆分，因为这些步骤涉及用户数据修复和写入时序，收益需要真实宿主测量后再单独立项。

## 取舍

- CSS 惰性化不减少 DOM 创建量，但风险低且能直接降低首屏布局/绘制成本；完整 DOM 维持键盘导航和预览契约。
- 索引缓存只在当前商店渲染闭包内存活，重渲染时重新建立，不持有旧节点，避免生命周期泄漏。
- 性能优化不改变版本号或发布边界，待后续真实宿主测量后再决定是否纳入小版本。
