# ADR 0113：第三方 provider 注册必须可核验、可回收、有限重试

- 状态：已接受并完成（T-7083）
- 日期：2026-10-03
- 关联：T-7069、T-7070、T-7072、ADR 0103、`docs/widget-protocol.md`

## 背景

Calendar 接入审计确认了两个独立问题：小驴雷切可能晚于第三方插件加载，单次探测会静默错过注册；第三方 provider 一次提供多个组件时，宿主可能返回 no-op 句柄或只接受部分注册。只等待加载顺序会留下半注册状态，只检查返回值又无法识别宿主是否真的挂载了组件。

## 决策

1. 接入模板使用立即探测加 `[250, 750, 1500, 3000, 6000]` ms 的 `setTimeout` 重试，总重试次数固定为 5 次；卸载时清除当前定时器，达到上限后安静放弃并允许下次重载恢复。
2. 多组件批次先注册全部定义，再用 `getHomeModules("desktop")` 检查每个 `moduleId`。列表缺项、注册抛错或返回 no-op 导致不可见时，先调用本批已经拿到的注销句柄，再进入下一轮。
3. 注册句柄统一归一为幂等注销函数，兼容函数、`{unregister()}` 对象和旧宿主空值。空值不制造虚假的回收能力；存在列表 API 时必须以完整列表作为成功证据，没有列表 API 时只能记录未知可见性。
4. 只有完整批次核验通过后才调用 `onRegistered`，避免宿主在半成功时收到可用通知。失败回收和最终卸载都复用同一组句柄。

## 未采用

- 不使用 `setInterval` 长驻轮询；它无法表达退避窗口，也容易在卸载后留下周期任务。
- 不把“注册函数没有抛错”当作注册成功；当前宿主明确用 no-op 句柄表示失败。
- 不在宿主没有列表 API 时猜测注册结果，也不通过伪造的删除 API补偿空值句柄。

## 验证

- 新增 `tests/widget-provider-lifecycle-matrix.test.cjs`，覆盖 **200** 个组合：5 个宿主就绪时机 × 5 种注册结果 × 4 种列表可见性 × 2 种生命周期。
- 组合覆盖函数/对象注销句柄、半注册、no-op、抛错、列表缺项、列表延迟可见、无列表 API、重试上限和卸载取消；定向套件 **204/204**。
- 负向验证：半注册与列表缺项场景必须拒绝 ready、回收已注册句柄并进入有限重试；无列表 API场景只记录未知可见性，不扩展虚构的验证能力。
- 既有打卡模板定向测试与 `git diff --check` 随后复验；本任务不改变生产面板数据读取或用户存量配置。

## 边界

本 ADR 收口第三方接入模板和协议文档的装载顺序语义；真实 Calendar 外部仓库的实现仍由其维护者合并和发布。宿主真实插件清单顺序仍需在真实思源会话中补充观察，不能由本地夹具替代。
