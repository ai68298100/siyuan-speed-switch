# ADR 0081：raw 包体自律线再校准（1024 → 1088 KiB）

- 日期：2026-09-26
- 状态：已采纳（T-6882 包体复核批）
- 关联：ADR 0074、ADR 0077（前次校准）、ADR 0079/0080、`scripts/release-readiness-metrics.cjs`

## 背景

raw 自律线 1024 KiB（ADR 0077，2026-09-24）设定时 `dist/index.js` 为 984939 B。此后 v0.33.0~v0.37.0 的已审计批次持续推进：R5-A 吸收批、工作上下文批、动作生态批、键盘优先批、三大支柱五波、片段工作室（T-6859~T-6863）、统一平台 P1（T-6867~T-6869）、全插件 UI 原型与 RZ-1~RZ-6 统一 UI 六批（T-6870~T-6876）、默认全屏（T-6877/ADR 0080）、跨表面对象三批（T-6878~T-6881）。当前 raw 为 1038623 B，余量 ~9.7 KiB——v0.38.0 的任何特性批都会越线。

## 减法审计（优先做减法的结论）

- **CSS 不在 raw 线内**：raw 线只度量 `dist/index.js`；样式增长（224 KB）走归档 512 KiB 硬上限约束，当前 zip 488149 B 合规。
- **JS 死代码**：生产构建经 tree-shaking，未接线的契约模块由生产图隔离门禁拦截（上限 68）；无意义的死重量可清理空间极小。
- **增长可归因**：上述批次全部逐批评审、逐批带契约与负向验证，属功能驱动而非失控膨胀。
- 结论：无可观减法空间，按先例做**带日期的再校准**。

## 决策

1. `RAW_BUNDLE_BUDGET_BYTES` 1024 KiB → **1088 KiB**（+64 KiB 步进，延续 ADR 0059/0062/0067/0074/0077 程序）。
2. 硬上限不变：归档 512 KiB、漂移容差 1 KiB 不动；压缩条目线 288 KiB 亦未动（当前 ~285 KiB，**同样逼近，越线时需新审计**）。
3. 数量类门禁仍只是观测护栏：单批异常膨胀（非 feature 归因的跳变）依然会被 review 拦下。

## 后续退出条件

- 越线 1088 前的下一批仍须包体复核留痕；压缩条目线（288 KiB）越线时单独走新 ADR。
- 增长若与 feature 归因不符（无对应批次的跳变），以回归对待并回查。
