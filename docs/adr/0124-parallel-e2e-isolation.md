# ADR 0124：多插件真实 E2E 的并行隔离

- 状态：已采纳
- 日期：2026-10-04
- 任务：T-7085

## 背景

多个思源插件需要同时做真实宿主 E2E。每个插件可以拥有自己的代码仓库，但如果复用默认端口、工作区或产物目录，内核数据、目标连接信息和截图/日志就会互相覆盖。单个思源内核内部仍只有一套文档树和插件实例，不能把同一个实例交给多个 Playwright worker 并行写入。

## 决策

1. 每个并行插件实例必须使用独立的 `SWSS_E2E_WORKSPACE`、`SWSS_E2E_PORT` 和 `SWSS_E2E_ARTIFACT_DIR`；工作区必须由 E2E 标记文件保护，不能指向用户真实笔记。
2. `SWSS_E2E_KERNEL` 可按插件指定不同思源内核；即使多个实例使用同一安装目录，也必须由各自的测试进程启动独立内核。
3. 每个实例内部继续 `workers: 1`、`fullyParallel: false`；并行边界放在插件实例之间。只读实例另外使用 `SWSS_E2E_READONLY_PORT`。
4. Playwright 结果目录、目标 JSON、内核日志和测试截图统一落入 `SWSS_E2E_ARTIFACT_DIR`，默认值仍是仓库的 `.artifacts/e2e`，保持单实例命令兼容。

## 边界

独立端口和工作区能隔离插件状态，但不能消除机器 CPU、内存、磁盘和思源安装目录的资源竞争。端口已被占用、工作区被其他内核锁定或同一插件仓库同时构建 `dist` 时，应等待、换端口/工作区或错峰构建；不能把两个写入型套件放进同一工作区。

## 验证

- `tests/e2e/helpers/app.mjs`、两个 Playwright 配置和两个全局 setup 均读取独立产物目录。
- 真实思源分组 E2E 在默认实例通过 **1/1**；T-7085 使用自定义工作区、`6847` 端口和 `.artifacts/e2e-t7085` 产物目录复跑同一用例并通过 **1/1**，确认变量确实生效。
