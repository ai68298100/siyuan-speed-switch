# ADR 0126：Gist 采用显式发布与禁用草稿导入

- 状态：已采纳
- 日期：2026-10-04
- 任务：T-6973

## 决策

1. Gist 是个人单点分享通道，社区商店继续遵循 GitHub 目录审核与链滴投稿。Gist 区默认折叠，读取公开 Gist 无需 token。
2. Token 明文保存在既有插件设置中，界面只显示末四位；保存后清空输入，支持替换与清除。配置导入、导出白名单均不接纳凭据或链接；不新增存储 key，不输出请求正文或原始网络错误。
3. 仅接收 HTTPS gist.github.com 完整链接；请求固定到 api.github.com/gists，凭据只放 Authorization，请求不带浏览器凭据、不跟随重定向、不发送 referrer。
4. Gist 新建明确为 unlisted，知道链接即可访问，不能称为私密。文件上限 64 KiB、32 文件、响应流上限 2 MiB、请求默认超时 10 秒；取消要终止流，忽略取消的迟到响应也要释放正文。
5. 预览展示所有文件的可解析状态，同本地 ID 可比较差异。导入始终产生新的禁用草稿；远端 ID 不复用为本地 ID，确认保存后才把新 ID 与完整来源链接关联。
6. 发布仅接受已保存且无未保存修改的片段；稳定文件名包含原生片段 ID 和类型。更新先读取并预填 description，再重读整个文件快照；只允许更新唯一、完整、可解析且 ID/类型匹配的文件。旧文件名可迁移，其他文件保持。
7. GitHub 不提供本通道的原子比较写入，重读与 PATCH 间仍可能变化；取消或写回执失败诚实提示可能已落地，不自动重试。读取、选择、编辑和销毁使用独立代际，迟到结果不替换当前草稿。
8. Gist 请求和预览代码留在片段实验室动态 chunk；设置清洗留在现有主图模块，公共 token 不放入口 DOM。

## 验证边界

模型和 UI 回归验证输入、凭据、流上限、取消、快照冲突、禁用导入及设置导出边界。真实思源 E2E 使用隔离工作区与受控 GitHub 响应，验证真实宿主的界面、内核保存和请求合同；不代表真实 GitHub 账号发布通过。Android 与最窄真实侧栏仍按 B-004/B-005 后置。
