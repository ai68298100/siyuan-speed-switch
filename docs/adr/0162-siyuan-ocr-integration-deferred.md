# ADR 0162：思源 OCR 接入后置到 3.8.7 正式版

- 日期：2026-10-10
- 状态：accepted
- 关联任务：T-7235
- 研究报告：[思源 OCR 接入调研](../research-siyuan-ocr-2026-10-10.md)

## 背景

用户希望评估思源最新源码中的 OCR 设置，并在新增能力时为未配置 OCR 的用户提供充分引导。当前思源最新正式版为 v3.8.6，v3.8.7 的 OCR 配置和 AI/PaddleOCR 能力仍处于 alpha/dev 演进阶段。直接依赖这些接口会把不稳定的宿主实现带入本插件生产版本。

本插件已经使用思源原生全文搜索接口。若思源完成 OCR 并把结果纳入索引，本插件可以复用已有搜索链路，不需要复制模型、扫描全部资源或维护第二套索引。

## 决策

1. T-7235 只交付源码调研、接入边界和后续验收清单，本轮不修改生产代码、版本号、README 功能说明或发布资产。
2. 等思源 v3.8.7 正式版发布后，重新核对 OCR 配置、图片 OCR、AI OCR、模型导入、默认值、迁移逻辑和最低版本，再决定是否立项实现。
3. 后续实现优先复用思源原生 OCR 结果和全文索引。只有稳定宿主能力明确提供且确有用户价值时，才增加图片 OCR 快捷操作、来源标识或筛选。
4. 所有 OCR 入口必须由宿主 capability 和配置状态控制；未配置、引擎不可用、模型缺失、格式不支持、加密笔记本、超时、取消和失败都要有具体状态与恢复动作。
5. AI OCR 必须单独说明外发、隐私和费用边界；自动 OCR 默认不由本插件替用户开启，也不由本插件扫描全部资源。

## 取舍

- 立即接入 alpha/dev API 可以提前试用新能力，但会产生宿主版本耦合、迁移风险和不可解释的失败路径，暂不采用。
- 在插件内自建 OCR 索引可以绕过宿主差异，但会重复消耗模型和资源，并可能与思源权限、加密笔记本和索引状态不一致，暂不采用。
- 只增加一个“开启 OCR”按钮无法覆盖用户配置、模型和隐私前置条件，暂不采用。

## 重新评估条件

思源 v3.8.7 正式版发布后，满足以下条件才可进入实现任务：

- 稳定 API 和配置契约已确认，且不依赖 alpha/dev 私有路径。
- 真实宿主验证覆盖成功、无结果、超时、取消、重试、加密笔记本和不支持格式。
- 第一面板原生全文搜索对 OCR 命中的行为和延迟有证据。
- 设置引导、能力状态、隐私提示、空态/错误态和双语文案已经评审。
- 新增功能的契约测试、负向验证和发布说明已经列入独立小版本计划。

## 验证

- 研究证据与上游版本边界记录于 docs/research-siyuan-ocr-2026-10-10.md。
- 当前源码没有新增 OCR 生产调用，版本仍保持 v0.46.8。
