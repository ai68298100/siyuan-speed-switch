# ADR 0065 zip 单条目压缩评审线校准至 256 KiB

日期：2026-09-20　状态：已采纳　关联：ADR 0059、ADR 0062、T-6680、T-6681、D-216 系

## 背景

zip 单条目压缩评审线（224 KiB，ADR 0059，自设评审线而非宿主限制）在 T-6680 执行链
六模块入图（+15113 bytes raw / 压缩条目 +4147 bytes）与 T-6681 写作打卡二轮增量后，
余量从 16504 bytes 收窄到 **11780 bytes**——按当前增量节奏，专项 C 的下一项
（强度分、12 个月回看）任意一项都会越线。与 ADR 0062 时的情形相同：继续开发将必然
越线，若不校准会迫使为守一个历史数字而砍功能。归档硬上限（512 KiB，余量 137365
bytes）与 raw 自律线（832 KiB，余量 31466）均无压力。

## 决策

1. zip 单条目压缩评审线从 224 KiB 调整为 **256 KiB**（262144 bytes）。校准后余量
   约 44 KiB，可容纳专项 C 二轮批次与 v0.24.0 发版增量。
2. 不变的约束：`package.zip` 512 KiB 归档硬上限不变；raw `index.js` 832 KiB 自律线
   （ADR 0062）不变；产物快照漂移诊断不变。
3. 256 KiB 仍是评审线而非放行线：每次跨越性增长仍须在账本记录真实增量来源；
   再次逼近时按同一程序重新评审，而非静默上调。
4. 修改资源门禁按 `docs/gate-audit-checklist.md` 做负向验证：临时把预算回退到
   190 KiB（低于当前产物）确认单条目压缩门禁精确失败，恢复 256 KiB 后通过且
   测试文件 SHA-256 一致。

## 后果

- 专项 C 二轮（强度分、12 个月回看）与近期发版增量不再被历史数字阻塞。
- 门禁仍保留对异常膨胀的预警能力；归档硬上限与 raw 自律线共同兜底真实发布风险。
- 校准仅动 `scripts/release-readiness-metrics.cjs` 的共享常量（三处消费方自动同步），
  测试与文档引用同步更新。
