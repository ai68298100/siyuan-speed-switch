# ADR 0103：第三方组件实例的生命周期语义（保留优先，显式清理）

- 状态：已接受（2026-09-30）
- 关联：T-7069（calendar#17 宿主修复）、T-7070、`docs/widget-protocol.md`「生命周期与失效恢复」

## 背景

calendar#17 暴露：运行时 `registerHomeModule()` 注册的第三方组件，被 `getHomeState()` 的归一化清除（归一化只认内置定义表）。T-7069 初版以「运行时注册表」为允许名单修复了添加路径，但引入了与文档承诺的冲突：

- `docs/widget-protocol.md` 承诺「provider 卸载 ≠ 配置删除」——禁用/升级/重载期间实例与布局保留，商店卡片标"当前不可用"并提供**显式清理入口**；
- 插件禁用/重载会触发 `unregister` → 运行时名单摘除 → 下次归一化把实例清掉。用户只是临时禁用一次 Calendar，布局就没了。

Calendar 维护者在 #17 中同时建议过「只保留当前已注册的 moduleId，避免无效持久化数据无限增长」。两条诉求表面冲突。

## 决策

**保留优先**：归一化允许名单 = 运行时注册 ids ∪ **已持久化实例的 moduleId**。

1. 用户添加过的第三方组件，在任何宿主状态归一化中都保留——禁用/重载后原样恢复，与内置组件生命周期对齐；
2. 数据增长天然有界：实例与布局受 64 条/表面上限约束，「无限增长」不成立；
3. 清理走设计好的显式路径：用户在商店删除实例（含"当前不可用"卡片的清理入口）→ 实例离开持久化 → 名单随之收窄 → 布局滤除。注册表 `homeThirdPartyIds` 仍负责运行时可见性（商店列表、读取路由），不再承担持久化存亡。

## 理由

- 「持久化实例 moduleId 必然来自真实注册添加」：`sw_home_state` 只经 `getHomeState()` 归一化后写回，非 builtin moduleId 进入持久化的唯一通路是 registerHomeModule 后的商店添加。名单因此**不引入垃圾回流**；
- 内置外部适配器（external-*）历来如此（定义常驻 `DEFAULT_MODULES`，卸载不删实例）——本决策把第三方组件拉齐到同一语义，消除两套生命周期；
- 维护者的膨胀担忧由 64 上限 + 显式清理承接，不牺牲用户数据。

## 后果

- 禁用插件 → 实例与三表面布局原样保留；重启用 → 即时恢复（此前会静默丢失）；
- 永久不再使用的组件：实例留存直至用户显式清理或达到 64 上限（商店"当前不可用"卡片可见可控）；
- calendar#17 回复草稿同步改写此语义（未外发，无成本）；
- 契约：`home-store-contract.test.cjs` 钉住双来源允许名单表达式。
