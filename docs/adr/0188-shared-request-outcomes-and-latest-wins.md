# ADR 0188：共享请求结果分类、取消与 latest-wins

日期：2026-10-14  
状态：已接受（T-7260～T-7262）

## 背景

搜索、工作台适配器和生活组件此前各自实现超时、取消、缓存和失败处理。相同请求可能重复发出，迟到响应可能覆盖较新的缓存；内核写入超时还无法区分“明确失败”和“服务端已经写入但响应丢失”。

## 决策

- 内核请求统一经过共享请求服务：请求键稳定序列化；同一取消语境下读请求去重；读请求最多一次瞬时失败重试；超时即使运行环境没有 `AbortController` 也必须结束等待。
- 每个搜索表面使用独立 latest-wins 作用域；旧响应只能被丢弃，不能渲染或写入缓存。宿主搜索测试通过结构化 `requestKernelJsonOutcome` 注入，避免重新建立一套网络策略。
- 工作台适配器的 deadline 和外部取消必须传到底层 reader；超时/取消先确定调用者结果，再中止 reader，防止取消回调同步成功污染状态。
- 生活组件按缓存键去重并保护缓存提交；强制刷新产生新代，旧响应不得覆盖新缓存，缓存清理也会使挂起响应失效。
- 写端点不自动重试。超时、网络中断、响应解析失败等无法确认服务端状态的写入返回 `outcome: "unknown"`；快速捕获保留窗口并锁定追加按钮，要求用户先核对目标再决定后续动作，避免重复追加。
- 401/403、网络/超时、无效响应和空结果保持可区分的错误语义；本插件不自建登录页，宿主会话仍由思源负责。
