# ADR 0117：三面板关闭契约与脏稿守卫

- 状态：已接受
- 日期：2026-10-04
- 关联任务：T-7028

## 背景

三面板的导航头部已经共享 `SurfaceNav`，但移动切换器仍缺少统一关闭入口；片段实验室的宿主关闭路径也可能绕过编辑器脏稿保护。返回、关闭、Escape 和嵌套浮层关闭还需要明确各自的所有者，避免局部浮层关闭时误销毁宿主 Dialog。

## 决策

1. 桌面切换器、工作台和移动切换器都由拥有它们的 Dialog 装配 `SurfaceNav` 关闭回调。设置和商店沿用各自的销毁释放入口，关闭后恢复打开控件焦点。
2. 片段实验室控制器暴露同步 `canClose()`。宿主发起关闭时先执行该判定；脏稿或忙碌状态阻止销毁，三选一结果确认后通过 `guarded` 意图只继续一次关闭。
3. 片段实验室内部返回和平台关闭都进入同一个离开意图协调器；移动排序浮层、片段目录浮层先在本地消费 Escape/关闭，再把关闭权交还宿主。
4. 契约测试直接扫描生产接线，真实思源 E2E 覆盖桌面三面板、脏稿取消/放弃和移动关闭；不以 DOM 合成替代真实宿主结论。

## 结果

- `tests/surface-close-contract.test.cjs` 定向 5/5 通过；删除移动 `onClose` 或片段宿主 `canClose` 的负向注入均精确失败并恢复源码哈希。
- `tests/e2e/surface-close.spec.mjs` 在思源 3.8.6 真实桌面/移动视口通过 2/2，验证关闭按钮归属和脏稿守卫。
- `tsc`、生产构建、全量测试和发布检查通过；内核退出时的 `mux: server closed` 只出现在测试实例收尾日志，不属于插件错误。

## 边界

Android 真机和最窄真实侧栏的触控/视觉验收仍由 B-004/B-005 管理。关闭契约不扩大到外部宿主无法控制的原生窗口生命周期。
