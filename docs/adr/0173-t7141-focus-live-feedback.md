# ADR 0173：T-7141 焦点回收与预览状态播报

日期：2026-10-12

状态：已接受，T-7141

## 背景

全平台焦点审计复现了两个可见问题：工作台组件从失败态点击“重试”后，成功内容替换会把焦点留在 `body`；片段冲突对话框的“放弃并重载”和“保存副本”出口在宿主销毁 Dialog 后也可能失去编辑器焦点。第一面板搜索预览在异步内容替换后只有视觉上的“已就绪”徽标，状态节点没有明确的动态播报语义。

## 决策

- 工作台重试成功时优先聚焦恢复内容的第一个可用操作，没有操作则聚焦组件区域本身；不改变数据、排序或刷新竞态语义。
- 片段冲突层统一使用编辑器回焦助手：继续、取消、重载已有版本、异步重载完成和保存副本成功都在 Dialog 销毁后回到编辑器；失败时保留当前操作按钮焦点以便重试。
- 预览正文保持普通内容区，只有头部短状态徽标设置 `role=status`、`aria-live=polite`、`aria-atomic=true`，让 loading/ready/error/blocked 的回执可播报而不重复朗读长正文。
- 真实 NVDA、思源桌面和 Android 读屏结果继续按 B-005/T-7115 后置，不把浏览器 DOM 属性当作宿主读屏验收。

## 验证

- 工作台、预览行为和冲突接线定向测试 **40/40**；其中重试回焦和预览 ready 状态为真实 jsdom 事件路径。
- `pnpm exec tsc --noEmit` 通过；完整 `pnpm test` **8664/8664**，`pnpm verify:release` 全链通过。日志见 `.artifacts/T-7141-full-tests.log` 与 `.artifacts/T-7141-verify-release.log`。
- 门禁测试对冲突回焦接线完成删除式负向验证：移除 `focusEditor()` 后目标测试按预期失败，源码恢复后重新通过，记录见 `.artifacts/T-7141-negative-probe.log`。

## 边界

本 ADR 不改变 Dialog 的关闭路由、保存冲突策略、预览取数、请求取消或内容结构；真实屏幕阅读器输出仍需后置环境取证。
