# ADR 0226：T-7334 路径首字母模糊加速打分与既有结果重排

日期：2026-10-19  
状态：accepted

## 背景

在大知识库场景中，文档通常具有多层级深路径（如 `思源库/研发/小驴雷切.sy`）。用户使用桌面或移动切换器搜索时，输入汉字子串或长拼音的键入成本较高。同时，2026-10-19 行业竞品调研中明确提炼出 VS Code Quick Open 式路径首字母模糊加速（Path Acronym Scoring）演进方向。

既有搜索模型（`src/search-model.js`）已具备纯 ASCII 拼音逐字匹配（T-6805），但该匹配主要作用于单一标题，未对多段层级路径（notebook / 目录 / 文档名）做跨段首字母缩写协同打分；若直接在全库发起模糊跨度匹配，在思源大库中会导致大量无关误命中。

## 决策

1. **只打分，不决定命中**：路径首字母加速（`src/path-acronym-model.js`）只在内核标题搜索或全文搜索返回的既有文档结果集内执行稳定重排（`rankDocumentsByPathAcronym`）。不新增结果、不剔除结果、不改变集合大小与内容。
2. **极短 ASCII 查询门禁**：只对 2~6 字节纯小写 ASCII 字母数字查询（`isAcronymQuery`）启用加速；单字符（`s`）因误命中率过高被拒绝，中文查询交给既有汉字子串/拼音管线，超长串避免退化。
3. **逐段消费与顺序不可逆**：路径被 `/` 切分为最多 8 个段，每段拼音首字母序列（汉字取 pinyin 首字母、拉丁/数字逐字保留）可消费查询的前缀；一旦某段贡献字符，后续字符必须严格来自更靠后的段，段间与段内均不可乱序或跨字跳过。
4. **零新增依赖与有界防线**：复用既有 vendor `tiny-pinyin`，不引入外部算法库；路径段数（8）、段长度（96 B）、候选上限（400）与段缓存（2000 项）四重有界防护，最坏情况复杂度保持在 O(N·K) 内。
5. **门禁与负向自查**：定向测试 `tests/path-acronym-model.test.cjs` 包含 10 项契约断言，并在尾部固化乱序拦截、段内跳字拦截、中文门禁拒收、集合长度不变与单字符拒绝五组判别性负向探针。

## 证据与边界

- **类型与全量测试**：`pnpm exec tsc --noEmit` 0 错误；全量测试从 8850 项扩充至 **8860 通过 / 1 跳过 / 0 失败**。
- **负向验证**：经破坏性注入验证（放宽乱序约束、放宽中文门禁、重排丢弃未命中项），测试分别定向出现 6 / 2 / 4 项失败，确认门禁真实有效。
- **构建与包体**：生产构建 `package.zip` 为 **590,508 B**，严格保持在 591,872 B（578 KiB）仓库门禁之下（余量 **1,364 B**）；`dist/index.js` 为 1,164,159 B（低于 1,187,840 B 预算线 23,681 B）；压缩条目 312,352 B（低于 327,680 B 门禁 15,328 B）。
- **批量门禁全绿**：可复现构建 3/3 一致；release-batch-audit（49/49）、quality-batch-audit（50/50）、integration-boundary-audit（50/50）、current-status-audit（170 tasks）、compatibility-probe、desktop-acceptance 以及全部 6 套端侧/Chromium Smoke 均已全绿。
- **边界声明**：本决策不改动远端 Release、Git Tag 或包版本号；真实多层级超大库真人使用体验持续待验。
