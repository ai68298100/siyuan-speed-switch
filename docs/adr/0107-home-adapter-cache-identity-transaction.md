# ADR 0107：工作台适配器缓存身份与 generation 事务

- 状态：已接受（T-7076）
- 日期：2026-10-02

## 背景

`readHomeModule` 在检查缓存和并发去重之前递增 generation。并发调用命中同一个 in-flight promise 时，后到调用会把 generation 提前推进，先到调用完成后无法写回成功快照，下一次读取继续击穿缓存。另一个独立问题是配置对象直接 `JSON.stringify`，同一组合法配置只要键插入顺序不同就会生成不同缓存槽。

## 决策

1. 工作台读取配置继续沿用原有类型、长度、字段数量和非法字段边界，但对已接受的顶层字段按键名排序后再传给适配器，保证等价配置拥有稳定序列化结果。
2. 增加 `buildHomeAdapterCacheKey`，缓存身份由模块、设备和规范化配置组成；设备仍只接受桌面、侧栏、移动三类。
3. 先处理失败退避、缓存命中和 in-flight 去重；只有真正创建新读取事务时才推进 generation。缓存命中和复用中的 promise 不再伪造新 generation。
4. 新事务复用同一份规范化配置传给适配器，避免 key 计算和 provider 输入各自归一化后发生漂移。

## 未采用

- 不按原始对象引用做缓存身份，避免每次渲染产生新对象后失去去重。
- 不把 force 刷新改成无条件并发多读；已有 in-flight 读取仍按 dedupe 语义复用，显式 `dedupe: false` 才允许并行事务。
- 不放宽配置类型或把数组、嵌套对象写入缓存 key；这会改变既有适配器协议边界。

## 验证

- `tests/home-adapter-cache-matrix.test.cjs` 以 2 设备 × 4 配置身份 × 4 执行方式 × 2 缓存策略 × 4 快照形态生成 **256/256** 个独立用例，另加矩阵数量和归一化边界断言；与首页既有定向套件合计 **356/356**。
- 基线复现：并发去重后第三次读取未命中缓存（provider 调用 2 次）；同值逆序配置重复读取（provider 调用 2 次）。
- 修复后最小复现：并发读取 provider 调用 **1** 次且第三次 `cached=true`；逆序配置 provider 调用 **1** 次且第二次 `cached=true`。
- 负向验证：系统临时副本恢复旧 generation 顺序时矩阵以退出码 **1** 在“事务后缓存可复用”断言失败；移除配置键排序时以退出码 **1** 在“等价配置共享身份”断言失败；生产文件不在临时副本中改写。

## 边界

本 ADR 只修复缓存身份与 generation 提交时机，不引入持久化缓存、跨设备共享数据或新的网络请求；真实宿主刷新频率仍受 B-005 的窄侧栏视觉取证边界约束。
