# ADR 0047：性能门禁自检改为自适应标定 + 比值断言

- 日期：2026-09-17
- 状态：已接受（T-6290）
- 范围：`tests/perf-complexity-gate.test.cjs` 的自检夹具

## 背景

自检 `perf gate fixture sanity` 用**固定迭代数**（400k / 800k）配**绝对毫秒下限**
`light > 0.5`。在 Node v22.22.2 快机上实测 `light≈0.152ms`，低于地板，导致**确定性失败**
（单独复跑 3/3 一致，排除抖动）。而此时 `ratio≈2.01`——比值语义完好，说明失败源于
**夹具与机器速度的耦合**，不是计时器或产品回归。

该文件的其余部分本就采用"按机器校准"口径（`rounds` 按规模校准至数十毫秒量级），
自检使用固定迭代数是唯一的不一致点。

## 决定

1. **自适应标定**：新增 `sumTo(n)` 与 `calibrateSelfCheckIterations(floorMs)`，以 2 的幂次
   放大迭代数直至单次耗时越过 `SELF_CHECK_FLOOR_MS = 2`，再以 `2×` 迭代数作为 heavy 侧。
   本机标定到 6,400,000 次，实测 `light 7.28ms / heavy 14.60ms / ratio 2.00`。
2. **弱断言升级为比值断言**：原 `heavy > light` 在负向验证中被证明**没有判别力**——
   把 heavy 退化成与 light 同规模后它仍然通过（等规模 workload 的 min-of-N 结果因计时
   噪声偶然满足大于关系）。改为 `heavy / light >= SELF_CHECK_MIN_RATIO(1.5)`。

## 不做的事

- **不放宽阈值让它通过**。0.5ms 地板暴露的是夹具设计问题，放宽只会把"夹具不可靠"
  这一诚实信号抹掉；本门禁的价值恰在于它敢于报告自身失效。
- 不改动 `RATIO_CEILING = 3` 与 `measureDoublingRatio` 的既有语义。

## 验证

负向验证三件套（脚本 `.tmp/negverify_perf_gate.py`，逐项字节级还原并核对 md5）：
等规模注入 → 精确 1 项 FAIL；地板设 1e9 不可达 → 精确 1 项 FAIL；两例下兄弟 5 项均不波及；
还原后 md5 对齐、6/6 全绿。全量测试 5872/5872。仅改测试文件，产品代码零改动。

## 教训

**负向验证的真正产出未必是"确认门禁有效"，也可能是"发现门禁无效"。** 本轮第一个注入
（等规模）在旧断言下全绿，是夹具判别力缺陷的实证，比原定的"修机器敏感性"更有价值。
