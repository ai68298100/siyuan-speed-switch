# ADR 0061 组件配置深度与 UI schema 上限

日期：2026-09-18　状态：已采纳　关联：T-6409~T-6416、ADR 0059

## 背景

组件深度优化要求把数据来源、范围、筛选、排序和显示层级交给用户控制。原有
`normalizeConfigSchema` 最多保留 8 个字段；“今日待办”等组件超过 8 项后，后续字段会被
静默裁掉，生产适配器虽支持路径和序号，配置页却无法设置。

配置对话框已经采用语义分区、内部滚动和 sticky 操作栏，继续使用 8 项上限不再带来明显的
布局收益，反而会形成 schema 声明与真实 UI 不一致。

## 决策

1. 组件 UI 的 `configSchema` 上限从 8 调整为 12，仍拒绝非法键、非法类型与空 select，单个
   select 仍最多 12 个选项。
2. 配置持久化仍最多保存 32 个键、字符串最多 512 字符；本次不放宽数据和递归深度边界。
3. Agent 组件发现接口继续只公开最多 8 项配置（D-037 的外部能力边界），本次仅调整用户可见
   的本地配置表单；需要 Agent 覆盖更多字段时另行审计。
4. 以 13 项输入被截断为前 12 项的契约测试锁定边界，并按门禁审计清单做负向验证。

## 后果

- 复杂内置组件可完整展示来源、范围与显示设置，不再出现“代码支持但配置页消失”的假配置。
- 最长表单增加滚动距离，但不扩大宿主 Dialog，继续遵循既有移动端与旧 WebView 兼容策略。
- UI schema 与 Agent 发现上限暂时不同，这是有意的信任边界，而不是遗漏。
