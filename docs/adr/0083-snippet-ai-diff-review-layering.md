# ADR 0083：片段 AI 的确定性审查层与 diff 接受语义

- 日期：2026-09-26
- 状态：已接受（设计定案，分期实现见设计文档）
- 关联：ADR 0078、ADR 0079、T-6862、T-6906、T-6907、T-6909、`docs/design-snippet-ai-diff-review-2026-09-26.md`

## 背景

片段 AI 候选目前是"全文 + 单按钮全量接受"。R8 调研（AI 代码审查形态、Obsidian 引用验证三段式、Stylus 验证器期待）指向"摘要 + diff + 逐条接受 + 接受前确定性审查"。实施前必须裁决三个取舍：摘要由谁生成、stylelint 是否引入、逐条接受的粒度与语义。

## 决策

1. **摘要在本地确定性生成，不解析模型自述。** 宿主 AI SSE 只返回单代码块，没有可靠的结构化摘要字段；改动摘要（hunk 数、行数、字节增量、审查发现数）由 diff/审查层计算。不承诺"AI 解释自己的改动"，只展示"这次接受实际上改变了什么"。
2. **不 vendor stylelint/ESLint 本体，采纳规则语义子集自实现。** 完整依赖树违反包体自律（raw 余 ~25 KiB）；`snippet-lint.js` 以版本化规则表实现 ~10 条高信号规则（stylelint 语义 + T-6907 policy 的可机检面），纯函数、零网络、发现不阻断接受（人裁决）。lint 与 policy 分层：policy 是生成前软约束，lint 是接受前硬信号——提示词不当安全门禁。
3. **逐条接受以 hunk 为粒度，拒绝删除 = 保留原文。** 行级 LCS diff 聚合 hunk；应用时从后向前拼接，rejected hunk 的 del 行保留、ins 行丢弃；应用结果走既有脏稿/冲突/保存链。不做逐字符 diff，不做自动接受。
4. **explain 模式不进 diff 管线；迭代模式可标注"相对上一轮"基准。** 与 ADR 0078 的"解释是受限纯文本、不误当代码"一致。

## 后果

- AI 多轮体验的可信度从"相信模型"转为"检验产出"：本地摘要 + 确定性审查 + 人工逐条裁决三段缺一不可。
- 新增两个纯函数模块（diff/lint），包体增量预计 <6 KiB 压缩，随分期实现复核预算。
- 规则表为保守起步，规则演进须版本号递增并配正反例单测；不追求 stylelint 全量兼容。
- 真实宿主 SSE 证据继续按 B-005 后置，不阻塞本地分期交付。
