# ADR 0080：三表面默认全屏与尺寸策略

- 日期：2026-09-26
- 状态：已采纳（T-6877，用户反馈驱动）
- 关联：ADR 0079、`docs/design-unified-platform-ui-round2-2026-09-26.md`

## 背景

统一平台改造（T-6869~T-6876）后，三个表面单屏承载的信息密度明显上升：切换器 = 已开页签 + 收藏/最近 + 全库结果 + 预览窗格；工作台 = 组件网格 + 商店入口；片段实验室 = 目录 + 编辑/预览/AI。用户反馈"每次显示的内容有点多，压缩后就不太好看了"，提议所有页面默认全屏、可选其他尺寸。

## 决策

1. **切换器默认全屏**：`panelSizeMode` 默认 `adaptive` → `fullscreen`（`fullscreen` 布尔由模式派生，语义不变）。全屏下已开页签网格可达 4~6 列，"一眼看出打开了什么页签"；工具栏既有全屏切换与 Esc 退出保留。
2. **工作台默认全屏**：`homeSizeMode` 默认 `follow` → `fullscreen`。仪表盘型表面受益最大，组件卡片以完整内容渲染而非压缩缩略。
3. **片段实验室默认全屏**：打开尺寸从 `min(1600, 92vw) × min(960, 88vh)` 改为视口全屏，并叠加 `sw-dialog--fullscreen` 容器类，与另两表面一致。
4. **其他尺寸全部保留可选**：三表面的尺寸设置项（自适应/固定/全屏、跟随等）一个不删，用户可随时改回。

## 取舍与影响面

- **持久化语义（关键约束）**：`updateSettings` 每次写入完整设置对象，因此任何改过设置的老用户都持有显式旧值——本决策只改变**新安装用户**的默认观感，老用户不受打扰；想要全屏的老用户在 设置 → 面板 一键切换。
- 切换器的身份是"快速切换"，全屏不损害该路径：热键 → 全屏覆盖 → 输入 → Enter 的肌肉记忆与窗口模式完全一致，且全屏反而让数字直达与行导航的可扫视范围更大。
- 移动端不受影响：移动切换器/工作台使用独立尺寸逻辑（92vw/85vh 与 `resolveMobileHomeSize`）。
- 片段实验室仍为桌面专属（ADR 0078），全屏不改变端侧边界。

## 后续退出条件

- 真实桌面全屏观感与多显示器场景归真机验收批（B-004/B-005），不以浏览器模拟充数。
- 若真机反馈全屏在小屏幕（≤1366px 宽）下密度过高，再评估按视口宽度分档的默认值，不回退本决策的方向。
