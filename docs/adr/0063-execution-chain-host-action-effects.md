# ADR 0063 执行链审批确认采用宿主 actionEffects

日期：2026-09-19　状态：已采纳　关联：T-1219、T-6476、D-399、ROADMAP §8.0.5 执行闭环波

## 背景

v0.24.x（T-1219 workspace-plan 执行链）原计划沿用自建审批路线：自有确认弹窗 +
一次性令牌（`src/agent-approval-token.js`、`src/agent-workspace-approval.js`）+
30 秒超时视为拒绝（`src/agent-workspace-execution.js`，合计约 177 行）。该路线的
硬代价是"自建确认弹窗必须通过 Android 真机逐项验收"（B-004，环境类阻塞），成为
执行闭环波的关键路径卡点。

2026-09-19 上游契约核对（dev-plan-2026-09-19 F6）实证：宿主 Agent 确认链已原生
支持逐 action 的效果判定、强制确认覆盖、会话级总是允许与确认超时
（`kernel/agent/agent.go:1691-1734`；`AgentChat.ts:4042-4060`），且 `siyuan`
1.2.7 已声明 `actionEffects` 符号（T-6476）。

## 决策

用户决断（2026-09-19，三选一取 A）：

1. 向 `addAgentCapability` 声明 `actionEffects`：只读动作显式
   `{localRead:true}` 免确认；写/批量动作声明 `{localWrite:true}` 走宿主确认卡。
2. 撤下自建审批三模块（约 177 行），确认/超时/会话放行语义全部交由宿主 UI 承担。
3. 执行链仅在能力检测到宿主确认链可用时提供；检测不到时保持现状（只读能力），
   不降级伪造确认路径。
4. `openDocument`/`openDocuments` 等已生产动作统一迁移到 `actionEffects` 声明，
   不保留两套确认路径。

被否决的备选：继续自建（可覆盖无确认链旧宿主，但 Android 真机硬阻塞不解除）；
混合双路线（覆盖最大，但两条确认路径都要开发与验收，范围最大）。

## 后果

- 自建弹窗的 Android 真机逐项验收阻塞解除，转为宿主确认卡的真机验证（仍需
  T-6305 场景，但验收对象是宿主 UI 而非本插件弹窗细节）。
- T-1219 退出条件改写：注册、卸载清理、权限拒绝、取消、异常输出均经宿主确认卡
  验证；门禁改动按 gate-audit 清单做负向验证。
- 无确认链的宿主（若存在）不提供执行链，只保留只读能力；配合 ADR 0064 的
  minAppVersion 下限抬升，该面进一步收窄。
- 撤除三模块后需同步清理其门禁登记与测试断言，防止"撤实现留死门"。
