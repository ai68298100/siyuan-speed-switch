# ADR 0115：工作台规格卡与生产目录双向审计

- 状态：已接受并完成（T-7023）
- 日期：2026-10-04
- 关联：T-6968、T-6969、T-6971、T-7023、ADR 0091、ADR 0101、ADR 0114

## 背景

T-6971 已产出 9 张规格卡，但规格卡、`DEFAULT_MODULES`、材质目录和默认档目录没有双向契约。审计发现导航批次仍有 3 个旧 moduleId 别名，终批重复 `clipped-unread`，生产布局归一化只保留四档，世界时钟和部分时钟/洞察组件的支持档不足以承载规格卡声明，另有 4 个默认/材质声明未与规格卡一致。

## 决策

1. 生产七档 `xs | small | medium | tall | wide | large | full` 继续作为布局持久化与渲染的唯一语义。规格卡中的 S/M/L/X 只作为设计审查速记，审计将其映射到七档；规格卡声明的支持档必须是生产支持档的子集，生产可保留既有兼容档。
2. `normalizeLayout` 接受完整七档，避免 `full`、`tall` 和 `xs` 在持久化读回时被清空。补齐世界时钟的 `wide/large/full`、年度进度的 `medium`、倒数日的 `large` 和使用时长的 `full`，不删除既有档位，不改变 schema 版本。
3. 按规格卡对齐默认档：时间与日期 `medium`、快速记录 `small`、每日放送 `medium`、服务状态 `small`；打卡摘要显式声明 `accent`。材质解析仍对未声明 moduleId 回退 `plain`。
4. 规格卡统一使用生产 moduleId，并移除终批重复卡，使 9 张规格卡与当前 58 个生产定义一一对应。
5. 新增双向审计测试：真实读取 9 张 HTML 规格卡并调用生产 `registerModules`、材质解析器和默认档解析器，校验 58 个 moduleId 的覆盖、唯一性、材质、默认档、支持档、目录键和七档归一化。

## 未采用

- 不把规格卡的设计审查字母迁移到持久化数据或用户界面。
- 不为了让数量相等而删除已有兼容档位或扩展未被规格证明的材质。
- 不为未声明组件增加自动取色；未知材质继续使用 `plain`。

## 验证

- 材质/尺寸/主页模型定向套件 **69/69** 通过；规格审计与商店契约的注入验证均按预期失败，源码哈希恢复通过。
- `pnpm exec tsc --noEmit`、构建、`pnpm run release:check` 和全量测试 **8289/8289** 通过；产物为 `dist/index.js` **1165038 bytes**、`dist/index.css` **294455 bytes**、`package.zip` **575423 bytes**。真实桌面与 Android 视觉/触控证据仍分别属于 B-005/B-004。

## 边界

本任务只收口规格、生产目录、布局归一化和商店/工作台共同消费的材质与档位声明，不改变组件 adapter 数据协议、第三方 provider 生命周期或用户现有布局的 schema 版本。
