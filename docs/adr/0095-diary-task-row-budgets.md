# ADR 0095：日记与任务长尾组件的首屏预算和写入边界

- 日期：2026-09-28
- 状态：已采纳（T-6982 / T-6971 批次⑨ B 组）
- 关联：`docs/design/component-specs-09-longtail.html`、T-6971、T-6981

## 背景

批次⑨ B 组包含今日日记、本月日记、近期日记、往年今日、今日待办、近期预约和闪卡待复习。旧实现已有大部分数据适配，但部分列表仍允许超过规格卡的首屏行数；近期日记没有字符摘要；预约查询可由旧配置带入过期项；今日日记入口不读取已有文档状态。

## 决策

1. `recent-daily-notes`、`on-this-day`、`today-tasks` 和 `today-reservations` 的 schema、归一化和投影分别钳制到 5、3、5、4 行；`today-tasks` 补齐规格要求的 small 档。
2. 近期日记和月度日记查询沿用有界 SQL，并为日记文档带出非文档块字符数。月度日记在快照中同时报告篇数、字符数和连续日期数；跨月选择仍由 `monthOffset` 决定。
3. 预约保留 `overdueDays` 配置键以兼容已保存配置，但归一化固定为 0；查询和纯投影都从本地今天开始，过期预约永不展示。
4. 今日日记只读探测当前日期的已存在文档，显示日期与字符数；已有文档行直接使用探测到的文档 ID 打开。缺失时显示创建指引，创建仅在用户点击动作后通过既有 `createDailyNote` 受控写入，不在刷新时自动创建。
5. 闪卡到期数继续来自思源 riff 统计 API。存在到期卡时追加进入思源闪卡复习的受控全局动作；统计为零时保持空态，不伪造可复习条目。
6. 今日待办继续复用 `flipTaskMarkdown` 与 `/api/block/updateBlock`，写入失败由既有控制器显示失败回执并强制刷新。

## 后果

- 小尺寸日记、任务和预约卡的首屏高度稳定，未来日期和过期预约不会混入列表。
- 旧配置中的 `overdueDays` 不再产生过期数据；用户仍可读取配置，不需要迁移存储。
- 日记统计多做一次受限相关子查询，但外层候选集仍有 `LIMIT 48`，不改变内核写入契约。
- 真正的闪卡复习界面仍由思源宿主提供；插件只提供入口和到期统计，宿主缺少全局命令时沿用受控不可用提示。
