# ADR 0199：第二面板紧凑小组件优先

- 日期：2026-10-16
- 状态：已接受
- 任务：T-7273 / T-7274
- 取代：ADR 0198 中的 Context Workbench 首屏层级提案

## 背景

用户明确指出第二面板新增内容“不好看”，不像想要的小组件，整体过大。当前证据与反馈对齐后，主要问题落在工作台窗口尺寸、默认组件尺寸/形状和视觉层级；Context Workbench、上下文头和语义分区不能解决这一问题。此前的 ObsidianArchive 参考只有视频截图，不能当作精确 UI 规格或实现文档。

## 决策

1. T-7274 先交付紧凑小组件静态对照原型，只使用 4～5 个现有内容类型，让尺寸形成小、宽、窄高等明显差异。
2. 原型删去模拟宿主导航、上下文分区、额外工具栏和底部状态区，只留轻量标题与添加入口。
3. 卡片以中性暖白为主，采用细边线和轻层级；限制彩色底块和阴影，不再叠加装饰背景。
4. 约 920×390px 的桌面窗口是对照实验起点，不是最终产品规格；按 1280×800、1920×1080、700px 侧栏和 375px 窄屏检查视觉密度及溢出。
5. 本 ADR 不修改生产 UI、homeSizeMode 默认值、已保存布局或现有用户的显式尺寸偏好。原型经过视觉评审后，才决定是否另起实现任务调整新装默认尺寸和首次播种尺寸。
6. Obsidian Canvas 与用户提供的 Archive 视频只作为卡片尺寸差异和紧凑排列的视觉参考；不复制未经核验的插件格式、交互或归档规则。

## 影响

- T-7274 聚焦视觉比例与小组件形态，不做 Context Workbench、Scenes、自由画布、新数据源或查询功能。
- 已保存布局继续沿用；若后续调整新装默认值，需要新增决策并验证迁移/不覆盖用户偏好的边界。
- ADR 0198 的上下文分区方向降为历史提案，不阻塞紧凑组件原型。
