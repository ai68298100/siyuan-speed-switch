# ADR 0108：关联内容 SWR 归一化与刷新事务

- 状态：已接受（T-7077）
- 日期：2026-10-03

## 背景

关联内容的持久层已经具备版本、年龄上限和 8 条容量上限，但归一化过程按输入顺序第一次看到某个 `rootId` 就标记去重。持久数据的顺序不是协议的一部分，旧条目排在新条目前面时，冷启动会错误保留旧投影。写入侧的内存淘汰也依赖 `Map` 插入顺序，已有条目更新后仍可能被当成最旧项淘汰。

工作台还可能在同一 `rootId` 上同时启动多次刷新。仅检查 `box.isConnected` 只能保证节点仍在 DOM，不能保证返回结果属于当前刷新；旧请求晚到时会覆盖较新的结果。

## 决策

1. `normalizeRelatedSwrStore` 先按 `rootId` 收集候选，重复项只保留最大 `at` 的有效条目，再统一按 `at` 降序和 8 条上限输出；不依赖持久数组的输入顺序。
2. 成功刷新通过 `mergeRelatedSwrEntry` 重新归一化后写回 `relatedSwrStore`，因此内存 Map 与落盘视图共享相同的去重、排序、年龄和容量规则。
3. 会话缓存更新时先删除同一 `rootId` 的旧项，再按 `at` 找最旧项淘汰，避免 Map 插入顺序代替真实新鲜度。
4. 每个 `rootId` 使用单调 request generation；只有当前 generation 可以渲染、写入缓存或结束请求，旧请求完成只允许退出，不得提交结果。
5. 已有持久缓存仍保持 stale-while-revalidate 语义：先显示缓存，后台刷新；请求失败或节点卸载不制造额外噪音，也不让旧请求删除新请求的节点。

## 未采用

- 不把持久数组位置当作“最新”依据，避免把某一次序列化顺序误当成数据语义。
- 不为每个工作台面板复制一份网络请求；generation 是同一 `rootId` 的提交闸门，不改变现有请求触发点。
- 不扩大持久条目数量、年龄上限或投影字段；容量与数据形态仍由既有 SWR 契约约束。

## 验证

- `tests/related-content-swr-matrix.test.cjs` 生成 4×4×4×4 = **256** 个乱序/重复/容量场景，并覆盖 merge 与 request generation 边界；连同既有关联内容模型套件共 **260+** 项通过。
- 负向验证：临时副本恢复“第一次重复项优先”的旧归一化逻辑后，矩阵对“最新投影必须保留”精确失败；生产工作树不写入临时副本。
- 类型、定向模型套件、全量测试、构建与发布检查在实现完成后执行并记录到当期账本。

## 边界

本 ADR 只处理关联内容 SWR 的数据归一化、缓存淘汰和刷新提交顺序，不改变内核 `/api/ref/getBacklink2` 契约，也不替代 B-005 所需的真实窄侧栏宿主视觉取证。
