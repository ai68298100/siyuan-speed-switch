# ADR 0122：标签树投影与虚拟父节点语义

## 状态

已接受（2026-10-04，T-6976）。

## 背景

`/api/tag/getTag` 的真实响应已经包含 `children`、`count`、`depth`、`name` 和 `label`。原标签组件把这些数据直接压成胶囊列表：层级只能靠路径文字表达，零计数的组织节点会被丢掉，用户无法判断它是空标签还是父级目录。

## 决策

1. 继续使用官方 `getTag`，消费其有界树和引用计数；不为已经提供计数的标签重复发 SQL 聚合请求。
2. 模型层把嵌套响应和带 `/` 的平面名称统一合并为树，最大深度 8、节点 128，按配置在兄弟节点内按名称或引用计数排序。
3. 真实计数为零但仍有后代，或仅为组织路径补出的节点，投影为虚拟父节点：显示计数、保留展开入口，但不携带 `tag:` 值，也不触发原生标签面板。
4. 视图以受控 `tag-tree` 类型渲染扁平前序行，用 `aria-level`、`aria-expanded` 和独立折叠按钮表达层级；折叠状态属于当前视图现场，不新增持久化键。
5. 搜索命中子节点时保留必要祖先，避免结果脱离树路径；点击仍以完整路径交给既有标签 dock 动作。

## 验收

- 模型测试覆盖嵌套排序、搜索祖先、虚拟父节点和完整路径值。
- 视图测试覆盖 `role=tree`、折叠/展开、焦点目标和虚拟父节点禁用动作。
- 保留 `getTag` 端点白名单与原有点击协议，不扩大内核写入或网络权限。
