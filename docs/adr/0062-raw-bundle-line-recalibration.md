# ADR 0062 组件深度优化收官后的 raw 自律线校准

日期：2026-09-19　状态：已采纳　关联：ADR 0059、T-6454、T-6455、T-6456

## 背景

组件深度优化专项（T-6348~T-6454，58/58）收官时，`dist/index.js` raw 体积为 784016
bytes，距 768 KiB 自律线仅余 2416 bytes。与 ADR 0059 时的情形相同：该线是自设的
自 discipline 信号（D-008 系），不是思源宿主限制；余量收敛到两千字节级是逐批合理
增量累积的结果，而非单次异常膨胀。继续开发（二轮增量建议、v0.23 发版前调整）将
必然越线，若不校准会迫使为守一个历史数字而压缩可读代码或砍功能。

## 决策

1. raw `index.js` 自律线从 768 KiB 调整为 **832 KiB**（851968 bytes）。校准后余量
   约 68 KiB，可容纳二轮增量批次与 v0.23.0 发版增量。
2. 不变的约束：`package.zip` 512 KiB 归档硬上限不变；zip 单条目压缩评审线 224 KiB
   （ADR 0059）不变；资源基线漂移诊断（SHA-256/字节快照）不变。
3. 832 KiB 仍是评审线而非放行线：每次跨越性增长仍须在账本记录真实增量来源；
   再次逼近时按同一程序重新评审，而非静默上调。
4. 修改资源门禁按 `docs/gate-audit-checklist.md` 做负向验证：临时把预算回退到
   768 KiB 以下（低于当前产物）确认 `release readiness matrix`/体积门禁精确失败，
   恢复 832 KiB 后通过且测试文件 SHA-256 一致。

## 后果

- 二轮增量建议（竞品调研 §11.2：countdown 双模式、year-progress 周期等）可以继续
  以功能与体验为先，不为几 KiB 的合理增量牺牲可读性。
- 门禁仍保留对异常膨胀的预警能力；归档硬上限与单条目评审线共同兜底真实发布风险。
