# ADR 0079：统一切换平台的外壳、表面与交互合同

- 日期：2026-09-25
- 状态：分阶段实现中（P1 视觉基础层 T-6867、表面导航 T-6868、路由上下文/单例/悬浮球恢复 T-6869 已落地；P2 片段与工作台组件对象、objectId 回跳已由 T-6878～T-6890 落地，跨表面动作继续按对象/动作分离原则增量推进）
- 关联：T-6865、T-6866、ADR 0076、ADR 0078、`docs/design-unified-platform-ui-2026-09-25.md`

## 背景

插件已经有三块主要能力：第一面板负责内容切换，第二面板负责信息组件工作台，第三面板负责代码片段管理和安全预览，悬浮球负责全局触发。它们目前由不同入口、不同头部和不同状态样式承载。尤其片段工作室使用独立的 `--studio-*` 视觉变量和独立选择器，用户会把它理解为外部工具，而不是平台的一部分。

如果直接把三个界面压成同一张卡片或一次性重写为 SPA，会牺牲搜索、网格、编辑器各自的工作效率，也会扩大回归范围。需要先固定平台层和表面层的边界。

## 决策

1. **建立一个平台外壳。** `PlatformShell` 提供品牌、`切换/工作台/实验室`表面导航、上下文栏、路由栈、焦点恢复、状态和关闭行为。表面 body 保留各自布局。
2. **把悬浮球定义为全局触发器。** 它不是第四个表面；轻触默认打开平台，更多动作复用同一 Action Panel 和 quick-action executor。平台回退入口不可删除。
3. **区分表面、对象和动作。** 表面使用 `SurfaceId`，对象使用 `content/action/workspace/widget/snippet`，展示描述和执行 handler 分离。未知 provider 可见，元数据或图标缺失不得阻止执行路径。
4. **统一 token 和状态语言。** 平台 token 以思源 `--b3-*` 为唯一颜色来源；`--studio-*` 仅在迁移期间保留兼容别名。三面板共享状态徽标、来源标签、能力说明、Action Panel、预览框、空/错/加载态和动效刻度。
5. **用路由栈保留上下文。** 跨表面打开对象时记录来源表面、焦点和对象 ID；关闭或返回后恢复。脏片段草稿和工作台布局编辑状态必须经过统一的 DirtyGuard，不得被表面切换销毁。
6. **保留片段安全边界。** 原生片段列表仍是唯一保存来源；CSS 预览保持 opaque-origin sandbox；任意 JS 执行仍禁用；AI 结果必须手动审核接受。移动端暂不开放片段编辑，真实设备证据另行验收。
7. **增量迁移，不做一次性重写。** 先加 token 和 DOM 适配器，再接外壳和路由，最后接统一对象/动作。现有动态 chunk、宿主 Dialog 和表面领域逻辑可以在过渡期继续存在。

首个跨表面动作只接入安全的 `openSnippetStudio` 导航描述（桌面支持，移动端显式不可用，失败回退切换器）；不把每条片段注册成快捷动作，以免把对象目录和动作目录混在一起。

T-6891 将同一边界用于悬浮球数字槽：槽位只持久化动作 ID 或保存的搜索 ID；保存的搜索仍由独立对象目录提供，执行时按 ID 回读当前对象并回放筛选，不把每条用户搜索注册成全局动作。目标失效时保留槽位并提示不可用，避免数字静默指向另一对象。

## 取舍

- 共享外壳会增加一层路由和状态协调，但能消除三个独立入口的认知成本，并为跨表面返回提供明确位置。
- 横向表面导航比桌面左侧常驻导航更适合当前紧凑切换器，也能自然退化为移动端横向滚动；工作台和实验室的内部侧栏仍由各自表面管理。
- 统一 token 需要清理片段工作室的独立颜色变量，但可以先保留别名，避免一次性改动造成视觉回归。
- 片段实验室不追求与第一、第二面板在所有端侧同时可用；能力状态诚实呈现比表面数量完整更重要。

## 后续退出条件

- 平台头部、表面导航、上下文栏、状态徽标和 Action Panel 在三个表面中有可复用实现。
- 跨表面跳转、返回、关闭、脏草稿守卫和焦点恢复有自动化验证。
- 桌面宽弹窗、窄侧栏、明暗主题和真实移动端证据分别通过；浏览器响应式结果不计作 Android 验收。
- 片段 JS 安全边界、AI 手动接受和原生列表保存语义未被统一外壳改写。
