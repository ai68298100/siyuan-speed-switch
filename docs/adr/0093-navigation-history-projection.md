# ADR 0093：导航历史组件的宿主顺序与本地元数据投影

- 日期：2026-09-28
- 状态：已采纳（T-6980 / T-6971 批次⑧）
- 关联：`docs/design/component-specs-08-navigation.html`、T-6478、T-6971

## 背景

批次⑧要求导航列表显示相对时间、路径和失效状态。思源的 `/api/storage/getRecentDocs` 已经提供稳定的历史顺序和打开时间，但返回协议不保证当前文档仍存在，也不包含可依赖的路径字段。直接把历史响应当作可打开文档会留下失效入口；把历史改写成全量 SQL 又会丢掉宿主维护的打开/关闭顺序语义。

## 决策

1. `recent-documents` 继续以 `/api/storage/getRecentDocs` 作为顺序、标题和时间的权威来源。
2. 首屏投影后，对最多 8 个候选 ID 发一条有界 SQL 元数据查询（`type='d'`、`LIMIT 12`），缺失 ID 保留为「已失效」行并禁用点击；查询失败交给既有快照保留/错误管线。
3. 时间在纯模型中按今天、昨天、月-日格式化；14 位宿主时间戳、秒级和毫秒级输入均归一，未知时间不伪造文案。
4. 批次⑧列表统一在投影模型中钳制首屏行数：最近/大纲 8、置顶 6、收藏 8、标签 12、书签 6、文档集 5、关系摘要 6。置顶源列表另有 64 条容量边界。
5. 失效的置顶、收藏、固定文档和最近历史条目保留可读占位但禁用动作；固定文档提示从设置中重新指定。书签若宿主返回块和根文档 ID，则带块目标打开，缺少完整 ID 时回退原生书签面板。

## 后果

- 宿主历史顺序不被本地 SQL 重排，跨日显示由插件本地时钟决定。
- 最近文档一次刷新最多增加一条小型 SQL 查询；缓存和 1200ms 超时仍由现有适配器管线负责。
- 书签 API 当前只保证名称、数量和延迟块数组字段，完整块 ID 不出现时无法伪造定位，继续走原生面板回退。
- 默认档位、列表行解剖、标签胶囊和失效行样式均由批次⑧契约测试覆盖，并已做违规注入验证。
