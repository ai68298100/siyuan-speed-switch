# ADR 0084：UI 设计规范 v1.0 作为界面设计唯一事实源

- 日期：2026-09-27
- 状态：已接受
- 关联：ADR 0073（皮肤）、ADR 0078（片段边界）、ADR 0079（平台状态语义）、ADR 0080（默认全屏）、T-6866、T-6870、T-6877、T-6928

## 背景

平台 UI 的设计结论分散在多处：T-6866 设计合同（定位/外壳/对象动作状态模型）、T-6870/R2 逐屏原型与六条应用模式、RZ-1~RZ-6 细节批、各专项 ADR 与 `_platform-shell.scss` 生产令牌。缺少一份"做新界面时先读哪一份"的权威规范，评审口径依赖口头记忆，长期必然漂移。

## 决策

1. **设立 `docs/design-system-v1-2026-09-27.md` 为 UI 设计唯一事实源。** 它收敛而非新造：所有取值（令牌刻度、六态、控件高度、文字刻度、布局定案）以既有 ADR 与生产实现为准；冲突时本文档服从已接受的 ADR，修正走新 ADR。
2. **配套组件画廊原型 `docs/design/design-system-gallery-2026-09-27.html`。** 自包含、明暗双主题可切换，用于评审组件状态；逐屏布局仍以 R2 原型为基准，两者职责不重叠（画廊管零件，R2 管整机）。
3. **不建立第二套视觉系统的约束不变。** 规范明确颜色唯一来源是宿主 `--b3-*`，`rz-*` 提案类名不进生产；新颜色/圆角/间距值进入规范前必须先论证并落入 token 层。
4. **规范变更即契约。** 后续 UI 改动以规范为评审依据；改动规范本身须同步相关契约测试并按 `docs/gate-audit-checklist.md` 负向验证。

## 后果

- 新界面/新组件有统一的入门文档与验收口径（规范 §11 扩展性指南直接给出 checklist）。
- 文档需随实现演进维护；出现"实现与规范不一致"时默认改实现，除非新 ADR 裁决改规范。
- 规范是纯文档，不影响包体与测试计数。
