# ADR 0156：全路径边界审计与 v0.46.4 修复

- **日期**：2026-10-09
- **状态**：accepted
- **关联任务**：T-7227
- **范围**：第一面板、第二面板、设置差异弹窗、已存搜索编辑器及组件目录公开说明

## 背景

v0.46.3 的全路径复核后，仍有几类不依赖特定主题即可复现的边界风险：宿主或主题重写 Dialog 内容后留下没有出口的空壳；分组重绘后搜索现场失配；排序浮层在窗口尺寸变化后停留在旧坐标；已存搜索的笔记本清单暂时不可用时会静默丢失原范围；收藏分组标题把文本当 HTML 转义；README 对路径筛选和组件就绪条件的描述已经落后于生产行为。

## 决策

1. **Dialog 失败边界统一销毁**：生产 Dialog 创建后，如果根节点或必需控件不存在，立即 `destroy()` 并结束装配。已有入口焦点恢复链由 `destroyCallback` 继续负责；没有已装配资源的路径也必须销毁空壳，避免遮罩和异步资源残留。
2. **显示文本与 HTML 上下文分离**：Dialog 的 `title` 作为纯文本传入；只有插入 HTML 属性或文本模板时才做属性转义，避免用户文档标题中的 `&`、引号等字符被显示成实体。
3. **重绘保持现场**：分组改变后重新应用当前搜索/筛选；挂在 `body` 的排序浮层注册窗口 `resize` 重定位，并由现有 disposer 移除监听。
4. **编辑保存不静默降级**：已存搜索的 notebook 范围先以 fallback option 保留，清单异步返回后复用该 option 并更新标签；清单失败时原范围仍可被保存。
5. **事实文案必须跟随生产能力**：README 中的路径筛选和组件目录说明以当前代码、readiness 状态和可用性分类为准，不把条件组件写成无条件开箱即用。

## 验证要求

- 每个新边界至少有正向契约和删除关键声明后的负向注入验证。
- 运行完整自动化、TypeScript、构建/发布检查和 UI smoke；真实 Android、读屏、最窄侧栏及第三方账号仍按 `BLOCKERS.md` 取证。
- 该批变更以 v0.46.4 patch release 发布，README 首屏按“新增 / 优化 / 修复”列出内容。
