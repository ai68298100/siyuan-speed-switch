# ADR 0104：片段备份恢复采用预览、单次撤销和回读核对

- 日期：2026-10-02
- 状态：已接受（T-7073 / AB-1304 第二阶段）
- 关联：T-6991、T-7025、ADR 0078、ADR 0100

## 背景

片段实验室已经可以保存、删除和把失败/冲突草稿放入回收站，但全量备份恢复仍缺少一个诚实的事务边界。思源原生片段接口是整表替换，不提供 CAS；如果先写入再解释差异，用户无法确认哪些行会新增、替换、删除，也无法在恢复失败或跨窗口变化后判断当前状态。

## 决策

1. 备份是版本化、大小有界的 JSON 文本，只包含原生片段字段和 CSS/JS 总开关；不包含个人文档、token、预览 HTML 或任意脚本执行结果。
2. 恢复必须先读取当前快照，生成按片段 ID 分组的新增/替换/删除/保持差异；默认全选，但用户可以取消任意组。没有确认不得写入。
3. 确认前保存当前快照为会话内单次撤销槽。撤销槽不写入持久化存储，恢复成功后才可使用一次；再次恢复会替换旧槽并给出明确提示。
4. 写入顺序为：重读并比较基线 → 写入片段列表 → 写入总开关 → 再读回列表和开关。任何回读失败都标记为“可能已落地”，禁止伪报完全失败；冲突则停止写入。
5. 工作室获得焦点、从隐藏恢复和宿主片段广播事件时触发有界刷新；刷新只替换原生列表和目录状态，脏草稿、焦点和预览不被静默覆盖。

## 后果

- 用户在整表替换前能看到可解释差异，并能在同一会话撤销一次恢复。
- 原生列表仍是唯一真源；备份和撤销槽不是第二份长期配置。
- 旧宿主没有广播事件时，焦点/可见性刷新仍提供最佳努力；不能把浏览器事件当作真实跨窗口原子同步。
- 备份导入失败、过大、重复 ID、未知版本或缺字段均零写入。
