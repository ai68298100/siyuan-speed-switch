# ADR 0114：组件商店桌面全屏并以内联预览为主路径

- 状态：已接受并完成（T-7084，承接 T-7024）
- 日期：2026-10-03
- 关联：T-6967、T-6999、T-7023、T-7024、T-7034、ADR 0091

## 背景

组件商店已经具备左目录、右详情、首项选中和独立预览 Dialog，但用户仍需点击第二次才能看到真实组件。独立 Dialog 还把预览生命周期与目录选择分开，目录切换无法自然表达“旧预览立即取消并释放”。工作台和商店也缺少同一材质与尺寸声明的消费点。

## 决策

1. 桌面商店 Dialog 使用 `sw-dialog--fullscreen` 和 `sw-home-store-dialog`，覆盖当前视口；移动端继续使用原有底部 sheet 尺寸和详情路径。
2. 抽出 `mountStoreWidgetPreview` 作为唯一预览挂载器。独立预览入口暂保留为兼容函数，但商店详情不再创建重复的预览按钮或第二个 Dialog。
3. 详情选中组件后立即创建 `sw-home-store__live-preview`，调用同一 `createHomeModuleController`、同一 `homeRuntime.read`、同一来源/隐私回执和同一尺寸语义。目录切换和商店销毁先调用当前预览的幂等 disposer。
4. 详情尺寸按钮通过 `setSize` 更新预览的 `data-size`、尺寸回执和读取参数；修改尺寸只刷新预览，不自动写入工作台，提交仍由添加/应用按钮负责。
5. 内联预览使用 `resolveHomeTileMaterial`，未声明组件仍回退 `plain`，避免商店与工作台产生第二套材质规则。

## 未采用

- 不把移动端改成全屏，保留移动端列表到 sheet 的空间和返回语义。
- 不把目录卡片的静态骨架当作实时预览，也不同时维护静态和实时两套详情预览。
- 不修改 provider 注册、数据读取、缓存或用户布局持久化协议。

## 验证

- 新增 `tests/store-inline-preview-contract.test.cjs`，覆盖桌面全屏、移动 sheet、首项内联预览、尺寸刷新、目录切换释放、重复 Dialog 删除和样式作用域；包含负向注入验证。
- 既有商店/预览定向测试 **185/185**，主页商店模型与可靠性 **472/472**，TypeScript 检查通过，生产构建通过。
- 新增 `tests/e2e/store-inline-preview.spec.mjs`，真实思源 3.8.6 前端 **1/1** 通过：打开工作台→进入商店→核验桌面全屏尺寸、实时预览完成、尺寸切换和目录切换后的预览重建。原有 `workbench-information` 的旧回执/窗口尺寸假设单独保留，不作为本任务证据。该证据仍属于真实 E2E 宿主，不等同 Android 真机证据。

## 边界

内联预览的真实数据取决于组件 adapter 和当前思源工作区；读取失败显示既有错误/缓存状态。Android 触控、旋转和移动 sheet 仍由 B-004 后置矩阵补证。
