# ADR 0100：片段回收站数据策略（T-7025）

日期：2026-09-30 · 状态：采纳 · 关联：T-7025、T-7045（写入后待确认态）、T-6958（冲突比较）、D-401（存储版本戳仪式）

## 背景

片段实验室的保存覆盖、删除与冲突放弃都是不可逆写入：原生片段列表是唯一真源，一旦覆盖/删除，旧内容即刻丢失。用户要求独立回收站保留这些旧版本，支持恢复、永久删除与有界自动清理。

## 决策

### D1 进入来源（仅三种，明确枚举）

1. **overwrite**：对已有原生片段（baseline 存在）保存修改且内容确有变化——写入前捕获旧版本快照，**原生写入确认成功后**才登记；
2. **delete**：删除原生片段——删除确认前捕获快照，删除成功后登记；
3. **conflict**：冲突界面选择「放弃并重载」——被丢弃的本地草稿登记（冲突副本路径已另存禁用副本，不重复入站）。

### D2 写入顺序与诚实性

登记动作永远在**原生操作确认成功之后**：登记失败只影响回收站完整性，不回滚原生写入、不虚报原生操作失败（不伪造原子回滚）。捕获快照与登记之间用「事务内临时变量」传递，不落中间态。

### D3 去重与淘汰（三限）

- 去重：同 `snippetId + content` 的条目在**5 分钟窗口**内只保留最新一条（冲突/覆盖连击不刷屏）；
- 数量上限 **50** 条：超限从最旧端丢弃；
- 年龄上限 **30 天**：启动与每次写入时清理过期项；
- 字节安全上限 **256 KiB**（仅计 content 与 name）：总量超限从最旧端丢弃直至回到线内。
淘汰是**有界清理**而非报错；清理计数进写入回执。

### D4 独立存储与 D-401 仪式

独立 key `sw_snippet_recycle`（HANDLED key）：store 携带 `version: 1` 版本戳，normalize 对畸形条目丢弃、非法版本整体重置为空 store（沿用 sw_related_swr 语义）。登记进 KEY_ORDER、storage-compatibility-matrix（文档↔代码双向契约）、存储页分组登记（系统组），计数契约 16→17 同步演进。

### D5 恢复语义

恢复 = 以快照内容**新建草稿**（走既有 choose 事务，过 T-6956 脏稿三选一守卫），新 id、`enabled=false`、不自动启用、不覆盖原片段；原生启用开关仍由唯一真源决定。永久删除/清空需 confirm 二次确认并如实回执。

### D6 非目标

不做普通撤销栈（T-6957 草稿撤销已覆盖编辑态）；不做跨设备同步；不执行 JS；不保存未声明的文档内容或网络数据；AI 生成但从未保存的草稿不入站（从未存在于原生真源）。

## 后果

- 原生写入路径增加一次快照捕获与一次插件存储写入（防抖队列），写入量有界（三限封顶）。
- 回收站视图（列表/恢复/永久删除/清空/回执）为 T-7025 第二阶段，数据层先行不提供用户入口前条目已受三限约束，无失控风险。
