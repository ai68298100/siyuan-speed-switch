# ADR 0076：工作上下文导航路线与统一结果模型

- 日期：2026-09-23
- 状态：已接受
- 关联：调研报告 `docs/research-cycle-r4-2026-09-23.md`、ADR 0072、ADR 0073、ADR 0075
- 关联任务：T-6811～T-6824

## 背景

v0.32.0 已经具备页签切换、统一索引、查询语法、拼音辅助匹配、文档集恢复、跳转栈、场景预设、Essentials、宿主命令桥、三端 UI 和 Agent 只读能力。外部调研显示，Quick Switcher++、PowerToys Command Palette、Omnisearch、Workona、Capacities、QuickAdd 以及思源社区的文档搜索/反链插件，长期价值都集中在“统一入口、可解释排序、工作现场恢复、关联内容和可控动作”几个共同问题上。

如果继续按单功能堆叠，会产生多个互不相容的结果列表、排序规则和执行入口；如果直接复制完整搜索引擎或主页，又会偏离插件定位、增加宿主和包体风险。

## 决策

1. **产品定位固定为“思源笔记的本地优先工作上下文切换器”。** 导航层、上下文层和动作层共享一个领域语义；它不替代思源原生搜索、文件树、历史、同步或主页。
2. **先复用现有基础，不建立第二套架构。** 统一索引、搜索会话、结果去重、文档集恢复、动作 registry、宿主命令 bridge 和三端生命周期继续作为唯一底座。
3. **统一结果模型先于新功能。** `buildNavigationResultModel` 只负责有界分组、来源标记、稳定键和数量诊断；展示层负责布局，执行层继续读取原有 command/adapter registry。模型不得保存函数、DOM、全文正文或凭据。
4. **开发顺序采用五阶段：**
   - 第一阶段：导航可靠性、搜索排序诊断、移动真实设备证据和宿主健康状态；
   - 第二阶段：关联内容、工作区恢复 2.0、低打扰预览、动态收藏组；
   - 第三阶段：快速捕获、提供方协议、键盘优先、深链接；
   - 第四阶段：移动一等表面、密度/布局/皮肤和可迁移配置；
   - 第五阶段：在检索质量、来源解释和权限矩阵稳定后再评估 Agent/语义检索。
5. **每个方向必须先有纯模型和退出证据，再扩大 UI。** 结果上限、来源、失败原因、宿主能力和移动端可用性都必须可测试；真实 Android/桌面验收与浏览器夹具分开记录。
6. 不引入任意 SQL/JS、GPL 代码、系统级跨应用覆盖层、复杂语义索引或新的大体积依赖；frecency 先留在候补池，等待真实使用数据。
7. 门禁只保留有明确用户、宿主兼容、数据安全、无障碍/触控、回归或集市合规价值的约束；测试计数、模块数量和包体自律线属于观测指标，因合理功能增量触发时按实测校准，不把它们当成产品限制。

## 首个落地切片

T-6812 在已有 `src/search-model.js` 中加入 `buildNavigationResultModel`，并让统一索引渲染经过该模型。它不改变现有视觉和激活语义，只把结果分组、来源、稳定键和有界计数固定下来；后续 tabs、opened、global、actions、related 等提供方按同一契约接入。

## 退出条件

- 统一结果模型的分组顺序、来源标识、上限、截断计数和畸形输入降级有纯函数测试；
- 搜索/动作执行仍由既有 registry 和 host adapter 完成，模型不持有副作用；
- 全量测试、类型检查、生产构建和相关 smoke 通过；
- 每个需要宿主能力的阶段都有真实桌面/Android 证据或明确的 `BLOCKERS.md` 阻塞记录。
