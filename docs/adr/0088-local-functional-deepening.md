# ADR 0088：本地可验收的功能深化路线

- 日期：2026-09-27
- 状态：已采纳（规划），功能 T-6949～T-6961 待开发
- 关联：T-6948、ADR 0076/0079/0082/0086/0087、[执行计划](../dev-plan-2026-09-27.md)

## 背景

用户要求完整复核愿景、目标、功能与 UI，并列入至少十项无需宿主实际验证的后续功能。此前路线中多个“现行”小节和原型建议并存，部分基础问题已在生产修复；“等待真机反馈”不应使无需宿主的新功能全部停滞。

## 决策

1. 保持「本地优先的统一切换与工作上下文平台」：切换器、工作台、片段实验室各司其职，悬浮球只作触发器；不新增搜索、动作或片段存储架构。
2. 下一阶段按 T-6949～T-6961 的 13 项用户可见增量推进：阅读与复用、工作台与版本透明度、草稿保护、编辑预览与配置迁移。新执行计划在排期上优先于旧路线“现行”和等待反馈表述；原安全和迁移约束不被覆盖。
3. 三面板继续取消重复宿主大标题、对齐平台顶部。第一面板保持已交付的预览面积和轻边框；功能操作进入各自局部工具栏。工作台聚焦内容/编辑/健康，实验室聚焦编辑/效果/保存风险，不强求主体同构。
4. 本批开发验收使用纯模型、生产 DOM、普通 Chromium 夹具和已有适配器 mock，不要求启动思源内核或个人实装；必须验证生产接线。真实宿主兼容和本地开发完成分开记账，浏览器不冒充实装证据。
5. 保持既有读写权限。固定预览与局部查找不增加取数；撤销仅对会话编辑生效；配置包沿用白名单；原生片段仍为唯一保存真源。CSS 静态沙箱不扩权，JS 不执行，AI 仅人工接受。
6. 配置包 UI 不宣称现有多 key 保存具有原子事务保证；冲突 UI 不宣称客户端检查等同服务端 CAS。保存失败、二次冲突和取消必须真实呈现。
7. 本轮只落盘方向和功能计划，不把新增测试/文档/重构计为功能，不自动开始实现。后续按每批 3～4 项做本地里程碑，不 push、不发布、不覆盖个人安装。

## 取舍与退出条件

优先深化已被使用的三面板，放弃用新增组件数量代表进度。沿用十组设置和既有数字键语义，避免为这批功能引入额外产品裁决。低频 UI 需审计分包与包体，体积线按 ADR 0059/0076 有证据地处理。

13 项均须具备已有基础、增量范围、UI 入口、非目标及无宿主验收路径。实现阶段发现必须新增宿主能力时，先缩小到已定义范围，无法兑现则单项记阻塞、继续其余任务；不得悄悄将本地验收改成个人宿主验收，也不得用 mock 掩盖未接线。
