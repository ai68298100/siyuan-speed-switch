# ADR 0099：三面板与悬浮球模块化可见性开关（T-7026）

日期：2026-09-30 · 状态：采纳 · 关联：T-7026、ADR 0079（统一平台 UI）、ADR 0072（悬浮球撤出侧栏）、T-7012（平台外壳合同）

## 背景

当前平台有四个可独立工作的模块：切换器（第一面板）、工作台（第二面板）、片段实验室（第三面板）与悬浮球（全局触发器）。入口分散在思源顶栏（**两个**并列入口：切换器 + 组件面板）、侧栏 dock、手机端顶栏/FAB、插件命令、快捷动作目录与 SurfaceNav。用户要求能按模块开关显示与可用性，同时保持一个统一平台入口。

## 决策

### D1 「启用」与「可见」采用单一语义

不做「功能启用但入口隐藏」的两层模型——两层会让用户面对"关了开关还能从命令打开"的困惑。开关即**可见且可进入**：禁用模块的所有入口（SurfaceNav 项、顶栏菜单项、快捷动作、悬浮球回退目标）隐藏，路由层对残留调用（命令、Agent 动作、保存的回跳目标）**诚实回执拒绝**，不静默也不降级打开。

### D2 切换器是平台根，不提供开关

切换器承载搜索、收藏、最近、日记等高频入口，是防锁死保底：它永启用、不可关闭。可开关的模块为**工作台、片段实验室、悬浮球**三项，默认全部启用。设置页自身永不被隐藏（非目标明确）。

### D3 顶栏收敛为单一统一平台入口

移除「组件面板」顶栏按钮（secondPanelTopBar），保留切换器顶栏按钮作为**唯一**平台入口；其右键菜单动态列出全部已启用表面 + 设置。工作台仍可经 SurfaceNav、快捷动作、命令、菜单四条路径进入，入口收敛不等于入口减少。

### D4 路由层唯一校验点

`openPlatformSurface()` 是平台表面唯一分发点（T-7012 合同），在此早期校验目标表面是否在「端侧可用 ∩ 模块启用」集合内：禁用时 `showMessage` 诚实回执并返回，不打开。`getAvailablePlatformSurfaces()` 追加模块过滤——SurfaceNav `available`、悬浮球回退目标、设置预览入口等既有消费方自动继承，不另设第二套判定。命令（snippetStudioOpen/secondPanel）与 Agent 动作均汇入该路由，自动被覆盖。

### D5 已开面板保留至用户关闭

禁用开关后：已打开的面板 Dialog **不销毁**（避免丢编辑现场），仅新路由被拒；用户关闭后不再从任何入口打开。回执文案如实说明"已停用，已打开的窗口保留至关闭"。

### D6 存储与迁移

设置新字段 `moduleVisibility: { workbench: true, studio: true, floatingBall: true }`：DEFAULT_SETTINGS 显式默认全开；normalizeSettings 对非对象/缺字段/非法值逐键回落默认（布尔归一），无版本迁移需求（缺省=全开，向后兼容旧配置）。悬浮球开关叠加既有 per-surface `floatingBall.enabled`（ADR 0072 端侧语义不变）：模块级关闭则任何端都不挂载。

### D7 快捷动作过滤

内建目录中 `value: "home"`（工作台）与 `"snippet-studio"`（实验室）两项在渲染管线按模块开关过滤——禁用模块的动作不出现在工具栏/更多面板/悬浮球面板，也不可执行（执行走路由层校验兜底）。第三方 provider 动作不经此判定（其能力声明自有契约）。

## 后果

- 防锁死成立：切换器永在，平台至少一个表面可进入。
- 顶栏从两入口变一入口是用户可见行为变化，随下版 CHANGELOG 说明。
- SurfaceNav/悬浮球/设置预览经 `getAvailablePlatformSurfaces()` 自动继承过滤，无需逐点改造。
- 明确不做：设置页隐藏、按端差异化模块开关（桌面/移动共用一套）、第四个入口系统、已开面板强制销毁。
