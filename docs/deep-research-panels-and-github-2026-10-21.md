# 小驴雷切全表面功能专项深度研究与 GitHub 治理优化报告

- 调研日期：2026-10-21
- 目标：逐一针对小驴雷切三大主面板（第一面板切换器/穿透检索/动作画板、第二面板工作台/小组件生态、第三面板代码片段实验室）及全局交互表面（悬浮球/设置/文档集）进行全景功能与交互深度解构；全面扫描 GitHub Actions CI/CD 流水线、Release 资产与社区治理配置，制定下一步高质量自驱演进路线。

## 一、 第一面板：切换器、深入穿透检索与次级动作画板

### 1.1 现状架构与核心能力
- **双层检索编排**：本地 MRU 已开页签立即过滤（0ms 响应） + 异步防抖内核检索（180-250ms 取消旧请求与最新代际标记覆盖）；
- **符号多模态穿透检索中枢**：
  - `@标题` / `:标题`：穿透当前活动文档或跨文档大纲（H1~H6）树形结果；
  - `^正文块`：生成安全只读参数化 SQL，深入全库段落、代码块与列表块，排除根文档块干扰；
  - `#标签` / `!书签`：直连内核 `/api/tag/getTag` 与 `/api/bookmark/getBookmark`，递归聚合标签/书签树；
  - `>命令`：全局动作与思源原生命令过滤执行；
  - `?速查指引`：纯本地内存聚合 8 项关键符号穿透与快捷键速查条目（CheatSheet）；
  - 富文本关键词高亮：自动剔除语法前缀，提取纯净搜索词，`<mark class="sw__search-mark">` 多词 AND 分词高亮与 XSS 防护；
- **次级动作画板（Action Palette，⌘K / Ctrl+K）**：
  - 声明式 DOM 模型（`role="dialog"` + `role="listbox"` + a11y 完整属性）；
  - 动作分流：激活、右侧分屏（`open-right`）、下方分屏（`open-bottom`）、只读预览（`open-preview`）、在思阅中阅读（`open-in-reader`）、在思播中打开（`open-in-media`）、保存为文档集（`save-as-doc-set`）、撤销关闭（`undo-closed-tab`）、置顶/收藏切换、复制块超链/Markdown 双链/ID/路径；
  - 交互增强：同 section 内部 MRU 动态前置排序、卡片获焦时免呼出单键快捷直达（`Alt+Enter`、`Alt+C/M/P/D/R/V` 等）；
  - 34% 独立阅读预览窗格：固定头部、正文独立滚动、大纲提取与块高亮。

### 1.2 现存痛点与竞品差距（对标 Raycast & Obsidian QS++）
1. **大库结果滚动性能**：当检索全库产生超过 50 条块结果时，DOM 节点瞬时全量创建可能引起轻微掉帧，缺少虚拟滚动（Virtual List）或渐进分页（Pagination）；
2. **动作画板自定义能力**：目前动作列表的分区与默认项为编译期内置，高级用户希望能够自定义常用动作的置顶收藏或隐藏低频动作；
3. **复合搜索语法**：尚未支持在特定笔记本范围内穿透大纲（如 `notebook:日记@总结`）。

### 1.3 专项演进方案
- **演进 1：长列表轻量虚拟视口渲染**：当穿透检索条目超过 30 条时，采用可视区按需挂载 DOM，将首开渲染帧时间压降至 16ms 以内；
- **演进 2：动作画板自定义与用户偏好持久化**：在设置页提供“动作画板管理”子项，支持用户勾选启用/禁用特定次级动作，并提供自定义快捷键映射；
- **演进 3：复合范围穿透过滤器**：增强 `parsePenetrationQuery`，支持 `notebook/path` 与符号前缀级联过滤。

## 二、 第二面板：工作台（Workbench Bento 网格与小组件生态）

### 2.1 现状架构与核心能力
- **12 列响应式 Bento 网格**：支持桌面宽屏（4~6列自由排版）、iPad 中视口（3~4列）与手机端（单列/双列并排），严格遵循 Apple Bento 同心圆角比例；
- **三维小组件生态**：
  - **思源原生类**：近期文档、今日日记、今日待办（0ms 乐观打勾与划线衰减）、收藏、文档集、标签、书签、月度日记、笔记统计、年度时间进度、属性视图看板（`database-board`）、闪卡复习（`flashcard-review`）；
  - **生活与资讯类**：时间日期（等宽去壳）、OpenMeteo 天气、Bangumi 每日放送、DailyHot 热榜、NewsNow 资讯、HackerNews 新闻、ActivityWatch 用时、UptimeKuma 服务状态、Frankfurter 汇率、Miniflux/RSS 订阅；
  - **小驴打卡桥接类（7 项）**：今日打卡、连续记录、打卡热力图、本周打卡、近期事项、本月打卡、打卡摘要，只读消费 `window.siyuanCheckin` 生态 API v4；
- **小组件商店与诊断机制**：
  - 主从双栏架构（左侧分类/来源目录，右侧卡片详情与实时内联预览）；
  - 健壮状态机（ready / stale / loading / error / blocked / timeout），支持失败脱敏诊断复制与手动强制重试。

### 2.2 现存痛点与竞品差距（对标 Craft & Apple iPadOS 桌面组件）
1. **编辑模式拖拽手感**：目前卡片重排依靠偏移按钮或基础拖拽，缺少像 Apple 桌面一样的**半透明占位影子轮廓（Drop Phantom）**和平滑物理挤压动效；
2. **场景预设（Presets）一键套用**：新用户从零配置工作台有一定探索成本，缺少“学习研究”、“项目复盘”、“极简日常”等场景化预设布局的一键切换与预览；
3. **小组件深色对比度精细化**：个别第三方卡片在极端自定义主题下的对比度仍需自适应微调。

### 2.3 专项演进方案
- **演进 1：物理感拖拽落点指示器**：在工作台编辑模式下，实现基于鼠标移动计算的实时虚线卡槽（Drop Slot），松手即按新顺序持久化并支持 Undo 一键撤销；
- **演进 2：场景预设模板库（Workbench Scene Presets）**：内置 3~4 套开箱即用的黄金网格排版预设，套用前支持无损预览与随时一键恢复既有布局；
- **演进 3：小组件分组折叠与看板增强**：为属性看板（`database-board`）支持点击直接在侧栏或下方展开特定行详情。

## 三、 第三面板：代码片段实验室（Snippet Studio 与安全沙箱）

### 3.1 现状架构与核心能力
- **双栏安全沙箱架构**：
  - 左侧：轻量代码编辑器（行号列、语法关键词高亮、快速保存与元数据编辑）、AI 辅助（受控单片段上下文、64KB 截断与 SSE 流式中断）；
  - 右侧：只读沙箱实时预览（Protyle 核心元素模拟：H1~H6、段落、引用、列表、表格、代码块，严格禁用危险脚本与音视频执行）；
- **核心工程模型**：
  - 纯前端状态机 CSS 格式化器（`formatWithCursor`，格式化并精准保持光标偏移，零 Prettier 依赖）；
  - 3 模式增量导入引擎（Merge 合并保留启用态、Fork 分叉派生、Overwrite 全量替换）；
  - 回收站治理（50 项 / 30 天 / 256KB 三限淘汰，支持清空与恢复）；
  - Gist 凭据四点脱敏（`••••cdef`）、未列出声明（`public: false`）与 UserCSS 变量导出。

### 3.2 现存痛点与演进方案
1. **代码片段分类树**：随着用户片段增多，平铺列表容易显得冗长，可在左侧增加按“主题样式”、“排版美化”、“功能增强”三级文件夹折叠；
2. **批量启用/停用开关**：在标题栏提供一键安全“全部停用（Emergency Disable）”按钮，方便用户排查主题样式冲突；
3. **语法高亮轻量增强**：为 CSS 编辑区增加轻量正则行内颜色标记（如 `#hex` 或 `rgb()` 旁展示色彩小圆点）。

## 四、 全局交互：悬浮球、设置中心与文档集会话保护

### 4.1 现状架构与核心能力
- **全局悬浮球（Floating Ball）**：
  - 自由拖拽停靠、离边吸附（避开宿主侧滑激活条）、空闲半隐；
  - 核心手势：轻触打开切换器、四向快滑（上/下/左/右绑定不同快速动作）、右键/Shift+F10 呼出搜索式更多动作面板；
- **文档集会话保护（Document Sets，Spaces）**：
  - 版本历史（最多保留前 3 版覆盖快照，支持无损版本回滚）；
  - `save-as-doc-set` 一键将当前工作区所有已开页签固化为带时间戳快照；
  - 批量打开 6 态安全回执与失效项跳过；
- **设置中心（Settings Sections）**：
  - 10 个独立标签页，支持跨标签多词 AND 匹配与真实 DOM 控件高亮聚焦；
  - 严谨预算守护（配置体积有界、损坏数据降级自愈）。

### 4.2 专项演进方案
- **悬浮球手势直达符号指引**：支持将向上快滑手势直接绑定为呼出“符号导航速查指引（CheatSheet）”或“次级动作画板”；
- **文档集按项目分类归档**：支持在设置页为文档集添加自定义标签或项目分组。

## 五、 GitHub 仓库工程与持续集成（CI/CD）专项优化

### 5.1 现状审计
- **CI 工作流（`.github/workflows/ci.yml`）**：
  - 触发分支：`main`, `master`, `dev/thispc-1002`, `dev/**`，以及 PR；
  - 执行步：Node 24.15.0、pnpm 缓存、Playwright Linux Chromium 安装、Type Check（`tsc`）、Reproducible build audit（`repro:audit`）、Unit tests（`test`）、Smoke test（`test:smoke`）；
- **Release 工作流（`.github/workflows/release.yml`）**：
  - 触发标签：`v*`；
  - 执行步：版本号校验（`release-version-preflight.cjs`）、全量发布门禁（`verify:release`）、包完整性审计（`package-integrity`）、GitHub Release 上传；
- **安全与社区配置**：
  - `.github/SECURITY.md`、`.github/dependabot.yml`、Issue 模板与 PR 模板齐备。

### 5.2 发现的优化空间与落地方案
1. **CI 门禁覆盖度升级**：
   - 目前 CI 只执行了 `pnpm test` 与 `pnpm test:smoke`，尚未包含本地开发常用的**四大批量门禁（`quality:audit`、`integration:audit`、`release:check`）**；
   - **优化**：在 `ci.yml` 中补齐四大批量审计与包体漂移检查，确保任何潜在的包体膨胀、未声明 i18n 死 key 或 SQL 规范破坏在 PR 提交时即被拦截。
2. **Release 资产 SHA-256 校验和自动生成**：
   - 目前 Release 上传了 `package.zip`；
   - **优化**：在发布工作流中自动生成 `package.zip.sha256` 独立校验和文件，并一并上传至 Release 资产，方便开源社区与集市维护者验证完整性。
3. **SECURITY.md 版本矩阵对齐**：
   - 现存文档记录的当前版本系列为 `v0.47.x`，已落后于当前 `v0.48.x` 基线；
   - **优化**：同步推进安全支持矩阵至 `v0.48.x`，明确安全漏洞私密报告渠道。
4. **Issue 模板入口对齐**：
   - 在 `bug_report.yml` 的出问题入口（Surface）选项中，补齐“动作画板（Action Palette）”与“穿透检索（Penetration Search）”。
