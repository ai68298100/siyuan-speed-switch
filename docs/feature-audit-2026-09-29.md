# 小驴雷切功能、界面、交互与逻辑审计

日期：2026-09-29  
基线：v0.43.2  
性质：源码、测试、ADR 与路线图的只读交叉审计；本文件不把浏览器夹具当成真实思源桌面或 Android 验收证据。

## 1. 产品总链路

小驴雷切是思源内的统一切换与工作上下文平台，包含三个主面板和一个全局触发器：

```text
思源顶栏 / 侧栏 / 快捷键 / 悬浮球
          ↓
  openPlatformSurface()
          ↓
切换器 | 工作台 | 片段实验室
```

三面板共用平台页眉、SurfaceNav、关闭/返回焦点和回执语义，但信息架构不同：切换器负责找到并打开内容，工作台负责查看和编排组件，片段实验室负责安全编辑和预览原生片段。悬浮球只提供入口，不是第四个产品表面。

## 3. 当前交互与数据逻辑

### 3.1 状态与生命周期

用户动作通常经过“入口 → surface 会话 → 纯模型/宿主适配器 → DOM 回执”的链路。异步搜索、组件刷新、AI 和片段加载都有代际或取消逻辑；保存、导入、恢复、删除等写入动作需要确认并在原地回执。现有统一合同要求异步重绘保存滚动锚点、焦点对象、预览对象、展开状态和编辑状态。

### 3.2 保存真源与安全边界

思源原生片段列表、宿主设置和组件 provider 分别保持各自真源，插件侧只保存必要的索引、布局和会话状态。片段预览永不执行任意 JS；社区/Gist、回收站、配置包和 AI 结果均不能绕过原生启用开关或脏稿守卫。

### 3.3 端侧差异

桌面弹窗允许较多工具栏和全屏；侧栏优先保留搜索、收藏、最近、日记和排序；手机端采用紧凑工具栏、sheet 和触控热区。当前差异主要风险集中在重绘现场、排序浮层销毁、路径筛选代际和侧栏日记入口，而非领域模型本身。

## 6. 已确认但并入既有任务的缺口

- 片段实验室“返回”在保存/放弃后应回到来源面板；Esc、遮罩和右上 X 销毁脏稿 Dialog 时必须调用 `leave.cancel()`，并恢复焦点。这些并入 T-7028 的验收，不另立重复任务。
- 预览构造器仍接受 `runJS=true` 的可达分支；T-7022 必须移除或封死 `allow-scripts`，并做负向验证。UI 按钮 disabled 不能作为安全契约。
- 真实思源桌面、窄侧栏、Android、ActivityWatch 和 BGM 网络仍受 B-004～B-007 约束，不把本地 Chromium 结果写成宿主已验收。

## 7. 审计结论

产品主链路已经成立，当前最需要投入的是“重绘不丢现场、异步不覆盖新状态、面板生命周期可清理、原型/生产/发布包同一语义”。新增任务集中在这些可复现缺口；已交付能力和仅缺真实宿主证据的事项不重复立项。
