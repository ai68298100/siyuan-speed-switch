### T-6478 SQL 有界读收口（第一批）

状态：部分完成（必须修的四处已改，其余登记为后续）。
依据：F2——无外层 `LIMIT` 时内核按 `search.limit`（默认 64、下限 32）静默截断；插件此前从不读取 `truncated`/`limit`。
已完成：
- `src/util.js` 新增 `normalizeSqlResult(json)` → `{rows, truncated, limit}`，对畸形信封（null / data 非数组 / truncated 非严格 true）返回确定空态。
- `src/index.ts:4736`（`loadUpdatedMap`，「最近编辑」排序的更新时间映射）：此前是**分发器之外的裸 fetch**，无白名单、无 5s 超时、无错误归一，且**没有外层 LIMIT**——打开页签多于 64 时部分文档缺 updated，排序静默错乱。改为 `fetchKernelJson` + `LIMIT ${ids.length}`，并让失败不写缓存（避免把空映射固化 `UPDATED_CACHE_MS`）。
- 日历月视图（原 `LIMIT 64`）→ `LIMIT 200` + `b.id ASC` tiebreak，消除"整月缺日无提示"。
- 文档关系摘要 UNION（child + reference）→ `ORDER BY relation ASC, id DESC`，使引用行不再把子块整类挤出 64 行。理想解是两支各自 `LIMIT`，需真实宿主验证 SQL 形态后再改（登记 T-6485）。
- 设置里两个选择器（数据库 / 文档）→ `LIMIT 200` + `id ASC` tiebreak，并在 `truncated` 为真时 `logger.warn`；用户可见的"仅前 N 条，请继续输入关键词"提示需新增 i18n 键，登记 T-6482。
门禁：`tests/sql-and-dialog-lifecycle.test.cjs`——分发器之外的裸 fetch 按端点登记为债务（`lsNotebooks` / `getDoc` / `searchDocs` 三处各自带独立超时语义，迁移会改变时序，须真实宿主取证后再动，登记 T-6483）；每条 `stmt:` 字面量必须含外层 `LIMIT` 或命中带理由的聚合/单点豁免，豁免表出现僵尸条目即失败。
