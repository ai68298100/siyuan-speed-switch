## 1. R8 遗留首项：iframe sandbox 深水区（T-6861 取证）

- 检索确认（MDN/Chromium 公开资料层）：`sandbox` 无 `allow-same-origin` 即 opaque origin——不能访问父 DOM/cookie/localStorage，这是片段 CSS 预览现有方案的根基，**设计正确**。
- `allow-scripts + allow-same-origin` 组合会使沙箱失效（脚本可自摘 sandbox 属性）——现有预览绝不加 `allow-same-origin`，纪律有效。
- **对 T-6861（JS 受限预览）的关键结论**：`allow-scripts` 的 opaque-origin iframe 虽然隔离了 DOM/存储，但脚本死循环仍在**同一渲染进程**主线程上冻结宿主 WebView（site isolation 不保证 srcdoc/sandbox 分进程），"超时后移除 iframe"的方案在主线程卡死时根本无法执行——**不可安全终止**。唯一可终止路径仍是独立线程（Worker，无 DOM → 只能受限模拟）。ADR 0078 的"禁执行 + 若干推进只能受限模拟"判定**维持不变**，且补上了"为什么 iframe 路线不行"的机制级理由。
