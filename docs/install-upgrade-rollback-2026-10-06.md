# 安装、升级、停用、卸载与回退手册（2026-10-06）

本手册给用户和发布前演练使用。它把“代码或包内已核对的事实”和“必须在真实思源宿主中点一次才能成立的结论”分开，避免把浏览器夹具、纯函数迁移演练或本地工作树误写成正式发布证据。

## 版本和证据边界

| 项目 | 当前事实 | 状态 |
| --- | --- | --- |
| 正式包基线 | `v0.44.1`；`plugin.json`、`package.json` 版本一致；GitHub Release 有 `package.zip` | 已核对发布元数据；下载后的文件仍应自行校验 |
| 思源最低版本 | `minAppVersion: 3.8.0` | 已核对 manifest；旧宿主是否显示何种禁用提示需真实宿主确认 |
| 集市 | README 标为“待上架社区集市” | 未证明已经可以从集市安装；当前推荐 GitHub Release 手动安装 |
| 本地工作树 | 可能包含高于 `v0.44.1` 的未发布修改；未发布文件不能当作用户升级包 | 本手册不把工作树当发布资产 |
| 安装/升级/卸载 | 自动化检查覆盖包清单、版本契约、迁移模型和卸载前 flush；没有替代真实宿主点按 | 真实桌面、浏览器桌面端、Android 演练待补 |

状态标记：**代码已核对**表示源码、manifest 或现有契约能直接支持；**本地演练**表示在本仓库临时环境完成；**宿主待验**表示必须在真实思源工作空间中执行；**用户操作**表示不能由发布门禁代替。

## 安装前准备

1. 记录思源版本、系统、前端类型（桌面、浏览器桌面端或手机端）和插件版本。插件要求思源 `v3.8.0+`；手机端和浏览器模拟的覆盖边界见 [README](../README.md) 与 [BLOCKERS](../BLOCKERS.md)。
2. 关闭正在运行的思源窗口，至少备份整个工作空间，另外保留当前插件安装目录和要安装的 `package.zip`。不要只备份插件目录就把它当成完整工作区备份：`loadData` 数据由思源宿主管理，源码没有证明它一定和插件文件夹同目录。
3. 若使用外部服务，先记录端点是否为可信 HTTPS、本机服务是否启动、Token/API Key 是否可重新取得。不要把凭据、笔记正文、完整工作区路径或带 Token 的 URL 贴到 issue。
4. 安装前记录当前插件版本和关键用户状态：收藏、收藏分组、置顶、最近使用、快捷入口、工作台布局、片段草稿/回收站。这样升级后能区分“数据未加载”和“数据确实丢失”。

## 正式安装（GitHub Release）

### 推荐路径：手动安装

1. 从 [GitHub Releases](https://github.com/ai68298100/siyuan-speed-switch/releases) 下载对应版本的 `package.zip`。当前正式基线为 `v0.44.1`；不要从仓库源码压缩包或本地未提交工作树安装。
2. 在下载目录执行哈希记录，例如 PowerShell：

   ```powershell
   Get-FileHash .\package.zip -Algorithm SHA256
   ```

   发布页当前没有把 SHA-256 写入正文，因此把哈希作为本次安装记录保存，遇到异常时随版本和来源一并提供。

3. 解压后确认 `plugin.json` 位于压缩包根部，而不是多套一层目录；目标目录必须正好是：

   ```text
   <工作空间>/data/plugins/siyuan-speed-switch/
   ```

   目录名必须为 `siyuan-speed-switch`。包内至少应能看到宿主入口 `index.js`、`index.css`、`plugin.json`、`icon.png`、`preview.png` 与中英文 README；额外文档由 `plugin.json.publish.resources` 明确声明。

4. 将解压后的目录复制到 `data/plugins/`。首次安装可直接复制；覆盖安装必须先退出思源并保留上一版本备份，避免运行中的文件替换造成半包。
5. 启动思源，打开 **设置 → 插件**，确认“小驴雷切 / LvSpeed Switch”出现并启用。打开切换器、设置页和一个已配置的组件，确认首屏可用；有外部组件时，先检查“需要配置/本机服务/暂不可用”提示是否诚实，再决定是否重试。

### 集市安装

README 当前仍注明社区集市“待上架”。在集市条目和发布者身份、版本号、资源哈希都被实际核对前，不要向用户承诺集市安装可用。若集市日后上架，安装路径应由宿主处理，并仍按下方升级后检查清单核对版本和数据。

## 升级（覆盖安装）

1. 备份工作空间、当前插件目录和旧版 `package.zip`；记录旧版 `plugin.json.version`。
2. 退出思源后，把新版本目录完整复制到同一路径。不要把 `index.js`、`index.css` 或 `plugin.json` 从两个版本混拷。
3. 启动思源并从 **设置 → 插件** 确认新版本。`package.json`、`plugin.json`、README 发布行和 Release tag 应指向同一个正式版本；本地工作树的改动不应在这里出现。
4. 代码层面，插件启动时按 `PERSISTENT_KEYS` 读取数据，随后执行已有的清洗、迁移快照、快捷入口默认值迁移和 schema 版本戳处理（`src/index.ts:1481-1502`）。合法数据会保留；损坏项可能按有界规则清洗、截断或丢弃，不能把“清洗成功”误报成“所有历史字节原样保留”。
5. 逐项检查收藏、分组、置顶、MRU、快捷入口、工作台布局、片段草稿/回收站和外部服务设置。提供方插件暂时未加载时，快捷入口配置应保留并显示不可用原因；提供方恢复后再检查是否自动恢复。
6. 首次打开设置页后，确认保存回执、组件商店筛选和至少一个桌面/侧栏入口。外部组件的端点、凭据和缓存状态按 [组件就绪地图](component-readiness-map-2026-10-06.md) 解释，不要把“可添加”当成“服务在线”。

### 当前数据兼容事实

- `docs/storage-compatibility-matrix.md` 记录了从历史版本演进的持久化 key、上限和迁移语义；本地工作树目前有 18 个 key（包括 `sw_schema_version`、片段回收站和片段分组），而部分旧 README 仍写 15 个。升级验收以运行中版本和代码清单为准，发布前应同步修正文案。
- `sw_schema_version` 当前为 1。新版本会在加载期处理后落戳；发现更高版本戳时保留原值并记录“疑似降级”，不会用低版本静默覆盖它（`src/index.ts:1504-1523`）。
- `storage-migration.js` 的 `runStorageMigration` 是只读演练管道，不能被描述成宿主已经使用的事务恢复机制；真实升级仍需备份和宿主演练。

## 停用和重新启用

### 停用整个插件

在 **设置 → 插件** 关闭“小驴雷切”，等待宿主完成卸载，再确认切换器、侧栏、悬浮球和片段实验室入口不再操作插件代码。插件 `onunload` 会标记卸载、销毁片段对话框、移除公开钩子和 body 标记、解除事件监听、取消活动控制器，并 flush 去抖写入（`src/index.ts:1890-1935`、`:2134-2142`）。这些是代码事实；宿主是否按当前思源版本完整触发、关闭窗口时是否等待回调，仍需真实宿主验收。

重新启用后，检查面板是否能重新打开、设置是否仍在、外部提供方是否重新注册。不要在停用过程中手工删除配置文件；停用不是卸载，也不是清空用户数据。

### 只停用某个产品模块

设置 → 面板 → 模块管理可以分别停用工作台、片段实验室或悬浮球；切换器为平台保底入口。模块停用会隐藏对应导航、快捷动作、命令和悬浮球动作，但已经打开的面板可能要用户自行关闭。此路径只改变插件设置，不删除收藏、文档集、片段或外部凭据；真实宿主中的入口残留和重启恢复需按发布前清单复核。

## 卸载

1. 先执行“停用整个插件”，关闭所有插件面板，备份工作空间和插件目录。
2. 使用思源的插件管理卸载入口；若宿主版本没有可用入口，退出思源后再删除 `<工作空间>/data/plugins/siyuan-speed-switch/`，不要在进程运行时直接删除。
3. 重新启动思源并确认顶栏、侧栏、悬浮球、命令和 Agent 能力没有残留。`onunload` 的清理路径已在代码中实现，但“卸载后宿主数据是否自动删除”没有本仓证据，不能把删除插件目录等同于删除 `loadData` 数据。
4. 若要彻底清除设置，先导出或截图必要配置，再按当前思源版本的宿主数据管理方式清理对应插件数据；清理后不可逆。当前插件没有提供“卸载即删除全部数据”的独立承诺。
5. 重新安装同一版本，检查数据是否保留或已清除，并把宿主版本、操作步骤和结果记入演练日志。该项属于**宿主待验**，不能由本地单元测试替代。

第三方提供方（如剪藏、打卡、Calendar）应单独停用或卸载。提供方缺失时，本插件应保留配置并显示“需安装/当前不可用”；不要为了让卡片消失而手工删除实例配置。

## 回退到旧版本

回退是“恢复旧包 + 恢复兼容数据”的组合操作，不是简单把一个 `index.js` 换回去。

1. 停用插件并退出思源；保留当前失败版本目录、旧版本包、工作空间备份和安装哈希。
2. 优先从工作空间备份恢复到回退前状态，再安装与 `plugin.json`/`package.json` 版本一致的旧 `package.zip`。不要用仓库 `main`、`dev/thispc-1002` 或源码 ZIP 冒充旧正式包。
3. 如果新版本已经引入更高的存储 schema 或结构，先恢复对应备份中的插件数据，再启动旧包；只替换代码而保留新数据可能触发“疑似降级”、丢字段或旧版本无法识别。当前 schema 戳为 1，但没有覆盖所有未来版本的逐版本回退保证。
4. 启动后检查版本、设置、收藏、快捷入口、组件配置和面板布局。遇到启动失败、空白面板或数据异常，立即停用并回到备份，不要连续覆盖多个版本导致证据丢失。
5. 确认回退完成后，再决定是否重新升级。将失败版本、目标旧版本、思源版本、平台、是否恢复数据备份和日志摘要记录在 issue 中；日志中不得包含 Token、API Key、笔记正文或完整端点凭据。

## 凭据、联网和备份边界

- Gist 发布使用 GitHub Token；README 已说明 Token 存在插件设置中、界面打码，公开链接读取无需 Token，新建 Gist 为 unlisted。导出配置包不应假设包含 Gist Token；工作空间级备份可能包含宿主管理的插件数据，备份文件应按敏感资料保管。
- Miniflux Token、API Key、用户端点和 ActivityWatch 本机地址属于可选集成配置。安装/升级不应自动向未配置端点发请求；配置后只访问组件白名单允许的地址。组件来源、隐私和失败状态以 [组件就绪地图](component-readiness-map-2026-10-06.md) 与 [组件商店指南](component-store-guide.md) 为准。
- 本插件的安装包不包含用户笔记正文、工作区备份或凭据。网络可用性、第三方服务条款、端点证书和提供方插件行为不由发布包保证。

## 故障排查与反馈

| 症状 | 先检查 | 处理 |
| --- | --- | --- |
| 插件列表没有插件 | 目录是否多套一层、目录名是否正确、思源是否 `v3.8.0+` | 退出思源，重新解压到精确路径；确认 `plugin.json` 在根目录 |
| 升级后版本没变 | 是否覆盖了旧目录、是否仍在运行旧窗口、`plugin.json` 与 Release tag 是否一致 | 停止思源后完整替换目录并重启；不要只替换单个 bundle |
| 收藏/布局看似丢失 | 是否打开了不同工作空间、提供方是否暂时未加载、是否发生迁移清洗 | 先停止写入，核对工作空间和备份；不要反复保存覆盖旧数据 |
| 外部卡片不可用 | 配置、网络、服务进程和端点白名单 | 阅读卡片状态的配置/本机服务/暂不可用原因后再重试；不要把空数据当成插件数据丢失 |
| 卸载后入口残留 | 是否真正停用并重启、宿主是否完成 `onunload` | 记录宿主版本和残留入口，重启后再核对；不要手工删除工作区文件来“修复” |
| 回退后数据异常 | 是否恢复了与旧包匹配的工作空间/插件数据 | 停止插件，恢复备份并保留失败现场，再提交报告 |

提交问题时使用 [Bug 报告模板](../.github/ISSUE_TEMPLATE/bug_report.yml)，填写思源版本、插件版本、环境、期望/实际行为和复现步骤。控制台输出只保留必要错误；先删 Token、API Key、Authorization、带凭据 URL、笔记正文和私人工作区路径。

## 发布前人工演练清单

以下项目目前不能用本地门禁代替，完成后应把日期、宿主版本、平台、包 SHA-256 和结果写入发布记录：

- 干净工作空间安装 `v0.44.1`，确认桌面、侧栏、手机端入口和主题显示；
- 从上一正式版本覆盖升级，逐项核对持久化数据、外部配置和提供方恢复；
- 停用 → 重新启用 → 重启，确认无残留 DOM、命令、Agent 能力或重复事件；
- 卸载 → 重启 → 重新安装，记录宿主是否保留 `loadData` 数据以及清理方式；
- 制造新版本数据后回退旧包，验证 schema/设置/布局和备份恢复；
- 至少各演练一次无网络、端点超时、凭据失效、提供方未加载和取消操作；
- 用真实思源桌面和 Android 设备重复关键步骤。浏览器 smoke、`runStorageMigration` 和本地 package integrity 只算辅助证据。
