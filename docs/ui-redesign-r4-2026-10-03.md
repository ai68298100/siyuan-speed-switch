# 小驴雷切 UI 重构规范 R4：Context Canvas

日期：2026-10-03
状态：设计候选，待与现有 `T-6998`～`T-7015`、`T-7024` 及第三面板专项任务合并
配套原型：[`docs/design/platform-ui-redesign-r4-2026-10-03.html`](design/platform-ui-redesign-r4-2026-10-03.html)

本文是一次完整的 UI 原型重构方案。它先收敛信息架构、页面职责、状态、交互和视觉规则，再把可施工的工作拆为 `UIR-` 候选任务。`UIR-` 不是已经登记到当期开发账本的正式 `T-xxxx`，落地前必须和当前账本去重、合并并按协议分配正式任务号。

## 1. 重构依据与结论

本轮审视了以下材料：

- 现行 UI 单一事实源 `docs/design-system-v1-2026-09-27.md`；
- 三面板与设置统一体验计划 `docs/ui-ux-improvement-plan-2026-09-28.md`；
- R1/R2 逐屏原型、设计画廊、工作台原型、状态原型、商店原型和悬浮球原型；
- `ROADMAP.md` 中的产品定位、三端约束、工作台/组件商店和片段实验室路线；
- 现有生产状态模型：`ready / loading / stale / dirty / blocked / error`。

现有设计已经具备清晰的三表面骨架、宿主 token、状态徽标、预览窗格、移动端方向和安全边界。问题主要集中在信息层级和连续性：

1. 顶部平台头、上下文栏和工具条叠加后，首屏有效内容被压缩，页面之间的层级重复。
2. 第一面板的卡片视觉吸引力足够，但“找到什么、来自哪里、会执行什么”在结果行中区分得不够快；搜索、预览、返回和异步状态仍需要一套统一的主线。
3. 第二面板查看态和编辑态的操作密度差异不够大，布局编辑时长期显示多个按钮，卡片尺寸、落点和失败恢复的语义还不够直观。
4. 组件商店早期三列卡片适合展示，不适合比较来源、权限、刷新和安装风险；左目录 + 中间列表 + 右侧详情应该成为默认结构。
5. 第三面板能力强，但编辑器、预览、属性、AI 和安全状态同时出现时容易过载。AI、差异和 JS 限制需要成为上下文侧栏，而不是另起一套聊天页面。
6. 设置页有完整标签基础，但长 rail、搜索、当前值、即时保存、迁移和恢复回执没有形成统一的任务路径。
7. 移动端已有卡片和 sheet 方向，但不能只是把桌面三栏压成一列；需要用底部导航、底部 sheet、单手操作和安全区重排。

## 2. 产品定位与设计目标

小驴雷切的 UI 需要服务一个明确的产品承诺：

> 用户从思源的任何位置进入，都能快速找到目标、理解上下文、执行动作，并在完成或失败后回到原来的工作现场。

四个表面的任务固定为：

| 表面 | 用户问题 | 一级结果 |
| --- | --- | --- |
| 切换器 | 我该去哪里？ | 打开、定位或执行 |
| 工作台 | 我现在要看什么？ | 查看、刷新或编排 |
| 片段实验室 | 我如何安全定制？ | 草稿、预览、审查、保存 |
| 悬浮球 | 我从哪里进入？ | 呼出平台或执行高频动作 |

设置是治理入口，不是第五个业务表面；组件商店和片段商店是对应表面中的发现与扩展流程。

R4 的设计目标：

- **一个主任务**：每个页面在首屏只突出一个主要决定。
- **一个对象语言**：内容、动作、工作现场、组件、片段、能力和回执使用不同的类型标识。
- **一个返回链**：任何入口都记录来源、查询、选中项、焦点和滚动位置。
- **一个状态协议**：异步、缓存、脏稿、受限和错误在所有表面使用同一套词和动作。
- **一个视觉来源**：继续继承思源 `--b3-*`，由 `--sw-platform-*` 做语义别名，不另造独立色板。
- **一个 AI 边界**：AI 只在当前上下文中解释、建议、生成草稿和审查差异，不能默认写入、启用或执行。

## 3. 信息架构与路由

```text
小驴雷切 PlatformShell
├── 切换器 /switcher
│   ├── 空查询、已开页签、收藏、最近、日记
│   ├── 搜索结果、内容预览、动作结果、工作现场
│   └── 过滤、排序、保存搜索、返回来源
├── 工作台 /workbench
│   ├── 查看、刷新、健康详情
│   ├── 编辑布局、尺寸、撤销/重做
│   └── 组件商店 /component-store
├── 片段实验室 /studio
│   ├── 片段目录、编辑、CSS 预览
│   ├── 差异、冲突、AI 审查、宿主回读
│   └── 片段商店 /snippet-store
├── 设置 /settings
│   ├── 外观、面板、行为、快捷键、收藏
│   ├── 工作现场、片段、移动端
│   └── 数据与存储、诊断
└── 悬浮球 /floating-trigger
    ├── 一级高频动作
    └── 当前上下文动作与更多
```

### 3.1 统一路由对象

进入任意表面时保存以下 `returnTo` 信息：

```text
surface       当前表面
source        入口：悬浮球 / 设置 / 结果行 / 组件卡 / 片段对象
objectId      当前对象 ID（可缺省）
query         查询词与搜索层级
filters       类型、范围、排序和分组
focus         来源元素的稳定 key
scroll        列表和预览滚动位置
dirty         是否存在未保存草稿或布局事务
```

关闭、返回或执行完成后按以下顺序恢复：来源元素仍存在 → 同表面同查询 → 表面首个主控件 → 宿主当前编辑器。来源对象被删除、关闭或失效时，要显示一个可解释的回落回执。

### 3.2 对象分类

结果行和卡片不能再用“卡片”“入口”“模块”覆盖所有对象。必须显示类型图标和类型文字：

| 类型 | 例子 | 主动作 | 次要信息 |
| --- | --- | --- | --- |
| 内容 | 文档、块、资源、PDF | 打开/定位 | 路径、命中片段、更新时间 |
| 动作 | 今日笔记、同步、捕获 | 执行 | 是否写入、是否可取消 |
| 工作现场 | 写作、研究、临时现场 | 预览/恢复 | 页签数、布局、缺失项 |
| 组件 | 上下文、日历、天气 | 添加/配置 | 来源、权限、刷新、缓存 |
| 片段 | CSS、JS 草稿 | 查看/加入草稿 | 语言、启用状态、风险 |
| 能力 | 网络、宿主 API、移动端 | 查看原因 | 可用端、限制、替代入口 |
| 回执 | 成功、失败、待确认 | 重试/回退 | 时间、对象、诊断 |

## 4. 平台外壳规范

### 4.1 桌面结构

```text
┌──────────────────────────────────────────────────────────┐
│ 品牌  [切换器] [工作台] [片段实验室]   状态  返回  设置  × │ 52px
├──────────────────────────────────────────────────────────┤
│ 工作现场 › 表面 › 对象/模式          快捷键提示            │ 上下文栏
├──────────────────────────────────────────────────────────┤
│                                                          │
│                        Surface Body                     │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ 回执 / 计数 / 当前主动作                                  │ 可选
└──────────────────────────────────────────────────────────┘
```

外壳只负责品牌、表面导航、来源返回、设置、关闭、能力状态和上下文。表面专属工具不得继续堆进平台头。

### 4.2 侧栏与移动端

| 维度 | 桌面弹窗 | 窄侧栏 | 移动端 |
| --- | --- | --- | --- |
| 头部 | 52px，品牌和完整导航 | 40px，隐藏品牌和描述 | 44px，导航横向滚动 |
| 预览 | 右侧 280～480px | 宽度不足时转抽屉 | 直接打开或底部 sheet |
| 工具条 | 主动作 + 次动作 | 只保留搜索、收藏、最近、日记 | 主动作置底，更多进 sheet |
| 命中区 | 28px 控件 | 28px 控件 | 所有可点元素 ≥44px |
| 片段实验室 | 完整 | 可隐藏或降级 | 只显示状态和入口 |
| 悬浮球 | 挂载 | 不挂载 | 挂载并避开 safe-area |

### 4.3 关闭与返回

- `Escape` 先关闭当前菜单或 sheet，再退出局部模式，再关闭平台。
- 有脏稿或未应用布局时，统一出现“保存 / 放弃 / 取消”三选项。
- 点击表面导航不能销毁另一个表面的脏稿；应保留草稿和编辑事务。
- 关闭平台时优先恢复触发源焦点；无法恢复时回到宿主编辑器。
- 移动端系统返回等价于 `Escape`，底部 sheet 从最内层开始关闭。

## 5. 第一面板：切换器与搜索

### 5.1 首屏

首屏顺序固定为：搜索框 → 类型过滤 → 已打开内容 → 动作/工作现场 → 收藏/最近/日记。空查询不发起全库搜索，也不展示大规模统计。

搜索框是唯一首焦点，支持：

- 已开页签本地过滤；
- 已打开文档内容；
- 当前笔记本/当前路径；
- 受限全库搜索；
- 动作和工作现场；
- `Ctrl/Cmd+K`、`/`、清空、输入法组合态。

### 5.2 结果行

每个结果至少包含：类型、标题、副标题、来源、当前状态、主动作、更多动作和快捷键。不能只显示一个标题和一个颜色点。

搜索阶段提示要区分：

- `未开始`：空查询，显示最近和固定入口；
- `本地结果`：已开页签和已打开文档；
- `正在搜索`：全库请求进行中，可取消；
- `无结果`：显示范围调整建议；
- `失败保留旧结果`：保留上一轮结果并就地显示重试。

### 5.3 预览

桌面右侧预览固定显示标题、路径、更新时间、对象类型、摘要/命中片段和主动作。预览切换不清空查询，返回时保留滚动与焦点。预览失败时只替换预览区，结果列表继续可用。

预览必须回答：对象是什么、来自哪里、是否已打开、会在哪里打开、是否写入、是否联网、是否可回退。

### 5.4 页签、收藏、最近、日记

- 页签卡的数字快捷键只属于已开页签，不与收藏/最近行复用同一命名空间。
- 页签超过 100 个时按当前、最近、其他折叠，并显示数量。
- 收藏组支持空态、拖拽插入线、重命名、删除、恢复默认和撤销。
- 最近打开与最近关闭明确分开；已关闭条目显示可恢复、已缺失或不可恢复。
- 日记入口始终在一级入口中，区分今日已有、创建中、创建失败和不存在。

## 6. 第二面板：工作台

### 6.1 查看态

查看态只保留组件内容、健康状态、刷新和配置入口。顶部显示工作现场、组件数量、最后刷新时间和健康汇总。每张组件卡显示：来源、数据时间、缓存年龄、尺寸档位和必要的主动作。

单组件刷新必须原地显示 `loading`，保留旧内容；成功、缓存回退和失败都在同一张卡上结束。刷新不得抢焦点、跳滚动或重置布局。

### 6.2 编辑态

编辑态采用“选中后显示操作”：未选中卡片只显示拖动把手、尺寸角标和状态；选中后才显示移动、配置、删除和更多。支持鼠标拖动、触控长按、键盘方向键、落点预览、撤销/重做和取消。

编辑工作台时必须保留：

- 当前组件 ID；
- 滚动锚点；
- 选中卡焦点；
- 展开/折叠状态；
- 未提交的布局事务。

### 6.3 空态、失败与健康

空工作台的主动作是“打开组件商店”，次动作是恢复默认或稍后再说。失败卡显示原因、缓存年龄、重试、复制诊断和替代入口。全局健康条只做汇总，详细原因留在组件级。

## 7. 组件商店

组件商店固定使用三栏结构：左侧目录，中间可比较列表，右侧详情。中间列表支持卡片和紧凑行两种密度，详情固定展示：

- 名称、来源、版本、许可证；
- 输入上下文和数据边界；
- 网络/宿主权限；
- 刷新、缓存和离线行为；
- 尺寸档位与移动端表现；
- 已安装、已添加、需配置、缓存、失效、版本不兼容状态；
- 安装、配置、移除和保留占位的影响。

安装动作先加入队列，底部回执显示进度；安装完成后返回工作台并选中新增组件。安装失败保留详情和重试，不关闭商店。

## 8. 第三面板：片段实验室

### 8.1 三栏工作区

左栏是片段目录和筛选，中栏是唯一编辑源，右栏依次是安全预览、属性、AI 建议和差异。窄容器时右栏变为可切换 sheet，移动端只展示片段状态、预览和桌面入口。

编辑器顶部始终显示片段名、语言、草稿/已保存、启用/停用和冲突状态。底部显示行数、语法诊断、保存快捷键和宿主回读结果。

### 8.2 CSS、JS 和安全边界

- CSS 预览使用安全近似 fixture，不读取用户正文、不加载远程资源。
- JS 默认 `blocked`，只能查看静态说明、诊断、导出和差异；不在浏览器原型中执行。
- 保存必须经历：草稿 → 静态诊断 → 预览 → 差异 → 用户确认 → 宿主写入 → 回读。
- 写入超时进入“待确认”，不能直接显示失败或成功。
- 冲突显示双方差异和回退入口，不能静默覆盖。

### 8.3 AI 侧栏

AI 只读取用户明确选择的片段、选区、诊断或预览结果。输出分为说明、建议、草稿、差异和检查结论；生成结果默认停留在草稿区，用户逐项接受后才可进入宿主写入流程。

## 9. 片段商店

片段商店的核心决定不是“买不买”，而是“是否值得加入草稿”。每个片段卡显示语言、影响范围、远程资源、许可证、兼容端、大小、来源和风险。主动作是“加入我的草稿”，加入后自动跳转片段实验室的差异审查，不自动启用。

脚本片段必须在卡片和详情中同时显示 `JS 受限`，并说明受限原因和可行的宿主内替代路径。片段商店不能伪装成可执行代码市场。

## 10. 设置页

保留十个标签：

1. 外观；
2. 面板；
3. 行为；
4. 快捷键；
5. 收藏；
6. 工作现场；
7. 片段；
8. 移动端；
9. 数据与存储；
10. 诊断。

“组件面板”作为“面板”页中的分组，不再增加不可达的第十一标签。设置页搜索打开即聚焦，结果显示标签、分组、当前值、默认值、是否已修改和跳转目标。

每个设置行采用“名称 + 解释 + 当前值/控件 + 回执”结构。即时保存统一显示 `pending → saved → failed → retry`；外部入口修改设置后，当前页局部更新或带现场恢复地重建。

### 10.1 重点分组

- **外观**：主题、密度、动效、缩放、面板圆角和缩略图。
- **面板**：三面板尺寸模式、固定宽高、预览开关和默认表面。
- **行为**：搜索层级、打开策略、返回、异步刷新、悬浮球联动。
- **快捷键**：动作注册、宿主冲突检测、恢复默认。
- **工作现场**：文档集、布局快照、应用前差异和失败恢复。
- **片段**：默认安全策略、预览范围、AI 审查和回读。
- **移动端**：底部导航、safe-area、触控、缩略图高度和横屏。
- **数据与存储**：schema、迁移、缓存、导出/导入、清理影响。
- **诊断**：脱敏状态、能力探针、最近错误和复制诊断。

## 11. 悬浮球与共用浮层

悬浮球不是第四个表面，只做入口和高频动作。首层最多四项：切换内容、快速捕获、打开工作台、恢复工作现场；低频动作进入“更多”。点击、长按、拖动三种手势在设置中可发现并可关闭，位置记忆必须考虑安全区和宿主侧滑。

所有确认对话框统一使用：标题、影响范围、主动作、次动作、取消、Esc/返回、焦点回归和失败回执。导入、恢复、覆盖、删除等副作用动作必须在执行前展示影响摘要。

## 12. 组件、状态与视觉规范

### 12.1 Token

继续使用现有 `--sw-platform-*` 语义别名和 `--b3-*` 来源：

| 类别 | R4 规则 |
| --- | --- |
| 颜色 | accent、surface、muted、line、text、success、warning、error；不新增固定色板 |
| 间距 | 4 / 8 / 12 / 16 / 24px |
| 圆角 | 控件 8、卡片 12、外壳/sheet 16、胶囊 999 |
| 动效 | 120 / 160 / 200 / 260ms；`prefers-reduced-motion` 即时化 |
| 控件 | 搜索 38（移动 40）、标准控件 28、分段 26、触控 ≥44 |
| 字体 | 标题 13/700、正文 12～12.5、meta 11、kbd 10.5 mono |
| 层级 | line → surface → elevated；常态卡片不使用重阴影 |

### 12.2 六态

| 状态 | 文字 | 允许动作 |
| --- | --- | --- |
| ready | 已就绪/已更新 | 打开、编辑、查看 |
| loading | 加载中 | 取消、等待 |
| stale | 缓存于某时刻 | 刷新、查看缓存 |
| dirty | 未保存更改 | 保存、另存、放弃 |
| blocked | 受能力/端侧/安全限制 | 查看原因、换入口 |
| error | 失败原因 | 重试、回退、复制诊断 |

状态必须至少同时使用文字与颜色/图标两种表达，不能仅靠颜色。

### 12.3 统一组件清单

平台原语：`SurfaceNav`、`ContextBar`、`StatusBadge`、`ReceiptBar`、`SearchBox`、`Chip`、`Kbd`、`ActionButton`、`PreviewRail`、`BottomSheet`、`ConfirmDialog`、`FocusReturnBoundary`。

领域原语：`ResultRow`、`TabCard`、`WidgetCard`、`StoreCard`、`StoreDetail`、`SnippetRow`、`CodeEditor`、`DiffPanel`、`AIReviewSidecar`、`SettingsRow`、`FloatingActionPanel`。

每个原语必须提供 ready/loading/stale/dirty/blocked/error 中适用的状态，并有键盘、触控和读屏语义。

## 13. 交互合同

### 13.1 焦点与重绘

异步刷新统一执行“捕获 → 更新 → 恢复”：保存焦点 key、滚动锚点、选中对象、展开组、预览对象和脏稿；更新后恢复，目标消失时按表面首控件回落。`aria-live` 只播报状态和操作结果，重绘不重复朗读整页标题。

### 13.2 搜索与异步

请求携带代际和取消信号；旧查询的迟到结果不得覆盖新查询。全库搜索显示阶段进度和取消；取消保留上一轮结果。网络/宿主失败保留可用的本地结果。

### 13.3 破坏性动作

删除、覆盖、导入、恢复、启用片段和移除组件显示影响范围；确认后只弹一次。能撤销的动作提供撤销；不可撤销的动作说明备份或导出路径。

### 13.4 键盘与触控

桌面：Tab、Shift+Tab、Enter、Space、Escape、方向键、Home/End、Ctrl/Cmd+K、Ctrl/Cmd+S。
移动：点击、长按、拖动和系统返回都有等价入口；不依赖 hover、右键或精确拖拽。

## 14. AI 融入规则

AI 应被理解为“上下文助手”，不是单独的聊天首页。

允许：

- 解释搜索结果和组件失败；
- 推荐搜索范围或相关内容；
- 总结用户明确选择的预览内容；
- 生成 CSS/JS 草稿；
- 解释作用域、主题变量、冲突和差异；
- 为工作现场生成名称和恢复摘要。

默认禁止：

- 自动读取整库；
- 默认上传全文、附件或外部组件数据；
- 自动修改文档；
- 自动启用 AI 片段；
- 执行任意 JS；
- 无差异预览地改变工作台布局；
- 以智能排序覆盖用户固定顺序。

每次调用前显示上下文选择器：当前文档、选区、块、搜索结果、片段、手动添加内容和外部数据开关。结果按“建议 → 草稿 → 差异 → 用户接受 → 宿主写入 → 回读 → 回滚”推进。

## 15. 无障碍、主题、性能与宿主兼容

- 所有自定义控件有明确名称、角色、选中/展开/忙碌/禁用/无效状态。
- 主题、颜色和高对比下状态仍通过文字和图标可理解。
- 200% 缩放、长中文文案和最窄侧栏不得产生不可达主操作。
- `prefers-reduced-motion` 关闭持续动画，仍保留状态变化。
- 首屏打开不依赖远程请求；已开页签过滤必须本地优先。
- 组件单独失败不得阻塞切换器；片段预览不得读取用户正文或加载网络。
- 宿主 API、网络、provider、移动端和侧栏能力缺失时显示可解释原因和替代入口。
- 真实桌面、真实移动端和真实内核证据单独标记，浏览器原型只作为结构与视觉证据。
