# 路径筛选侧栏体验评估

> 评估日期：2026-09-13
>
> 结论：暂不把路径筛选常驻到侧栏。先保留桌面筛选弹层的单笔记本、路径 chip 和安全降级设计，等宿主能力探测在真实桌面版本中取得稳定证据后再做最小入口实验。

## 当前判断

- 侧栏宽度通常小于桌面弹层，路径名称容易被截断；常驻树或多级展开会挤压页签卡片和最近记录，收益不足以抵消扫描成本。
- 侧栏更适合展示一个已选路径 chip 与清除按钮，而不是主动枚举目录。枚举请求应由用户打开筛选入口后触发，并沿用最多 100 项和可取消请求边界。
- 笔记本切换必须清理旧路径状态，避免路径 ID 在新笔记本下产生空结果或误导性“无文档”。当前生产入口已覆盖该状态一致性契约。
- `/api/filetree/listDocsByPath` 虽在上游源码中存在，但未列入公开 API 清单；能力探测失败时必须保留普通笔记本/全库搜索，不得把失败解释成空目录。

## 建议的最小实验

仅在能力探测成功且有真实桌面宿主证据时启用：

1. 侧栏顶部显示单行路径 chip，文本最多两行并提供明确的移除按钮。
2. 点击 chip 打开一次性目录选择弹层；不在侧栏常驻目录树，也不在面板首开时请求目录。
3. 选择路径后只更新筛选状态，目录请求可取消；切换笔记本立即清理路径并回到笔记本范围。
4. 能力缺失、超时或响应错配时隐藏路径入口，保留现有筛选项并显示稳定的非阻塞提示。

## 进入条件与退出条件

进入条件：至少一个受支持桌面版本的真实宿主确认端点可用、响应字段稳定，且生产 `package.zip` 仍有不少于 2 KiB 余量。

退出条件：侧栏窄宽度下 chip、清除、键盘焦点和失败降级均有宿主证据；若任一条件不满足，撤销入口并继续使用纯模型，不扩大 CSS 或请求代码。

## 后续待办

- 在真实桌面大版本验收时记录端点能力探测结果和侧栏最窄可用宽度。
- 若进入条件满足，再拆分 T-103a（桌面弹层最小入口）与 T-105a（侧栏 chip 体验），分别做包体预算和回归测试。
- 手机端路径树继续后置，不以 Chromium 窄屏模拟替代 Android 宿主验收。
