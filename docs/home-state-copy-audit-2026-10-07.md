# T-7138 对象状态与行动文案审计（2026-10-07）

## 复现与判断

- 组件已有旧快照、强制刷新失败时，卡片仍有可读内容，但原先只呈现“缓存”，工作台汇总仍把它归入普通失败；这会让用户误以为内容不可用。
- 适配器返回 `timeout`、`unsupported`、`unregistered` 或 `backoff` 时，原先的状态渲染路径可能把内部原因 token 直接交给界面；未知原因也没有稳定的兜底文案。

## 本轮处理

- 控制器把旧快照回退标为 `stale`，同时保留刷新失败结果用于重试统计。
- 工作台卡片、健康汇总和刷新回执分别呈现“旧内容仍可见、刷新失败”，并保留单项/全部重试入口。
- 状态原因使用双语白名单映射；未知原因统一回退到通用失败文案，不展示原始异常文本。

## 边界与后续

本轮没有虚构外部组件的安装、配置或授权能力。外部 provider 的“未安装/未配置/授权失败”需要继续沿用就绪条件和来源表，补上可执行动作后再单独验收；这属于后续状态文案批次，不改变现有数据请求与重试逻辑。
