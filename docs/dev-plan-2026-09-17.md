## 0. 结论先行

仓库的工程成熟度远高于同量级思源插件：**ADR + 契约测试 + 负向验证 + 发布门禁的质量体系已经成型**，不是"需要补测试"的状态。真实缺口在另外三个方向：

1. **样式层完全未重构**（`index.scss` 6517 行，六轮 TS 重构均未触及）；
2. **`index.ts` 仍有 27 个 ≥60 行成员**（合计 3860 行），其中 `openSecondPanel` 602 行是最大单体；
3. **发布链路卡在人工决策**（40 个本地提交未推送、真机验收未完成）。

因此"多加功能"不是当前最优解，**"把已有资产的最后一公里走完"才是**。

## 2. 架构评价

### 2.1 已经做对的部分（建议保持）

- **model / view / controller / adapters 四层分离**在 Home 子系统完整落地，是全仓最健康的部分。
- **契约优先（contract-first）**：每个能力先落 `agent-*.js` 契约层，再决定是否接线生产；这使得"未验证能力"不会污染生产路径。
- **发布门禁体系**：`tests/host/` 下 reproducible-build / package-integrity / final-package-audit / release-quality / rollback-preflight 构成真实拦截力。
- **胖 BLOCKERS.md 文化**：把"环境不可用"明确标注为非工程阻塞，避免假装验证。

### 2.2 结构性问题

**问题 A：样式层是唯一未被治理的巨型文件。**
`index.scss` 6517 行、单文件承载三端全部视觉。仓库已有 `scripts/css-window-census.cjs` 与 `tests/css-block-scan.cjs`（块级断言 `parseRules/findRules/declaresIn`，支持 `topLevel` 与复合 at-rule）——工具链现成，缺的是立项。

**问题 B：`index.ts` 剩余成员集中在"第二面板"与"移动端"两块。**
`openSecondPanel`(602) + `bindMobileSwitcherToolbarActions`(176) + `openMobileSwitcherDialog`(161) + `renderMobileList`(109) + `openMobileGroupActions`(79) ≈ **1127 行**，语义同属"端侧界面装配"。这是下一批最自然的外迁靶点，风险剖面与已交付的 R5b 高度相似。

**问题 C：治理文档体积失控。**
`TODO.md` 454957 B、`DECISIONS.md` 237575 B、`PROGRESS.md` 228393 B。三者互相覆盖且必然过期；事实源应为 `ROADMAP.md` + `docs/adr/`。（已于 T-6294 归档至 `docs/archive/`，见 ADR 0051）

**问题 D：路径筛选 UI 悬置。**
`path-filter-model.js` 已就绪，API 层证据已在 `docs/path-filter-host-evidence.md` 采齐，剩"最窄可用侧栏宽度"这一 UI 度量未取证。

## 5. 建议的实现优先级

### P0 — 先把不需要用户决策的事做完

**P0-1：修复 `perf-complexity-gate` 自检的机器敏感性** — ✅ 已交付（2026-09-17 上午）

> **执行记录（T-6290）**
> 现象：本机确定性失败（单独复跑 3/3 一致），失败点 `tests/perf-complexity-gate.test.cjs:176` 的
> `assert.ok(light > 0.5, 'light workload must stay well above timer precision')`。
> 根因：该断言是**绝对毫秒下限**，与文件自身"按机器校准"的设计相悖。实测 Node v22.22.2
> `light≈0.152ms / heavy≈0.305ms / ratio≈2.01`——比值语义完好，只是绝对值落在 0.5ms 之下。
>
> 修法（沿用本文件既有口径，非放宽阈值）：新增 `sumTo(n)` 与 `calibrateSelfCheckIterations(floorMs)`，
> 以 2 的幂次放大迭代数直至单次耗时越过 `SELF_CHECK_FLOOR_MS = 2`，再以 `2×` 迭代数作为 heavy 侧。
> 本机自适应标定到 **6,400,000 次**，实测 `light 7.28ms / heavy 14.60ms / ratio 2.00`，远离计时精度。
>
> **负向验证暴露的真实缺陷（比原计划更进一步）**：注入「heavy 退化为与 light 同规模」后，
> 原断言 `heavy > light` **仍然通过**——计时噪声使等规模 workload 的 min-of-N 结果偶然满足大于关系，
> 该断言**没有判别力**。已改为比值断言 `heavy / light >= SELF_CHECK_MIN_RATIO(1.5)`（2× 规模应≈2.0 倍）。
>
> 负向验证三件套（脚本 `.tmp/negverify_perf_gate.py`，逐项字节级还原并核对 md5）：
> 注入 A（等规模）→ 精确 1 项 FAIL；注入 B（地板设 1e9 不可达）→ 精确 1 项 FAIL；
> 两种注入下兄弟 5 项均不受波及；还原后 md5 对齐、6/6 全绿。
>
> 验证：单文件连跑 3/3 全绿；**全量 5872/5872（原 5871/5872）**。仅改测试文件，未动产品代码。
