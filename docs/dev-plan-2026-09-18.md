### T-6301 ✅ 命令注册守卫（issue #1）

**根因**（对照思源 master 源码 `app/src/boot/globalEvent/globalShortcut.ts`）：内核
`sendGlobalShortcut` 固定读取 `window.siyuan.languages["_trayMenu"]`；`languages` 未就绪的
宿主时序下该行抛 `TypeError: Cannot read properties of undefined (reading '_trayMenu')`，
与 issue #1 堆栈完全一致。触发链：`addCommand` 仅在命令带 `globalCallback` 时调用
`sendGlobalShortcut`——全插件只有 secondPanel 命令带它。**损害面**：异常冒泡中断 onload，
`registerAgentCapabilities()` 与全部受控 Agent 动作注册被跳过（用户"插件很好用"是因为
主切换路径在 onload 前半段已就绪）。

**修复**：① `util.js` 新增 `isGlobalShortcutHostReady`（languages 缺失则不带
globalCallback，从源头绕开内核脆弱路径）与 `safeRegisterPluginCommand`（try/catch 隔离；
已入队后抛错不重试防重复注册，仅降级丢全局热键；未入队且带 globalCallback 时去掉重试
保住应用内热键）；② index.ts 两处 `addCommand` 全部改走安全助手。tsc 0 错误。

**门禁**：`tests/command-registration-guard.test.cjs` 11 项（就绪判定、四种注册语义、

## 9. T-6331：标题快路径与已打开内容搜索并行

状态：✅ 已完成（2026-09-18）

现状缺口：标题搜索命中时，`runDocSearchFetch` 直接返回，跳过已打开文档内容探测。
因此页签标题不含关键词、但正文命中的文档不会被即时恢复，违背分层搜索中“已打开内容
优先于全库”的交互语义。

实现：

- 标题快路径启动时同步启动有界的已打开文档内容探测（最多 6 个文档、最多 3 个并发）。
- 探测完成后，在请求版本、查询词和 DOM 仍有效时增量刷新页签卡片；标题结果无需等待探测。
- 标题无结果或端点失败时复用同一个 Promise，继续按已打开内容 → 全库回退顺序执行，避免重复请求。
- `AbortError` 保持静默取消，非取消异常仅记录诊断，不阻塞标题结果或页签切换。

验证：`pnpm exec tsc --noEmit` 通过；`tests/search-orchestration.test.cjs` 4/4 通过，
并将标题命中用例改为同时验证已打开内容探测。该改动不新增 CSS 预算约束；后续以性能、
结果时序和交互可见性为主要验收标准。
