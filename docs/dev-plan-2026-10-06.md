# 小驴雷切精品化开发计划

日期：2026-10-06。规划任务：T-7124。依据：[产品评审](product-review-2026-10-06.md)、[ADR 0147](adr/0147-product-quality-roadmap.md)。接续 [2026-09-27 账本](dev-plan-2026-09-27.md)。

**当前状态只维护在 [current-status-index.json](current-status-index.json)。本文件定义范围、顺序和验收，不另维护状态列。** 当前环境验收沿用 T-7115；可本地续跑任务从 T-7125 开始。本轮交付规划，不把后续计划写成已经开工。

## 1. 产品目标和任务准入

定位保持“统一切换与工作上下文平台”。高频本地查找和切换优先，工作台帮助理解当前信息，实验室安全调整片段，浮球快速到达。目标是让普通用户容易上手、让熟练用户快捷可靠、让失败有恢复路径、让发布和介绍可信。

本期新增 **44 个工作单元 T-7125～T-7168**，并复用 **6 个已有单元 T-7115～T-7120**。44 项涵盖确认修复、文档/素材交付和条件审计，绝不代表要新增 44 项功能。各任务编号、当前状态、优先级及责任类型以索引为准。

- **修复**：已有具体源码缺口；先锁定复现，再改最小范围。文中 P0 指严重阻碍主要路径或可信验证的缺口，不代表全部都是数据丢失漏洞。
- **交付**：缺少明确产品材料、测量或用户能力；交付可评审结果，不自动附带外部发布。
- **条件**：先复用已有实现做用户路径/差距审计；只有可复现缺口才修改生产。无缺口时保存证据并完成，不重做同名功能。
- **环境**：旧任务补真实设备、账号、服务或人工证据；前置缺失就保留单项阻塞，推进其他本地任务。

首屏不增加强制教程、宣传卡、统计模块。新布局/默认值影响已接受 ADR 时先记新的取舍；不因本计划直接切回非全屏或关闭既有模块。完整编辑器、片段外 AI 与 JS runner 保持原后置/关闭边界。

每张任务表中的源码入口是定位线索，不是修改清单。实施前重新检索，避免期间已有修复；评审基线行号见产品评审，续跑使用函数/对象名定位。

这不是四个必须串行等待的大版本。品牌 brief、用户手册、支持表和可用性脚本可与 M0 并行；最终截图须等待相关 UI 稳定。外部服务验证按服务分别执行，不等待其他提供方。每次只让少量依赖闭合的生产任务在制，3～5 个相关任务收口一次本地提交，不 push。

**首个施工批：T-7125 → T-7126 → T-7127 → T-7128 → T-7129。** 同期可独立处理 T-7130/T-7131 工程声明和 T-7132 文档事实；有未提交用户改动时保留它们，不混入任务提交。先检查“当前缺口是否仍存在”，之后实现和验证。

本地默认顺序记录在索引 `localExecutionOrder`；T-7115 的环境验收仍未完成，这不会阻塞下一本地工作。后续实现开始时才更新 `currentTask`，规划阶段不虚构 in_progress。

`dependsOn` 是必须先完成的工程前置；`inputsFrom` 是参考脚本/反馈来源，不是硬前置。T-7168 可先准备任务脚本，真人反馈继续待证；本地条件审计可以依据已有真实反馈或独立复现推进，不因没有受访者冻结 UI、截图或 README。默认顺序遇到不可做项就选其他依赖闭合项，不把准备稿冒充真人验证。
