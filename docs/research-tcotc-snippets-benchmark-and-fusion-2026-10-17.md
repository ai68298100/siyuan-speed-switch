# TCOTC/snippets 深度调研与小驴雷切第三面板融合方案报告

- **调研对象**：[https://github.com/TCOTC/snippets](https://github.com/TCOTC/snippets)
- **最新版本**：v2.0.4（2026-10-16 发布）
- **发布包大小**：约 478 KiB（490,053 bytes）
- **调研目标**：解构其架构与交互亮点，分析其对小驴雷切第三面板（代码实验室 Snippet Studio）及对应片段商店（Snippet Store）的吸收融合价值。

## 一、 TCOTC/snippets 核心架构与功能解构

`TCOTC/snippets` 是思源笔记生态中专注于代码片段管理的单一领域插件，其核心功能链覆盖了从编辑、组织、热重载到外部同构分发的全流程：

### 1. 存储层与分组映射（Sidecar Architecture）
- **内核限制对抗**：思源内核 `conf.json` 原生仅提供每条片段的 5 个基础字段（`id`, `name`, `content`, `type: "css" | "js"`, `enabled`, `disabledInPublish`），不包含任何分组、标签或自定义排序字段。
- **插件外挂映射文件**：TCOTC 采用在插件 storage 目录持久化 `plugin-groups.json` 的外挂映射策略（Sidecar Pattern）：
  - 组结构：`{ id, name, type, snippetIds: string[] }`；
  - **顺序权威**：组内片段的排序权威完全交由 `snippetIds` 数组维护，拖拽排序直接改动该数组；
  - **防御性静默对账**：当外部或其他插件删改片段 ID 时，在读取映射时静默剔除无效 ID，未归属片段自动落入虚拟的 `default`（未分组）占位组。
- **跨窗口实时同步**：利用思源 WebSocket 广播业务消息。广播消息**严格禁传片段原文**，仅下发 `snippet_save` 事件携带 ID，接收窗口自行通过 API 拉取权威数据，避免多窗口并发数据撕裂。

### 2. 生效注入与热更新机制
- **CSS 片段（0ms 热重载）**：
  在 `document.head` 动态挂载 `<style id="snippetCSS{id}">`。拨动开关或在编辑器中敲击代码时，直接实时替换 `styleElement.textContent`；关闭或禁用时直接 `remove()`，达成无缝热重载与实时微预览。
- **JS 片段（安全提示与重载握手）**：
  在 `document.head` 挂载 `<script id="snippetJS{id}">`。由于浏览器原生环境无法直接反注册或清理已执行的 JavaScript 内存状态与全局事件监听器，TCOTC 在用户修改、禁用或删除旧 JS 片段时，通过顶栏触发 **呼吸动画与顶部提示“旧 JS 无法即时卸载，需重载界面”**，引导用户适时执行 `Reload UI`。

### 3. GitHub Gist 云端生态与导入规划（Import Plan）
- **文件命名身份编码**：
  在 Gist 中将文件命名为 `<清洗后的名称> <片段ID>.<ext>`（如 `readable-focus 20260905120000-abcdefg.css`），使得单 Gist 多文件能够天然反解出片段的唯一身份。
- **成熟的导入三模式（`ImportPlan`）**：
  1. `merge`（合并更新，默认）：本地已有同 ID 片段时，更新名称与代码内容，但**保留本地的 `enabled` 启用偏好和自定义排序位置**；未见过的片段作为新增；
  2. `overwrite`（镜像覆盖）：以导入集合作为唯一事实源，完全覆写本地；
  3. `fork`（分叉新增）：完全忽略文件名携带的 ID，为所有条目重新生成本地唯一 ID，将他人分享的代码转化为完全独立的本地副本。
- **安全凭证托管**：集成 `siyuan-token-vault`，安全存储 GitHub Personal Access Token。

### 4. 编辑器与 Prettier 格式化工程
- **CodeMirror 6 深度集成**：包含行号列、括号匹配、语法高亮折叠、搜索替换，并读取思源 `window.siyuan.config.editor.codeTabSpaces` 自动对齐制表符或空格缩进。
- **定制化 Prettier 策略**：
  - 打包了 `prettier/standalone` + `meriyah`（轻量 JS 语法解析器）+ `postcss`（CSS 格式化）；
  - **短片段软折行抑制**：将 `printWidth` 强制锁为 `Number.MAX_SAFE_INTEGER`，防止 2~3 行的精简 CSS 被格式化工具生硬折成 10 行碎块；
  - 使用 `formatWithCursor` 自动计算光标相对偏移，格式化前后光标不乱跳。

### 5. 本地文件夹监听（File Watcher）
- 支持轮询指定工作区目录（如 `data/snippets/`）下的 `.css` 和 `.js` 外部文件，自动将外部用 VS Code 编写的文件导入到思源内。

## 二、 深度横向对比切片

| 核心维度 | TCOTC/snippets (v2.0.4) | 小驴雷切第三面板（片段实验室 + 商店） | 优劣与取舍切片 |
| :--- | :--- | :--- | :--- |
| **产品定位** | **单一领域工具**：专注于代码片段的编辑与管理 | **统一切换与工作上下文平台**：第一面板（切换器）、第二面板（工作台）、第三面板（代码实验室）、悬浮球同生共长 | 小驴雷切具备跨表面协同与即时唤醒优势；TCOTC 则在单点深度上更深。 |
| **安全与沙箱** | **直接注入执行**：JS 直接以 `<script>` 注入 DOM，缺乏权限与风险防线 | **极致安全防御（ADR 0222）**：JS 默认处于 `script: "blocked"` 安全禁执行态；AI 生成代码具备行级/块级 Diff 隔离草稿审查区 | **小驴雷切完胜**。在笔记插件中无限制执行第三方 JS 会带来灾难性的笔记破坏隐患，小驴雷切的安全防线不可妥协。 |
| **片段组织层级** | **Sidecar 分组折叠树**：支持用户自定义创建分组、拖拽排序、组间穿透 | **两级平铺过滤**：按全部 / CSS / JS 过滤，暂无自定义文件夹或业务分组 | **TCOTC 领先**。用户片段超过 20 个后，缺乏分组会导致列表过长，值得小驴雷切借鉴吸收。 |
| **片段商店与生态** | **Gist 同步与发布**：依赖用户自建 GitHub Gist 分享，缺少内置官方推荐源 | **内置精选开箱即用商店**：具备官方甄选 CSS 片段（焦点环、极窄侧栏流、防眩光），1 键导入草稿 | **互补性强**。小驴雷切有现成的内置商店大厅，但缺乏导入第三方 Gist 与合并冲突规划（Merge/Overwrite/Fork）。 |
| **代码格式化** | **内置 Prettier**：支持 JS 与 CSS 自动排版与光标保持 | **无内置格式化器**：依赖用户手动排版 | TCOTC 体验优秀，但为此付出了巨大的包体体积（见下方包体分析）。 |
| **包体与性能预算** | **约 478 KiB**（只包含一个片段管理功能，CodeMirror 6 + Prettier 占据 80% 体积） | **575 KiB 严苛门禁**（包含切换器、全功能工作台、小组件系统、代码实验室、悬浮球 5 大体系） | **小驴雷切资源利用率极高**。小驴雷切不可能引入 200KB+ 的 Prettier 依赖，否则会击穿 578 KiB 仓库发布门禁。 |

## 三、 小驴雷切第三面板与商店的吸收融合建议（精益落地路径）

结合小驴雷切现有的 **“零破坏、包体紧平衡（<=578 KiB）、高安全隔离、跨面板一体化”** 约束，我们应采取**“吸纳其优雅交互与数据策略，摒弃其沉重依赖与安全隐患”**的渐进式吸收方案：

### 1. 吸收融合一：落地片段商店的 `ImportPlan`（合并 / 覆盖 / 分叉三模式）
- **借鉴点**：`TCOTC/snippets` 的 `import-plan.ts` 纯函数算法极其干净，无外部依赖。
- **落地方式**：
  在小驴雷切的片段商店从社区、Gist 或本地 JSON 导入代码时，提供三种清晰策略：
  1. `[ 增量合并 (Merge) ]`：本地同 ID 片段更新代码，保留用户的启用状态与工作台绑定；
  2. `[ 分叉新增 (Fork) ]`：全部重新派生本地 ID，作为独立的自定义副本（适合从商店一键克隆并二次魔改）；
  3. `[ 镜像覆盖 (Overwrite) ]`：全量替换。

### 2. 吸收融合二：轻量级分组与折叠树（Sidecar Grouping）
- **借鉴点**：不改写思源内核 `conf.json` 原生数据结构，通过在插件 storage 维护轻量 `snippet-groups.json` 实现组归属。
- **落地方式**：
  - 在第三面板左侧增加轻量级业务分组（如：“🎯 编辑排版”、“🎨 视觉主题”、“⚡ 效率增强”）；
  - 保留未分组（`Ungrouped`）兜底；
  - 组状态（折叠/展开）记录在本地存储，保持小驴雷切极简轻快的交互感。

### 3. 吸收融合三：轻量免依赖 CSS 格式化器（Lightweight Rule-based Formatter）
- **拒绝引入重型依赖**：`Prettier standalone` 编译后体积达 180~250 KiB，小驴雷切目前剩余包体余量仅约 2.7 KiB，绝不能引入 Prettier。
- **替代方案**：
  在 `src/util.js` 中实现一个**仅 2.5 KiB 的零依赖 CSS 紧凑格式化器**：
  - 利用状态机对选择器、大括号 `{}`、声明分号 `;` 和冒号 `:` 进行标准缩进展开（2空格）与尾随空格修剪；
  - 同样锁住软折行，保持短片段代码的紧凑可读性。

### 4. 吸收融合四：本地工作区片段目录静默联动（Local Workspace Ingestion）
- **借鉴点**：TCOTC 的本地文件夹监听深受外部习惯使用 VS Code / Sublime 用户的喜爱。
- **落地方式**：
  无需打包重型 `chokidar` 或复杂定时轮询，而是利用思源原生的 `/api/file/getFile` 与 `/api/file/readDir` API：
  - 在第三面板工具栏提供一个 **`[ ↻ 从 data/snippets 扫描导入 ]`** 快捷按钮；
  - 用户用外部 IDE 修改本地 CSS 文件后，点击瞬间即可一键对账并以 `Merge` 模式同步至第三面板。

### 5. 坚守小驴雷切独有的核心安全壁垒（Non-Negotiable Guardrails）
- **安全红线不动摇**：坚决保留小驴雷切在 ADR 0222 中确立的“JS 运行时强制沙箱阻断（`script === "blocked"`）”与“AI 代码生成行级/块级 Diff 差异审查隔离区”，不盲目开放用户任意运行未审查 JS 的通道，确保笔记数据 100% 安全。
