# 备份覆盖与故障恢复剧本（2026-10-06）

这份记录对应 T-7148，建立在 [`docs/data-scope-2026-10-06.md`](data-scope-2026-10-06.md) 的数据范围上。它用于本地隔离演练和后续 T-7118 候选升级演练，不把一次本地测试写成真实宿主、跨设备或发布渠道已验证。

## 覆盖盘点

| 手段 | 能覆盖 | 明确不覆盖/限制 | 恢复入口 |
| --- | --- | --- | --- |
| 配置包 | 设置白名单 + 文档集，整体校验后导入 | 不含最近/收藏完整历史、工作台全部运行时状态、缩略图、回收站、原生片段和 Gist Token；多 key 仍不是宿主事务 | 设置页导出/导入，导入前预览并确认 |
| 原生片段备份 | 原生 CSS/JavaScript 片段快照和主开关，带版本、大小和条数上限 | 不替代插件设置；预览不执行 JS、不加载网络；真实宿主写入回执仍需核对 | 片段实验室“备份片段”→“恢复备份”→选择条目→确认 |
| 片段回收站 | 保存前覆盖、删除前和冲突快照；有数量/年龄/总量限制 | 清空后不可逆；只保存有界片段快照，不是全量工作区备份 | 回收站“恢复为新草稿”，恢复后保持停用 |
| 思源/工作区备份 | 覆盖范围由宿主版本和用户备份策略决定 | 当前没有证据证明它会原子覆盖插件 18 个 key 或外部 Gist | 依宿主原生恢复流程，恢复后重新打开插件并检查健康状态 |

## 隔离演练剧本

### A. 配置包失败与回退

1. 使用一次性工作区写入一个设置白名单字段和一组无敏感文档集，导出配置包并记录文件 SHA-256。
2. 修改 JSON 的 `app`、schema 版本、未知设置字段、超大备注和非法文档集形状，逐个导入。
3. 预期：导入在整体校验阶段拒绝，当前设置和文档集保持不变；错误不能把未知字段透传到设置。
4. 用未修改的包导入，确认只应用白名单和文档集；随后导出一次比较归一化后的内容，明确 `generatedAt` 是导出元数据，不把它当成用户数据同步证明。
5. 在导入执行中主动取消确认，确认没有半包应用；若宿主返回写入未核验，记录“可能已生效，请刷新核对”，不能自动重试覆盖。

### B. 原生片段备份恢复

1. 在隔离工作区准备两个禁用片段和 CSS/JavaScript 主开关，导出原生备份。
2. 修改一个片段、删除另一个片段，再打开恢复预览；检查新增、替换、删除、保持四类行和可选主开关恢复项。
3. 只选择一个片段并确认，确认未选择项保持原状；恢复后刷新原生列表，检查保存回执和片段内容。
4. 在恢复前让原生片段发生一次外部变化，确认签名冲突会阻止覆盖并提示重新读取；导入过大、条目过多或结构损坏的文件必须拒绝。
5. 恢复成功后执行一次“撤销恢复”，确认只在当前会话保留一次性撤销快照，不生成新的持久化备份。

### C. 片段删除与回收站

1. 保存前覆盖片段和删除片段各一次，确认回收站条目带来源和时间边界，但不回显完整敏感路径。
2. 选择“恢复为新草稿”，确认新草稿默认停用；编辑、保存、启用必须由用户分开完成。
3. 清空回收站并刷新，确认条目不可再恢复；此步骤只使用隔离夹具，不触碰用户真实片段。

### D. 宿主故障、取消和重启

对每种写入分别注入：网络/宿主超时、明确失败、响应结构异常、写入可能已落地但读回失败、用户取消。每种结果记录：

- UI 状态（成功、失败、待核验、取消）；
- 是否保留编辑草稿和原快照；
- 刷新后能否确认真实状态；
- 重试是否会重复写入或覆盖新变化；
- 插件重载后是否仍保留回收站、分组和文档集。

## 通过条件和当前限制

- 失败和取消不清空原状态；确认成功必须有宿主读回或明确结果，未知写入只能标待核验。
- 配置包与片段备份均在导入前校验大小、版本和形状；不得通过放宽上限来“恢复成功”。
- 多 key 持久化不是原子事务；如果设置已写而文档集写入失败，界面必须显示分项结果并允许重新导入。
- 当前自动化已覆盖纯模型的校验、差异、恢复计划、取消和失败分类；真实思源的下载、文件选择器、安装升级和长期同步仍待 T-7118/T-7115～T-7117 取证。
- 未完成真实演练前，发布材料只能写“支持配置包/片段备份的本地恢复路径”，不能写“支持一键完整备份”或“跨设备无损恢复”。
