# T-7144 候选矩阵与准入边界（2026-10-16）

这份矩阵把 T-7144 当前能独立验证的证据和仍需真人或旧宿主数据的边界分开。它服务于下一轮候选选择，不把隔离思源样本当成使用频率，也不把“没有发现缺口”改写成已完成的 UI 精修。

## 证据等级

| 等级 | 含义 | 能支持的结论 |
| --- | --- | --- |
| E0 | 模型、接线或契约测试 | 响应归一化、排序、渲染和动作合同成立 |
| E1 | 隔离思源真实宿主单样本 | 当前宿主版本的响应形状和点击路径成立 |
| E2 | 隔离宿主加规模、负向或多场景回归 | 已关闭一个可复现的工程缺口，仍不代表个人工作区频率 |
| E3 | 真人问题记录或使用频率 | 满足 T-7144 的“高价值”排序输入，可决定是否做体验精修 |

## 当前结论

T-7144 仍不能仅凭本矩阵标记完成。已有 E1/E2 证据足以关闭若干工程缺口，但任务原始准入要求从 T-7168 或问题记录选择 5～8 个真实高频项；当前没有 E3 输入，不能把“高价值”排序或体验收益据为事实。

在无真人反馈的情况下，最小可验证工作是旧字段 fixture 兼容审计：书签旧字段已由 T-7285 收口，大纲由 T-7286 明确无活动文档和未知包装的拒绝边界；统计仍待可核验旧字段样本。该工作只在仓库内验证兼容边界，不扩大支持版本声明；生产修改须在 fixture 暴露真实缺口后才发生。

标签精确定位暂不施工。当前思源公开接口只有 `toggleModel("tag", true)`，没有稳定的选中参数；继续伪造“已选中”会把动作成功和定位成功混为一谈。
