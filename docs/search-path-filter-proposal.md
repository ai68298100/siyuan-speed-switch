# 路径筛选 UI 研究草案

## 当前可复用能力

搜索模型已经接受 `filters.notebook` 与 `filters.paths`，并在请求层转换为思源原生 `paths`/`idPath`。路径会统一斜杠、去重并拒绝危险字符、`..` 跳转和不安全笔记本 ID；模型层不需要新增 SQL 或任意字符串拼接。当前 UI 暂不暴露路径树入口。

上游源码核验确认 `/api/filetree/listDocsByPath` 由 `CheckAuth` 保护，请求使用 `notebook`、`path` 和可选 `maxListCount`，成功响应的 `data` 包含 `box`、`path`、`files`；每个文件公开 `id`、`name`、`path` 与 `subFileCount`。该端点已存在于 v2.8.x，但未列入上游 `docs/API.md` 的公开 API 清单，因此原型必须保留能力探测与降级，不能把失败解释为空目录。

本仓库已新增 `src/path-filter-model.js`，只负责构造有界请求和清洗响应：严格校验笔记本、父路径、文档 ID 与文件路径一致性，最多返回 100 项，并将失败、输入非法和响应错配区分为稳定原因。由于端点尚未列入公开 API 清单，生产 UI 暂不接入路径入口；目录枚举模型保留给后续能力探测使用。

侧栏入口的空间与回退判断见 [路径筛选侧栏体验评估](search-path-filter-sidebar-evaluation.md)。

## v0.17 小范围原型

1. 桌面搜索筛选弹层增加“路径”二级入口，只有选定笔记本后才启用。
2. 首版只展示宿主确认过的文档路径前缀，不在前端猜测目录结构；无法取得路径树时保留笔记本筛选并显示轻量降级提示。
3. 已选路径以可删除 chip 展示，最多 8 条；清空路径不会清空关键词、类型或排序条件。
4. 侧栏沿用相同筛选状态但压缩为单层列表；手机端默认只提供笔记本筛选，路径入口待真实窄屏验收后再开放。

## 性能与生命周期边界

- 仅在用户打开筛选弹层后请求路径数据，不为首屏搜索预取目录。
- 路径请求使用现有会话取消和请求序号，关闭弹层、切换笔记本或开始新搜索时丢弃过期结果。
- 列表最多渲染 100 个节点，输入过滤 150ms 防抖；不引入树形图库或常驻观察器。
- 路径列表只在当前筛选会话内缓存，切换笔记本立即失效，避免跨工作区携带陈旧目录。

## 可访问性与验收

- 路径入口使用按钮语义和 `aria-expanded`，结果列表使用可键盘到达的选项；每个 chip 提供独立移除名称。
- 无路径结果与 API 缺失都使用现有 bounded empty/error 状态，不遮挡重试和折叠控件。
- 进入主线前需以能力探测确认目标宿主可调用路径枚举端点，并补 UI 请求取消与降级回归。
- 桌面原型先通过结构 smoke；真实桌面和手机视觉验收仍集中到大版本节点，不以 Chromium 截图替代宿主证据。

## 未决问题

- 路径枚举端点作为未列入公开 API 清单的内核接口，未来版本是否保持兼容。
- 路径权限变化时是否需要重新验证已选前缀。
- 多路径选择是否值得在手机端开放，或长期保持笔记本级筛选。
