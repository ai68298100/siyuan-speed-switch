## 品牌锚点

### 名称

- 中文主名：**小驴雷切**。
- 英文主名：**LvSpeed Switch**。
- 仓库/包标识：`siyuan-speed-switch`。
- 对外首次出现使用“小驴雷切（LvSpeed Switch）”，后续根据语言环境使用一个主名；不要在同一页面交替使用 `Speed Switch`、`LvSpeed`、`小驴速切` 等未定名称。

### 一句话定位

中文推荐：**小驴雷切是思源笔记的本地优先导航与工作上下文平台，把切换、工作台、片段管理和快速触发放在一条可恢复的工作路径上。**

English recommendation: **LvSpeed Switch is a local-first SiYuan navigation and work-context platform that connects switching, the workbench, snippet management, and quick actions in one recoverable workflow.**

短版（集市卡片或 GitHub 摘要）：

- 中文：**在思源里快速找到、预览并回到正在做的事。**
- English: **Find, preview, and return to your work in SiYuan.**

“本地优先”表示核心切换和多数状态在本地工作；联网组件、凭据、本机服务和第三方提供方必须在界面中单独说明。它不表示所有组件离线可用，也不构成隐私或服务可用性承诺。

### 四个入口的关系

四个入口是一条工作路径的四种工作方式，不是四个互相竞争的产品：

| 入口 | 用户问题 | 品牌角色 | 对外短语 |
| --- | --- | --- | --- |
| **切换器**（第一面板） | 我现在要找哪个页签、文档或片段？ | 高频入口和平台根；搜索、预览、打开 | **找到并预览** |
| **工作台**（第二面板） | 我想把哪些信息放在手边？ | 组件、布局、健康回执和恢复现场 | **看见并编排** |
| **片段实验室**（第三面板） | 我如何安全管理 CSS/JavaScript 片段？ | 桌面优先的编辑、隔离预览和人工确认 | **修改并审查** |
| **悬浮球**（全局触发器） | 我怎样从当前页面快速回到平台或动作？ | 快速触发器，不取代前三个表面 | **随时回到工作** |

README 当前声明片段实验室为桌面专属，悬浮球用于桌面主窗口和手机、侧栏不挂载；侧栏的 44 px 是侧栏布局约束。对外素材不得把悬浮球画成侧栏内置功能，直到产品事实完成统一对账。

四入口的视觉层级应保持：切换器最大、最容易识别；工作台和实验室作为平台内表面；悬浮球为轻量触发符号。素材不要把四个入口画成四个独立品牌，也不要暗示工作台组件、第三方服务或 AI 是安装后的必经步骤。

## 核心受众与语气

### 受众优先级

1. **普通思源用户**：有多个页签、收藏和文档，需要更快找回工作现场；首次使用不应先理解组件协议或 AI。
2. **高频工作者**：需要键盘、分栏、搜索预览、收藏分组、工作台布局和跨表面恢复；关心速度、确定性和可回退。
3. **片段维护者**：管理 CSS/JavaScript 片段，要求预览安全、保存回执、冲突保护和回收站；桌面优先说明必须显眼。
4. **生态插件作者/高级用户**：通过公开协议接入只读组件或快捷动作；需要看到版本、来源、生命周期和不可用边界。

不把“想要一个自动化 Agent”或“需要完整内容库”的人群作为主入口。Agent、联网组件和兄弟插件可以作为可选能力，不能成为品牌承诺的中心。

### 语气规则

- **清楚**：用“找到、预览、打开、保存、重试、需要配置”等动作词，少用抽象口号。
- **克制**：说明“本地优先”“可选联网”“桌面专属”“需要提供方”等限制；不使用“全能、无缝、零配置、全平台完成”等未被证实的词。
- **可恢复**：失败文案要给下一步和回退路径；不要把空数据写成数据丢失，也不要把缓存写成实时保证。
- **尊重宿主**：复用思源主题、图标和交互语义；不把插件说成替代思源原生搜索、片段或备份。
- **双语一致**：中英文使用同一事实、端侧范围和快捷键；`switcher / workbench / snippet lab / floating ball` 作为固定术语。

## 视觉方向（沿用并收敛）

### 主符号

当前蓝青层叠页签 + 闪电已经同时表达“多个工作对象”和“快速切换”，没有证据要求推翻它。后续精修应围绕以下约束：

- 保留一个清晰的页签/窗口叠层轮廓与一个主闪电形；不要继续堆叠文字、四个入口缩略图或复杂渐变。
- 闪电是速度和回到现场的象征，不暗示电量、AI 或网络状态。
- 图标在 16/24/32 px 时依靠轮廓、色块和留白辨识；发光、细描边和微小内嵌细节只能作为增强，不能成为识别条件。
- 蓝/青为主色方向，具体色值应从可维护母版和思源主题对照中冻结；本 brief 不凭截图猜测新的色值。

### 尺寸、背景和裁切

T-7156 的导出验收至少覆盖：16、24、32、48、160 px；浅色、深色和中性灰背景；方形展示与圆形头像裁切。每个尺寸都要检查：

- 图形主体四周保留稳定安全边距，圆形裁切不切掉页签或闪电；
- 白底版本不靠白色外发光分离，深色版本不靠黑色描边制造脏边；
- 16/24 px 不保留不可读的细线、文字或多层阴影；
- 明暗主题之间只改变必要的底板/对比度，不改变主符号语义；
- 导出母版、透明/底板变体、尺寸清单和 SHA-256 可追溯；插件包只放宿主需要的导出，不把大母版塞入 `package.zip`。

当前 `icon.png` 160×160 且低于 20 KB，尺寸与体积可作为基线；是否达到圆形头像、暗色背景和 16 px 可读要求尚未验证，不能在发布材料中提前写“各尺寸已通过”。

## 截图与演示选择原则

### 首图优先级

新的 `preview.png` 应首先让陌生用户看懂“找到 → 预览 → 打开”这条主路径；四入口关系可用第二张界面图或 README 分图补充。建议素材顺序：

1. 切换器桌面真实生产界面：有搜索/页签/预览层级，内容使用脱敏测试文档；
2. 工作台真实界面：显示来源、健康状态和布局，但不堆满 58 个组件；
3. 片段实验室真实桌面界面：展示安全预览或 blocked 说明，不伪装 JavaScript 被执行；
4. 手机/悬浮球界面：只有真实设备或明确标注的浏览器宿主证据才能使用；
5. 明暗主题、宽桌面和窄侧栏各选能说明差异的一张，不做同一画面的重复变体。

### 截图硬约束

- 只能使用当前生产代码对应的实际界面；原型、静态 mock、旧版本截图必须在文件名或说明中明确标注。
- 不出现真实笔记正文、私人路径、账号、Token、API Key、带凭据 URL、第三方受版权保护的内容；用专门的脱敏夹具或测试工作区。
- 每张图记录插件版本、思源版本、端侧/窗口尺寸、主题、来源（真实宿主/浏览器 smoke/原型）和捕获日期；README `alt` 文本描述用户能看到的事实。
- 不在截图中烧录过时版本号、营销大字或无法核实的“全部可用”徽章；状态徽标和失败态要保留，以免素材暗示无故障。
- 浏览器截图不能冒充 Android、真实桌面最终观感、读屏或网络服务证据；真实设备素材要单独保存证据入口。
- 首图缩小到集市卡片尺寸仍应读出主流程；若文字只能放大查看，优先减少内容而不是塞更多标签。

现有 `preview.png` 是旧深色切换器画面，尺寸合适但不能证明当前四入口和最新 UI；在新真实截图完成前继续保留它可以避免无素材发布，但应避免把它称为“当前完整预览”。
