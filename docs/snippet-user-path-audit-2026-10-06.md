# 片段实验室普通用户路径审计（2026-10-06）

这份记录对应 T-7145。它只盘点当前代码和中英文案的实际行为，供 T-7168 的真人可用性走查使用；没有把尚未在真实宿主、真实提供方或真人测试中验证的效果写成承诺。

## 路径和状态词

| 阶段 | 用户动作 | 当前可见状态 | 用户应形成的理解 | 失败/取消回执 |
| --- | --- | --- | --- | --- |
| 新建 | 点击“新建”或从商店选择“以此新建禁用草稿” | `草稿`，保存按钮为“保存草稿” | 内容只在工作室草稿中，尚未写入原生片段，也不会启用 | 空名称或空代码时保存按钮禁用；返回前会进入离开守卫 |
| 修改 | 编辑名称、类型、代码或元数据 | `未保存` | 当前预览反映草稿，原生保存版本仍在“已保存”窗格 | 切换、返回和关闭触发保存/放弃/继续编辑选择；保存失败保留草稿 |
| 预览 | 查看实时预览、切换场景/宽度/主题、打开诊断 | “效果预览”；能力回执显示场景、宽度、主题、探针、脚本、网络和语义边界 | 这是隔离的近似样例，不等于当前笔记；网络与脚本在预览中关闭 | 预览失败显示错误态；JS 预览不会执行脚本，并给出暂缓说明 |
| 保存 | 点击“保存”或“保存草稿” | `已停用`（新草稿）或原生片段的 `已启用/已停用` | 保存写入思源原生片段；启用是另一个明确动作 | 写入结果会显示成功、失败或“可能已生效，请刷新核对”；不把未知结果当成功 |
| 启用 | 已保存后点击“启用” | `已启用` | 片段进入原生启用状态；启用前必须先保存 | 未保存时按钮被拦截并提示“启用前请先保存草稿” |
| 停用 | 已保存后点击“停用” | `已停用` | 片段仍保存，但不再由宿主应用 | 宿主回执失败时保留当前界面并提示刷新核对 |
| 取消/返回 | 点击“返回切换器”或关闭 | 无脏稿时直接返回；有脏稿时出现离开选择 | 取消离开不会偷偷丢弃草稿；保存是显式选择 | 选择保存失败会留在工作室；选择继续编辑可回到草稿 |
| 恢复 | 从回收站选择“恢复为新草稿”或从备份打开恢复预览 | 新草稿保持 `已停用` | 恢复先生成可检查的副本，保存并启用仍由用户决定 | 备份无效、版本不支持、冲突、取消和未核验均显示独立状态 |

## 预览的安全词义

- “效果预览”只渲染隔离文档中的静态样例和有限探针。能力回执中的“语义近似预览，不代表当前笔记”必须与预览标题一起保留。
- CSS 预览使用内置主题快照或基线对照；它帮助判断选择器覆盖方向，不代表当前思源主题的最终像素结果。
- JavaScript 片段在工作室预览中始终不执行。`snippetJSCascadeHint` 说明原生列表顺序，`snippetJSPreviewUnavailable` 说明预览执行被暂缓；两者不能改写成“脚本已运行”。
- 预览网络为“无”。媒体只显示占位，音频、视频和嵌入内容不加载。预览不会修改笔记，也不会自动保存片段。
- AI 区域先显示上下文范围、权限与同意项，再显示候选。候选只是草稿内容；用户必须逐条接受差异或整块接受，接受后仍需手工保存，AI 不直接写入原生片段。
- Gist 导入创建新的禁用草稿；Gist 发布/更新属于显式联网动作，不能从“读取预览”推断已经发布。

## 本地走查记录

在真实用户走查前，维护者按下面的最小脚本复核一次：

1. 从切换器进入片段实验室，创建一个 CSS 草稿，填写名称和一条可观察的规则。
2. 确认头部依次能区分 `草稿`、`未保存`、`已停用/已启用`；打开“已保存”窗格时，新草稿显示“尚无已保存版本”。
3. 切换预览宽度和主题，确认能力回执更新；在 CSS 中加入一个不会命中静态样例的选择器，确认诊断允许“可能未命中/未知”而不声称已生效。
4. 点击返回，在离开守卫中选择继续编辑；再次返回并选择保存，确认保存后仍为停用状态。
5. 点击启用，再点击停用；把宿主写入改为失败或未核验响应，确认界面保留草稿并显示可恢复的刷新提示。
6. 导入一个备份或从回收站恢复，确认结果是新的禁用草稿；取消恢复和冲突均不能覆盖当前原生片段。
7. 若环境提供 AI 夹具，开始生成后点击取消，确认请求取消、按钮恢复、候选不会残留；若没有提供方，只记录“夹具未提供”，不伪造在线质量结论。

## 仍需 T-7168 补证的观察点

- 新用户是否把“保存草稿”和“启用”理解成两个动作；是否能在第一次失败后找到刷新/重试路径。
- 新用户是否把 CSS 近似预览当成当前笔记的最终效果，是否能读懂能力回执中的“近似”“无网络”“脚本禁用”。
- 新用户是否知道 AI 候选需要接受后再保存，取消生成后是否知道下一步可以重试。
- 新用户是否能区分“恢复为新草稿”“恢复备份”和“撤销恢复”，以及取消/冲突时是否敢于继续操作。
