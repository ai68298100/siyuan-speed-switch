# 可选联网与凭据数据流清单

日期：2026-10-06。任务：T-7150。

这份清单按当前源码和仓库内政策说明整理，帮助用户判断“什么时候会联网、会带什么、数据存在哪里、怎样停用”。它描述的是插件可执行的请求边界，不代表远程服务的隐私政策、日志保留、收费、配额或实际账号状态。没有真实账号、真实提供方或宿主后台证据的地方明确标为“未知/待验证”。

## 阅读口径

| 术语 | 含义 |
| --- | --- |
| 本地 | 当前思源工作区、插件内存、原生片段和同源思源内核 API。 |
| loopback | `localhost`、`127.0.0.1`、`[::1]` 等本机服务；请求仍可能经过思源的本机正向代理。 |
| 远程组件 | 用户添加并配置后，向固定公开服务或用户填写的 HTTPS 端点发起的只读组件请求。 |
| origin | 代码实际允许的目标来源或用户配置的端点；不是“数据归属方”的法律判断。 |
| 传出内容 | 请求 URL、查询参数、请求头和请求体中可能离开插件/思源的数据。响应内容不等于插件会持久化的内容。 |

通用边界：外部组件默认不请求；只有添加组件、完成必要配置并刷新/打开可见组件时才读取。网络请求有白名单、超时、取消、响应大小上限、缓存 TTL 和失败回退。组件移除或插件销毁会取消刷新；旧响应不得覆盖新配置。具体组件仍以代码为准。

## 本地与思源宿主流

### 插件本地存储

当前持久化 key、内容和清理入口见 [docs/data-scope-2026-10-06.md](data-scope-2026-10-06.md)。其中包含最近历史、收藏、文档集、工作台布局、缩略图缓存、RSS 已读、片段回收站/分组和设置。原生 CSS/JS 片段仍由思源原生片段存储，是片段正文的唯一保存源；插件回收站只是有界恢复层。

插件没有自建云同步。思源是否同步插件目录、是否在卸载时删除目录、跨设备冲突如何表现，取决于宿主版本和同步策略，当前没有完整真实矩阵证据。

### 同源内核 API

搜索、文档预览、工作台内置组件、文档集恢复和 Agent 能力通过思源同源 API（例如 `/api/query/sql`、`/api/filetree/...`、`/api/outline/...`）读取或执行。请求可能包含文档 ID、笔记本 ID、查询条件、用户配置或受控写入正文。插件的内核请求只接受源码登记的相对路径白名单；插件不把这些请求转发到任意外部主机。

Agent 的只读能力声明 `localRead: true`、`dataEgress: false`；受控写动作声明 `localWrite: true`，确认链由思源宿主 `actionEffects` 管理。旧版宿主不支持能力注册时应跳过，不影响普通切换器。Agent 输出为有界快照，不包含 Token；宿主模型是否记录会话由思源配置决定，插件没有该后台证据。

## loopback 与用户自建服务

### ActivityWatch

组件 `external-activitywatch-time` 仅接受本机地址和固定 Query API（默认 `127.0.0.1:5600`），按应用/桶聚合使用时长，不读取窗口标题；查询结果经思源 `/api/network/forwardProxy` 访问，组件缓存约 5 分钟。未配置或服务未运行时不请求并显示配置/不可用状态。删除组件或清除端点停止读取；ActivityWatch 自身数据库和日志不由插件删除。

### 本机 HTTP 订阅、Uptime Kuma、Miniflux

RSS/iCal 允许 HTTPS 公网或 HTTP loopback；Uptime Kuma 允许 HTTPS 或 loopback HTTP；Miniflux 允许 HTTPS 或 loopback HTTP，并且只访问 `/v1/entries`、`/v1/categories` 等固定路由。Miniflux Token 通过 `X-Auth-Token` 请求头发送，不进入 URL、缓存 key、日志或 Agent 快照。订阅正文只进入有界解析和内存缓存；RSS 的已读键（不是全文）进入 `sw_rss_read`。

这些服务可能记录请求、Token、订阅内容或访问时间；仓库没有服务端日志/保留策略证据。用户应在对应服务侧清除历史、撤销 Token 或删除订阅。

## Gist：代码和凭据的特殊边界

Gist 默认折叠；读取公开链接不需要 Token。发布或更新只接受已保存且没有未保存修改的片段，正文以一个带原生片段 ID/类型的文件发送，`public: false` 表示 GitHub 的 **unlisted**：知道链接即可访问，不能称为私密。仓库不自动把 Gist 删除当作清除本地链接，也不自动重试不确定的写入。

插件设置中保存 Token 明文，但输入框默认密码态、保存后清空、界面只显示末四位；配置包白名单明确排除 Token 和 Gist 链接。读取/发布请求使用 `credentials: omit`、`redirect: error` 和 `no-referrer`；请求/响应大小、文件数、超时和取消均有上限。详见 [ADR 0126](adr/0126-snippet-gist-sharing.md) 与 [数据范围说明](data-scope-2026-10-06.md)。

清除 Token 只阻止后续需要认证的请求，不会撤销已经签发的 GitHub Token；撤销必须在 GitHub 账户侧完成。删除远端 Gist 也必须在 GitHub 侧完成。远端 GitHub 的日志、Token 生命周期和账号组织策略未知。

## 宿主 AI：插件边界与未知项

片段实验室调用思源原生 `/api/ai/editor/chat` SSE 接口，不直连某个供应商，也不读取供应商 Token。请求可包含：

- 用户输入的指令；
- 用户明确勾选的当前 CSS/JS 草稿；
- 用户明确勾选的最近 AI 对话历史。

其他文档、选区、块、搜索结果、组件数据、Gist Token 和外部组件响应不会自动进入片段 AI 上下文。请求和响应有长度上限；取消、超时、401/403、格式错误会回到本地失败状态。候选先显示摘要、差异和确定性审查结果，必须由用户逐项接受后才改草稿。

宿主决定提供方、模型、账单、配额、会话保留和服务端日志；当前仓库没有真实在线提供方或账号证据，因此不能宣称“零费用”“不留存”或某家供应商的隐私政策。用户应在思源 AI 设置和相应提供方控制台停用、换 Key、查账单或撤权。

## provider 与其他插件

`registerHomeModule()` 和 `registerQuickAction()` 保存可序列化的 ID、标题、配置和端侧目标，运行时回调只保存在内存。雷切调用提供方的 `read(config, device, context)` 或动作 handler；提供方可以自行访问网络、读取其插件数据或执行宿主动作，这些内容不由雷切协议完整约束。雷切不扫描 DOM、不保存外部函数引用、不把 provider secret 放入 Agent/商店快照。

注销/卸载提供方后，雷切保留用户配置和布局，组件显示不可用并停止调用；重新注册可恢复。提供方的远程日志、凭据存储、删除策略和真实权限必须由提供方文档与实机证据补齐，本清单不替其背书。打卡桥接和未来“小驴常用”入口属于此边界，具体数据域在各自插件。

## 缓存、错误与日志检查

- 外部生活组件响应缓存位于 `life-widget-network.js` 的内存 `Map`，有数量上限和 TTL；缓存 key 使用端点/用户名等必要标识，Miniflux Token 不进入 key。
- RSS 已读状态是有界持久化标记；它不保存完整 feed 正文。缩略图、关联内容和片段回收站的本地边界见 [数据范围说明](data-scope-2026-10-06.md)。
- Gist 和 Agent 错误被归一化为稳定错误码；源码路径、原始网络响应和 Token 不应写入 UI/日志。内核代理会在本机请求体中携带必要的目标 URL/附加请求头；仓库没有宿主代理服务端日志证据。
- provider 返回值由适配器做有界投影；无法识别或超长响应进入失败/不可用态，不作为可信数据继续传播。
- 本地代码审查确认的“不自动上传”只适用于本插件已知路径；操作系统、思源、浏览器、代理、远程服务和第三方插件可能有各自日志，当前未知。

## 用户操作速查

1. **只用本地能力**：不要添加外部组件，关闭已添加组件并清除城市、URL、用户名、Token 等配置；工作台刷新后不再发对应请求。
2. **删除本地痕迹**：按 [数据范围说明](data-scope-2026-10-06.md) 清理历史、缩略图、RSS 已读、回收站、Gist Token 和布局；清空回收站不可逆。
3. **撤销远程权限**：插件内先清 Token，再到 GitHub/Miniflux/其他服务撤销；删除已发布 Gist、订阅和 ActivityWatch 数据要在各服务侧执行。
4. **停用 AI**：在思源侧关闭 AI 能力或删除提供方配置；插件取消当前流并保留本地草稿。
5. **停用 provider**：在提供方插件中注销/卸载；雷切会保留配置但显示不可用，不应继续调用已注销回调。
