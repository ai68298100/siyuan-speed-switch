# 调研-吸收循环 · 第 4 轮报告：未来产品方向（2026-09-23）

> 本报告最初用于用户评审和未来路线规划；2026-09-23 已由 [ADR 0076](adr/0076-navigation-context-roadmap.md) 和 `ROADMAP.md` §8.0.16 正式吸收。报告保留为调研依据，生产落地另见当期开发账本。
> 研究范围：GitHub、Obsidian 社区插件、思源社区插件、桌面启动器、浏览器工作区工具和知识管理软件。

## 1. 先确定插件应该成为什么

### 1.1 产品定位

小驴雷切应该继续定位为：

> **思源笔记的本地优先工作上下文切换器。**
>
> 它把“我正在处理的内容、我经常访问的内容、我下一步想执行的动作”放在一个快速入口中，帮助用户找到、预览、切换、恢复和继续工作。

这个定位包含三层：

1. **导航层**：已打开页签、最近关闭、收藏、文档集、搜索结果和关联内容。
2. **上下文层**：当前文档、工作区、滚动位置、光标位置、场景、最近动作和相关文档。
3. **动作层**：思源宿主命令、日记、模板、快速记录、插件动作和受控 Agent 能力。

它不应变成：

- 另一个完整文件树；
- 另一个完整全文搜索引擎；
- 一个泛化的主页/数据大屏；
- 一个系统级启动器；
- 一个不受约束的脚本执行器；
- 一个把所有组件都塞进首屏的功能市场。

### 1.2 用户真正要完成的事情

用户打开插件时通常只有五种意图：

1. 回到刚才正在看的内容；
2. 找到某个已经打开但被遮住的页签；
3. 找到一个记得大概内容、但不记得路径的文档；
4. 恢复一个项目或研究现场；
5. 立即执行一个和当前上下文有关的动作。

因此未来功能必须回答一个问题：它是否让这五件事更快、更可靠、更容易恢复？不能回答的功能进入候补池。

### 1.3 统一评价标准

未来每个方向使用以下评分：

- **价值**：是否减少寻找、切换和恢复成本；
- **频率**：是否每天或每周都会用；
- **独特性**：思源原生是否已经做得足够好；
- **宿主风险**：是否依赖不稳定或移动端缺失 API；
- **跨端收益**：桌面、侧栏、手机能否共享语义；
- **复杂度**：是否会引入新的数据模型、索引、权限或依赖。

优先做高价值、高频、低宿主风险、能共享语义的方向。

## 2. 外部研究得到的共性信号

### 2.1 强入口产品都把“搜索”和“动作”放在同一个入口

Obsidian Quick Switcher++ 已经把打开编辑器、工作区、书签、命令、相关内容和快速筛选放入同一个切换器；它还保留最近命令、固定命令和结果类型过滤。PowerToys Command Palette 同时提供应用、文件、网页、命令、扩展、紧凑搜索框和边缘 Dock。Flow Launcher 通过插件商店、关键词和键盘上下文扩展入口。它们共同说明：统一入口的价值来自**结果类型和动作类型的统一编排**，不是来自把所有 UI 堆到一页。[Quick Switcher++](https://github.com/darlal/obsidian-switcher-plus)、[PowerToys Command Palette](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/overview)、[Flow Launcher](https://github.com/Flow-Launcher/Flow.Launcher)

### 2.2 搜索产品的差异在排序、上下文和可恢复性

Omnisearch 使用 BM25、文件名/标题权重、模糊容错、查询语法、文件类型过滤、结果高亮、搜索历史和最近度增强；思源的文档搜索插件则补充了按笔记本/路径/块类型筛选、结果定位、代码块和数据库高亮、移动端 Dock 搜索。Dataview 证明了“有界索引 + 可组合查询 + 动态视图”对知识库导航很有价值。[Omnisearch](https://github.com/scambier/obsidian-omnisearch)、[思源文档搜索](https://github.com/Misuzu2027/syplugin-document-search)、[Dataview](https://github.com/blacksmithgu/obsidian-dataview)

### 2.3 工作区产品的核心不是保存一个名字，而是保存一个可回到的现场

Workona 会自动保存空间中的标签页，切换空间时隐藏/恢复现场，还提供最近会话恢复、快照和跨设备同步；Obsidian Workspaces Plus 提供当前工作区指示器、工作区选择器、重命名/删除/创建和独立快捷键。小驴雷切已经有文档集和现场恢复基础，下一步应把“恢复成功”扩展成可解释的会话连续性。[Workona Tab Manager](https://workona.com/help/tab-manager/)、[Workspaces Plus](https://github.com/nothingislost/obsidian-workspaces-plus)

### 2.4 关联内容比单纯“更多搜索结果”更有价值

Capacities 会根据当前对象自动显示相关内容和未链接提及；其反链既是回溯入口，也是上下文复查面板。思源反链过滤面板进一步展示了按锚文本、关联定义块、提及、路径和保存条件筛选的实现空间。小驴雷切可以把相关内容放入切换器的第二层，而不必扩张成完整知识图谱。[Capacities Related Content](https://docs.capacities.io/reference/related-content)、[Capacities Backlinks](https://docs.capacities.io/reference/backlinks)、[思源反链过滤面板](https://github.com/Misuzu2027/syplugin-backlink-panel)

### 2.5 高级动作的关键是组合、预览和可解释失败

Obsidian QuickAdd 把模板、捕获、宏和多选组合成一条动作链，并提供单页输入、变量传递、目标预览、已有文档查找/创建和失败前置检查。Raycast 的扩展模型强调每个扩展提供聚焦命令或搜索入口；PowerToys Command Palette 的扩展可以提供列表页、详情页、表单页、上下文菜单和固定命令。[QuickAdd](https://github.com/chhoumann/quickadd)、[QuickAdd Macros](https://quickadd.obsidian.guide/docs/Choices/MacroChoice/)、[Raycast Extensions](https://manual.raycast.com/extensions)、[PowerToys Extension API](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/extensibility-overview)

### 2.6 思源社区已经出现“导航、搜索、主页、关联内容”四类可复用信号

思源集市通过 `plugins.txt` 维护社区插件列表和版本发布机制；官方插件示例明确了插件元数据和发布边界。社区中已经有文档搜索、反链过滤面板、主页工作台、查询视图、选中已打开文档、快捷入口等方向。小驴雷切应该吸收这些**交互和协议思想**，不复制代码，也不把自己改成主页插件。[思源 Bazaar](https://github.com/siyuan-note/bazaar)、[思源插件示例](https://github.com/siyuan-note/plugin-sample)、[思源主页](https://github.com/Glaube-TY/siyuan-homepage)、[sy-query-view](https://github.com/frostime/sy-query-view)

## 3. 值得考虑的未来大方向

下面列出 15 条，已经按建议优先级排序。这里的 P0/P1/P2 是规划优先级，不是任务号。

### D1｜统一导航与动作中枢（P0）

把已开页签、最近关闭、收藏、文档集、场景、宿主命令和插件动作纳入同一个结果编排层。输入一个词时，结果可以同时出现“打开目标”和“执行动作”，但必须有清晰的来源、类型和副作用提示。

**吸收点**：Quick Switcher++ 的多模式切换、命令/工作区/相关项统一搜索；PowerToys 的命令、文件、扩展和紧凑模式。

**建议首片**：统一结果模型和来源分区，先不增加新的动作数量。

**成功标准**：用户不需要先猜“应该打开哪个面板”，一次输入就能找到目标或动作。

### D2｜搜索与排序引擎第二版（P0）

继续保留“已开页签即时过滤 → 已打开文档内容 → 全库结果”的顺序，但把排序、拼音、标题、路径、块类型、收藏、最近、修改时间、查询语法和上次选择统一到一个可解释评分模型中。

**吸收点**：Omnisearch 的 BM25、字段权重、模糊容错、类型过滤、结果高亮和最近度；思源文档搜索插件的块定位、代码/数据库高亮和 `@` 查询过滤。

**边界**：不复制 Omnisearch，不把全文片段永久写入插件存储，不替代思源原生搜索页。

**成功标准**：常见查询前三项命中率提升，且每个结果都能说明“为什么排在这里”。

### D3｜当前文档的关联内容层（P0）

在切换器或第二面板增加“与当前文档有关”的轻量区：反链、提及、同路径/同标签、最近一起访问、文档集内邻居和相关搜索。默认最多显示少量结果，点击后回到原位置。

**吸收点**：Capacities 的 Related Content、Backlinks 和未链接提及；思源反链过滤面板的锚文本/提及/关联定义块筛选；Quick Switcher++ 的 Related Items。

**成功标准**：用户从当前文档继续探索时，不必重新输入关键词或打开完整反链页面。

### D4｜工作区和现场恢复 2.0（P0）

把“文档集”升级为可恢复的工作现场：页签、分栏、当前文档、光标、滚动比例、筛选条件、悬浮球场景和最近动作都可分层保存。恢复过程要显示成功、跳过和失败原因，并提供重试。

**吸收点**：Workona 的自动保存、快照、最近会话恢复和空间切换；Workspaces Plus 的当前空间指示器、快捷切换、重命名和删除确认。

**边界**：先保存插件能够稳定获得的状态，不伪造宿主无法读取的编辑器内部状态。

### D5｜快速捕获与组合动作（P1）

建立安全的“捕获 → 选择目标 → 预览 → 写入 → 回执”流程，支持日记、当前文档、收集箱、模板和指定文档。多步骤动作可以组合，但每一步都要声明输入、输出和副作用。

**吸收点**：QuickAdd 的 Template/Capture/Macro/Multi、单页输入、变量复用、查找已有文档、目标预览和无效路径提前拒绝。

**边界**：不开放任意用户脚本，不把执行失败吞掉，不绕过思源写入权限。

### D6｜快捷动作提供方协议与生态 SDK（P1）

把当前快捷动作目录正式化为提供方协议：动作 ID、图标、输入表单、支持表面、能力检测、版本要求、数据副作用、失败原因、恢复方式和来源插件。第三方插件没有元数据时保持 `unknown`，但不阻止用户手动添加。

**吸收点**：Raycast 的扩展命令模型、PowerToys 的扩展页/列表/表单/上下文菜单、思源 Bazaar 的包元数据和发布约束。

**成功标准**：第三方动作可以被发现、配置、测试、禁用和恢复，执行能力与展示能力继续分离。

### D7｜移动端成为独立的一等表面（P0）

移动端不再只是桌面 DOM 的缩小版：采用底部面板、触控优先的动作排序、键盘弹出避让、首帧稳定壳、宿主侧滑所有权和真实 Android 验收矩阵。桌面/侧栏/手机共享语义，但不强求相同布局。

**吸收点**：思源文档搜索插件已经把 Dock 搜索、触控结果定位和移动使用作为独立场景；Obsidian Quick Switcher++ 也明确支持移动端。

**成功标准**：手机首帧、添加入口、搜索、恢复、更多动作和悬浮球均能用真实设备证据证明。

### D8｜低打扰预览与“窥视后决定打开”（P1）

搜索结果和相关内容支持首块/摘要/路径/命中位置预览；预览可以固定、调整大小、跳到指定块，关闭后焦点回到原文档。预览默认只读，避免把导航器变成第二编辑器。

**吸收点**：Hover Editor 的可拖动、可调整大小、固定、多预览、焦点恢复和标题/块引用定位；Heptabase 的位置上下文和对象定位。

**成功标准**：用户在打开目标前能确认“这是我要找的内容”，误开和来回返回减少。

### D9｜动态收藏组与查询型文档集（P1）

允许把“标签、笔记本、路径、类型、状态、更新时间”组合成可保存的动态组。它们在空查询工作台、搜索结果和收藏面板中以轻量入口出现，而不是生成大量静态快捷项。

**吸收点**：Tana 的 Search Nodes/Supertags、Dataview 的动态查询视图、Capacities 的对象类型/标签/查询区分。

**边界**：只使用参数化内核查询和有界结果，不开放任意 SQL。

### D10｜键盘优先和可发现快捷键（P1）

增加命令前缀、数字直达、最近命令、固定命令、结果类型热键、link hints、快捷键徽标和键盘可访问的上下文菜单。鼠标和触控流程继续保留。

**吸收点**：Quick Switcher++ 的 `+` 工作区、`>` 命令、`~` 相关内容和 Quick Filters；PowerToys/Flow 的键盘链路；GitHub Command Palette 的上下文建议。

**成功标准**：熟练用户可以只用键盘完成搜索、选择、打开、切换工作区和执行动作。

### D11｜密度、布局和皮肤成为可组合系统（P1）

在当前融合模式和可选皮肤基础上，继续提供紧凑/舒适密度、面板布局配置、桌面/侧栏/手机独立显示策略，以及对比度、焦点、reduced-motion 和 44px 触控的统一门禁。

**吸收点**：PowerToys 的紧凑搜索框和 Dock；Capacities 最近的统一页面、侧栏和快捷菜单改版；本项目 ADR 0073 已确定作用域变量皮肤方案。

**边界**：不做主题编辑器、不把 CSS 配置暴露成无边界的用户脚本、不破坏思源主题融合。

### D12｜索引、宿主和动作健康中心（P0/P1）

为搜索索引、宿主 API、第三方动作、同步状态和缓存增加轻量诊断：最后更新时间、失败原因、重建入口、降级状态、耗时预算和数据来源。用户不需要看日志才能知道为什么某个结果或动作不可用。

**吸收点**：Omnisearch 的缓存清理、索引更新和大文件/移动端降级；思源 sync-aware 插件的设备状态感知；PowerToys 的扩展发现和管理。

**成功标准**：失败是可解释、可恢复、可测试的状态，而不是空白列表或无响应按钮。

### D13｜外部捕获、深链接和剪贴板入口（P1/P2）

支持从浏览器、系统剪贴板、思源分享链接和外部启动器进入“快速记录/打开指定文档/加入当前工作区”。优先做本地 deep link 和剪贴板，不先做云端收件箱。

**吸收点**：Raycast Quicklinks、Alfred Universal Actions、Capacities 的 WhatsApp/Telegram/邮件/Web Extension 快速捕获。

**边界**：所有外部输入都要经过 URL/文本消毒、来源标记和用户确认；不把远程服务凭据放入插件数据。

### D14｜受控 Agent 与语义检索（P2）

让 Agent 帮用户解释当前工作现场、推荐已有文档或生成搜索条件，但默认只读，输出必须带来源和范围；写入、批量操作和跨文档动作继续走审批链。

**吸收点**：Heptabase 的空间搜索、关键词/语义搜索、当前页面上下文和明确的搜索开关；思源主页插件的知识工作台和 Agent 工具。

**进入条件**：先完成 D2 的检索质量、D12 的诊断和真实宿主能力矩阵，再决定是否扩大 Agent 默认入口。

### D15｜跨设备连续性与可迁移配置（P2）

把工作区快照、动作目录、皮肤、动态组和恢复记录设计成可导出、可导入、可冲突解释的版本化包。跨设备同步可以先通过思源已有同步和显式导入导出实现，不另建云端账户体系。

**吸收点**：Workona 的跨设备空间恢复、快照和冲突应用；思源 Bazaar 的版本化包发布与校验机制。

**成功标准**：配置和工作区可以迁移，失败时保留旧配置，不出现静默覆盖。

## 4. 建议的路线分层

### 第一阶段：导航可靠性和移动证据

先完成真实桌面/Android 验收、移动侧滑所有权、D1 统一结果编排、D2 排序诊断和 D12 健康状态。这一阶段的目标是让现有能力可靠、可解释、可测量。

### 第二阶段：工作上下文连续性

推进 D3 关联内容、D4 工作区恢复 2.0、D8 预览和 D9 动态收藏组。目标是从“打开一个文档”升级为“回到一段工作上下文”。

### 第三阶段：动作和生态

推进 D5 快速捕获、D6 提供方协议、D10 键盘入口、D13 深链接。目标是让动作可组合、可发现、可恢复，并让第三方插件安全接入。

### 第四阶段：表面和个性化

推进 D7 移动一等表面、D11 密度/布局/皮肤、D15 可迁移配置。目标是让三端都稳定，同时允许用户形成自己的使用方式。

### 第五阶段：受控智能

最后评估 D14 Agent/语义检索。只有当检索质量、来源解释、权限边界和真实宿主证据都足够稳定，才扩展默认入口。

## 5. 暂不建议吸收的方向

- 把插件扩展成主页、统计大屏或组件市场；这会直接偏离“导航器”定位。
- 复制 GPL 插件代码或把竞品 DOM/样式带入本仓库；只吸收交互思想，逐项核对许可。
- 任意 SQL、任意 JavaScript、脚本权限和模拟点击；它们会破坏能力边界和安全回执。
- 系统级跨应用悬浮窗、截屏/录屏、分屏管理和背面敲击；当前思源插件宿主不稳定支持这些能力。
- 在没有真实使用数据前直接引入 frecency、复杂语义索引或大体积依赖；先用可解释的最近度、标题权重和有界查询验证价值。

## 6. 建议的决策顺序

如果现在只选择三件事，建议是：

1. **D1 + D2**：把切换器变成真正统一、快速、可解释的导航入口；
