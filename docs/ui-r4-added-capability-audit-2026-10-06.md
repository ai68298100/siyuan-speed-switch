# R4 原型与生产新增能力对账

日期：2026-10-06
范围：`docs/design/platform-ui-redesign-r4-2026-10-03.html`、`docs/ui-redesign-r4-2026-10-03.md` 与当前生产入口。

这次对账区分“功能不存在”和“原型没有把已有功能画完整”。R4 的一级信息架构仍然成立：切换器、工作台、片段实验室、设置和悬浮球；组件商店与片段商店继续是对应表面内的二级流程。需要调整的是新增能力在视觉层级中的位置，避免低频治理动作抢占主流程。

## 本轮适配

- 片段实验室头部从五个并列动作收敛为状态 + “更多” + 返回；备份/恢复/撤销恢复仍可达，但不会压过 R4 原型中的主流程。
- “更多”菜单、元数据折叠区和 Gist 折叠区复用同一套描边、圆角、焦点环和浮层阴影；窄屏时数据菜单改为底部浮层，避免超出右缘。
- 切换器命令模式和保存搜索只增加局部状态提示，保持原有搜索、回放、右键删除和命令执行逻辑不变。
- 58 项组件/provider 生态不通过伪造更多首页卡片解决；来源、就绪条件和 unavailable 状态应进入组件商店/工作台的二级卡片，避免把静态 R4 示例误读为真实组件总数。

## 结论

没有发现需要新增一级表面或改写功能逻辑的能力。真正晚于 R4 的主要是 Gist 和片段目录元数据；其余是 R4 规范已概念性覆盖、配套 HTML 没有画全的状态。调整重点应继续是二级入口、状态和优先级，而不是增加导航项。
