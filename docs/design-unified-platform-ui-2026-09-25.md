# T-6866 统一切换平台 UI、功能与交互设计（2026-09-25）

> 本轮是产品和交互设计，不修改生产代码。目标是把第一面板、第二面板、片段实验室和悬浮球组织成同一个插件的四个工作入口：有一个平台外壳、一套对象和动作语义、一套状态语言，以及按工作类型变化的内容区。

## 1. 先确定产品主语

### 1.1 正式定位

**小驴雷切：思源笔记的统一切换与工作上下文平台。**

面向用户的一句话说明：

> 在一个入口里切换内容、工作台和片段工具，并保留当前的工作上下文。

更短的产品叙事是：**一个入口，切换内容；一个工作台，切换现场；一个实验室，切换界面。**

“各种各样切换的总平台”可以作为宣传或口头表达；产品界面需要把用户正在切换的对象说清楚。插件提供的是一套连续的工作流：

```text
找到要去的地方  →  看当前需要的信息  →  编辑或验证一个工具能力
      切换器             工作台                 片段实验室
```

悬浮球不作为第四个面板。它是从任意宿主位置进入这套平台的**全局触发器**，也负责执行高频动作。

### 1.2 三个表面的命名

| 当前称呼 | 对外称呼 | 用户要完成的事 | 主表面 | 核心结果 |
| --- | --- | --- | --- | --- |
| 第一面板、页签面板 | **切换器** | 找到并回到内容、动作或工作现场 | `切换` | 选中后打开、定位或执行 |
| 第二面板、组件面板 | **工作台** | 查看、刷新和编排信息组件 | `工作台` | 读懂状态、配置布局、恢复现场 |
| 第三面板、代码片段实验室 | **片段实验室** | 管理、编辑和安全预览片段 | `实验室` | 修改草稿、预览、审核后保存 |
| 悬浮球 | **平台入口** | 在宿主任意位置快速呼出平台或动作 | `打开小驴雷切` | 打开平台、执行动作、恢复来源 |

“实验室”是能力名称，不代表另一套视觉系统。`实验`状态只用于能力或安全边界提示，不能成为第三面板的主视觉。

## 2. 第一性原理：统一什么，保留什么

三个面板看起来统一，必须先统一用户心智中的四件事：

1. **我在哪里**：当前表面、当前工作现场、当前对象通过同一条上下文栏表达。
2. **我能做什么**：主动作、次动作、更多动作使用同一套动作行和 Action Panel。
3. **现在发生了什么**：加载、就绪、缓存、过期、未保存、阻塞、错误使用同一套状态徽标和回执。
4. **怎样回去**：平台内部使用同一条返回栈，关闭后恢复触发来源和焦点。

应当保留的差异是每个表面的工作方式：

| 表面 | 不应被统一掉的部分 |
| --- | --- |
| 切换器 | 搜索框应首屏聚焦，内容结果的键盘导航和预览密度优先 |
| 工作台 | 网格、卡片尺寸、拖动和编辑布局是核心，不应变成结果列表 |
| 片段实验室 | 编辑器、预览、冲突保护和 AI 审核是核心，不应变成普通卡片画廊 |
| 悬浮球 | 小点击目标、拖动分流、触控防误触和 safe-area 是核心，不应变成常驻面板 |

因此统一的对象是**平台骨架和交互合同**，不是把所有内容强行做成同一种卡片。

### 2.1 当前为什么会像三个产品

现状已经有不少可复用能力，但它们没有落在同一个外壳上：

- 第一面板有 `sw__main → sw__dock + sw__content`、工具栏、零查询工作台和 `sw__workbench-dock`；它实际上已经具备平台首页和上下文入口的雏形。
- 第一面板的 `sw__workbench-dock` 位于滚动区之外，适合升级成三个表面都能看到的“当前工作现场”条；目前工作台和片段实验室没有对应的 context strip。
- 第二面板以独立的 `speed-switch sw-home` Dialog 装配 `sw-home__bar`、问候、网格和商店，根节点没有第一面板的 `sw__body`/平台头部，因此相同的 toolbar 规则不能自然复用。
- 悬浮球已经复用 quick-action registry/executor 和能力状态，但“更多”仍主要按 provider 分组，用户不一定能看出“进入平台、打开工作台、运行工具”的层次。
- 片段实验室从 `index.ts` 的第一面板桌面工具栏单独打开，使用独立 Dialog、动态 chunk、`sw-studio__*` BEM 和 `--studio-*` token；它没有第二面板或悬浮球的同级入口，也没有跨表面面包屑。

所以首要问题是**入口、外壳和状态协议断裂**，不是继续增加色值或装饰。统一设计应先让这些边界对齐，再处理表面内部的排版细节。

## 3. 统一平台外壳

### 3.1 外壳结构

桌面端的三个表面进入同一个 `PlatformShell`。首期可以继续使用思源 Dialog 承载，只把公共头部、导航、上下文和路由状态提取出来，不要求一次性改成完整 SPA。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 小驴雷切   [切换] [工作台] [实验室]       当前现场  ⋯  状态  关闭 │  ← platform header
├────────────────────────────────────────────────────────────────────┤
│ 平台 / 当前表面 / 当前对象                 返回来源  ⌘K 动作       │  ← context bar
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│                       surface body                                │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 状态回执/快捷键提示                                      保存/完成 │  ← optional footer
└────────────────────────────────────────────────────────────────────┘
```

公共区只有三层：

- **Platform header**：品牌、三个表面导航、当前工作现场、全局动作和关闭。
- **Context bar**：面包屑、选中对象、返回来源、能力/网络/隐私状态。
- **Surface body**：各表面自己的主内容；不能把表面专属工具塞进平台头部。

首屏打开切换器时，搜索输入框仍然是第一焦点；打开工作台或实验室时，焦点进入对应表面的第一主控件。平台导航首期使用点击、Tab 和方向键；`Alt+1/2/3` 只作为候选快捷键，须先核对思源和用户快捷键冲突后再定稿。当前表面用文字、图标和下划线同时表达。

### 3.2 入口和路由

```ts
type SurfaceId = "switcher" | "workbench" | "studio";

interface PlatformRoute {
  surface: SurfaceId;
  objectId?: string;
  returnTo?: { surface: SurfaceId; focusId?: string };
  dirty?: boolean;
}

interface PlatformSession {
  lastSurface: SurfaceId;
  workspaceId?: string;
  routeStack: PlatformRoute[];
  surfaceState: Record<SurfaceId, unknown>;
}
```

路由只描述当前表面和返回关系，表面内部状态仍由自己的模型管理。切换表面不能销毁未保存的工作室草稿，也不能让工作台布局编辑状态丢失；关闭平台时只保存会话内的返回焦点和表面状态。

行为约定：

| 触发 | 结果 |
| --- | --- |
| 悬浮球轻触 | 打开平台并恢复上次表面；无可恢复状态时进入“切换” |
| 第一面板工具栏的“工作台/实验室” | 在同一外壳内切换表面，保留 `returnTo` |
| 第二面板卡片动作 | 进入切换器或片段实验室时带上对象 ID，回退后恢复卡片焦点 |
| 片段目录的“在切换器中查找” | 回到切换器并把片段作为选中结果，主动作是“在实验室打开” |
| Escape | 先关闭 Action Panel/选择器，再退回路由；有脏草稿时走统一确认 |
| 关闭平台 | 返回触发平台的宿主焦点；无法恢复时回到宿主当前编辑器 |

移动端继续使用全屏或底部表面容器，外壳头部改为横向可滚动的表面标签和返回按钮；不把桌面三栏硬缩成手机三栏。片段实验室当前仍遵守 ADR 0078 的桌面入口边界：移动端暂不提供可编辑入口。若未来需要显示第三项导航，只能作为“桌面可用”的能力状态，不能伪装成已经支持移动编辑。

## 4. 三个表面的共同构图

三面板都采用“来源/导航 → 主工作区 → 上下文/动作”的构图，只是每一列的内容不同：

| 区域 | 切换器 | 工作台 | 片段实验室 |
| --- | --- | --- | --- |
| 左侧来源 | 搜索范围、结果分组、已开页签 | 已安装组件、组件商店分组 | 片段目录、来源/类型筛选 |
| 中间主区 | 结果列表和文档预览 | 组件网格、编辑落点 | 代码编辑器、代码属性 |
| 右侧上下文 | 预览、行级动作 | 组件配置、健康状态、商店详情 | CSS/HTML 预览、AI 审核、冲突 diff |
| 底部回执 | 结果数量、来源、快捷键 | 布局草稿、刷新和失败回执 | 未保存、预览状态、保存/导出结果 |

这套构图让用户在三个表面中都能预测“左边找对象，中间处理对象，右边查看上下文”。

### 4.1 切换器设计

切换器的视觉重心仍是搜索，不新增大型首页横幅。建议调整为：

1. 平台头部下直接放搜索框和范围芯片：`全部 / 内容 / 动作 / 工作现场 / 组件 / 片段`；空查询仍优先最近、固定和当前现场。
2. 结果按对象类型分区，明确显示“打开”“执行”“恢复”“在实验室编辑”等主动作，不再只靠来源小字猜含义。
3. 右侧预览沿用现有文档预览，但改用平台 `PreviewFrame`、`StatusBadge` 和 `ActionRow`；窄侧栏按现有规则隐藏或降级。
4. 搜索得到片段时显示 `片段` 类型、启用状态、来源和字节/行数摘要；Enter 打开片段实验室，`Ctrl/Cmd+Enter` 执行安全的次动作（如导出或复制）时才启用。
5. 继续保留 `>` 命令模式。命令结果与内容结果共享搜索会话、状态和动作面板，不另建执行器。

### 4.2 工作台设计

工作台不再被称作“主页”。

- 头部第一行是 `查看 / 编辑布局` 状态切换，旁边显示当前现场和“刷新全部”。
- 查看态以网格为主，卡片只显示标题、来源、更新时间/缓存年龄、健康状态和一个主动作。
- 编辑态显示明确的“正在编辑布局”横幅、拖动落点、撤销一步和恢复默认；移动端使用上移/下移按钮，不依赖拖动。
- 组件商店作为同一表面里的侧面板或路由子页，沿用 `可用 / 已添加 / 需安装 / 不可用` 状态芯片，不再像另一套产品。
- 组件配置侧面板使用与片段属性面板相同的表单、分组、底部操作条和变化回执。
- 工作台进入片段实验室时通过卡片 Action Panel 完成，不能依赖隐藏的图标按钮。

### 4.3 片段实验室设计

当前工作室的 `--studio-*` 变量、实验性大徽标、独立 footer 和独立选择器使它像一套外部工具。统一方案保留安全边界，重排视觉层级：

```text
┌────────────┬─────────────────────────────┬───────────────────┐
│ 片段目录   │ 代码编辑区                  │ 预览 / AI / 属性   │
│ 搜索/筛选  │ CSS/JS + 当前草稿状态        │ 预览为主，AI 可折叠 │
│ 来源/类型  │ 保存、另存为、导出、冲突提示  │ diff/说明/能力提示  │
└────────────┴─────────────────────────────┴───────────────────┘
```

具体规则：

- 片段目录从嵌套选择器升级为可折叠左栏；窄屏再退回选择器，不要求手机同时显示三栏。
- 中间以编辑器为主，名称、类型、启用、发布禁用等属性放在同一表面右栏的“属性”折叠组中。
- 右栏默认显示 CSS 隔离预览；AI 作为同一右栏的 `预览 / AI / 属性` 标签，不再拥有独立的颜色、边框和页眉。
- 预览、代码、AI 请求和宿主保存都使用平台状态徽标：`就绪 / 加载中 / 草稿 / 未保存 / 被阻塞 / 错误`。
- 片段目录的筛选、来源、类型和当前项状态沿用工作台商店的 `SourceChip`/筛选行语义，不再保留一套独立的选择器外观。
- 片段的保存、预览、启用和“发布时禁用”是相互独立的维度，显示为组合信息（例如“已保存 · 已启用 · 发布时禁用”并附“预览就绪”），不把它们画成自动推进的单一流水线。
- “实验性”降为能力提示，放在片段类型或安全说明附近；标题直接叫“片段实验室”。
- 保存、另存为、导出、删除、启用和投稿都进入统一 Action Panel；破坏性操作必须显示副作用和恢复路径。
- 当前 `openSnippetStudio()` 使用 `disableClose` 和返回前脏稿检查；迁移到平台路由后，Dialog 的关闭/销毁回调必须先经过同一个 `DirtyGuard`，不能因为换了外壳而绕过保护。
- 继续禁止任意 JavaScript 同步执行。JS 行显示 `管理/导出可用，运行预览受安全边界限制`，禁用原因可展开；不能用 Worker 冒充完整宿主预览。
- AI 结果默认是“待审核草稿”，必须手动接受。接受前显示变更摘要，接受后仍标记为未保存，避免把生成等同于写入宿主。
- 冲突时右栏切换到 diff/另存为状态，保留当前草稿和外部版本，不用错误 toast 覆盖用户正在编辑的内容。

## 5. 统一视觉语言

### 5.1 Token 原则

现有切换器和工作台已大量复用 `--b3-*` 宿主变量；片段工作室另外定义 `--studio-*`。迁移时建立平台 token 别名，让宿主主题仍是唯一颜色来源：

```scss
.sw-platform-shell {
  --sw-platform-accent: var(--b3-theme-primary, #8576e8);
  --sw-platform-accent-soft: color-mix(in srgb, var(--sw-platform-accent) 12%, transparent);
  --sw-platform-bg: var(--b3-theme-background);
  --sw-platform-surface: var(--b3-theme-surface);
  --sw-platform-surface-muted: var(--b3-theme-surface-lighter, var(--sw-platform-surface));
  --sw-platform-line: var(--b3-border-color);
  --sw-platform-text: var(--b3-theme-on-background);
  --sw-platform-text-muted: var(--b3-theme-on-surface-light);
  --sw-platform-focus: var(--sw-focus-ring);
}
```

`--studio-*` 在过渡期可以作为兼容别名，但不再增加新的 studio-only 颜色、圆角或阴影。片段现有径向渐变应降为平台外壳的轻微 accent wash，表面主体使用相同的背景和边框层级。

### 5.2 视觉刻度

| 项目 | 平台刻度 | 说明 |
| --- | --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 | 控件内部、卡片、区块、外壳边距统一取刻度 |
| 圆角 | 8 / 12 / 16 | 控件、卡片、外壳；不再由工作室单独使用 11/13 等近似值 |
| 层级 | line / surface / elevated | 只用边框、背景和有限阴影表达层级 |
| 动效 | 120 / 160 / 200 / 260ms | 沿用 `00-tokens.scss` 的四档和减动效规则 |
| 状态 | ready / loading / stale / dirty / blocked / error | 颜色、图标、文字三者至少有两种同时出现 |
| 触控 | 普通按钮最小 44px，桌面密集控件不影响焦点环 | 触控命中区与视觉大小分开控制 |

### 5.3 共享组件名

后续实现应优先建立这些平台级原语，三面板只组合，不复制：

`PlatformShell`、`PlatformHeader`、`SurfaceNav`、`ContextBar`、`StatusBadge`、`SourceChip`、`CapabilityRow`、`ActionRow`、`ActionPanel`、`PreviewFrame`、`EmptyState`、`LoadingState`、`ErrorState`、`DirtyGuard`、`FooterReceipt`。

这些是视觉和行为原语，不是要求一次性把现有文件重写成同一组件框架。第一阶段可以用 DOM 适配器包住已有节点。

## 6. 统一对象、动作和状态

### 6.1 对象和表面分开

表面是用户进入的工作区域，对象是搜索、工作台和实验室里被操作的目标。两者不能混成一个枚举：

```ts
type SurfaceId = "switcher" | "workbench" | "studio";
type PlatformObjectKind = "content" | "action" | "workspace" | "widget" | "snippet";

interface PlatformObjectDescriptor {
  id: string;
  kind: PlatformObjectKind;
  title: string;
  subtitle?: string;
  source: string;
  status: "ready" | "loading" | "stale" | "dirty" | "blocked" | "error";
  capabilities: string[];
  sideEffect: "none" | "navigation" | "localWrite" | "external";
  surfaces: SurfaceId[];
}
```

展示注册表只提供有界描述；真正的执行继续走现有 quick-action registry、宿主适配器和组件 runtime。未知来源必须可见并显示能力状态，不能因为图标或元数据缺失而把对象从平台中删掉。

### 6.2 状态和回执

三面板共享以下状态文案和动作：

对象描述中的 `status` 是用于列表排序和首要徽标的摘要；片段实验室、组件卡和工作台布局可以在摘要旁展示独立的状态维度，不能因为摘要只有一个值就丢掉 `dirty`、`preview`、`enabled`、`disabledInPublish` 或缓存年龄。

| 状态 | 统一表达 | 默认可用动作 |
| --- | --- | --- |
| loading | 加载中 + 骨架 | 取消（若存在请求） |
| ready | 已就绪/已更新 | 打开、编辑或查看 |
| cached/stale | 缓存于时间 + 过期提示 | 刷新、查看缓存 |
| dirty | 未保存更改 | 保存、另存为、放弃 |
| blocked | 受能力/端侧/安全限制 | 查看原因、换入口 |
| error | 失败原因码/人类可读原因 | 重试、回退、复制诊断 |

所有异步请求都必须有取消、代际校验和销毁清理。失败回执留在产生它的卡片、结果行或右栏，不用全局 toast 取代上下文。

### 6.3 跨表面动作（P3 规划）

以下是统一后的目标动作，当前仓库尚未全部实现，接入时必须由对象索引和平台动作描述提供能力状态：

首批只接入能复用现有能力的动作：

- 切换器结果中的片段 → `在实验室打开`；
- 工作台组件 Action Panel → `回到切换器`、`打开相关文档`或`在实验室编辑片段`；
- 片段实验室 → `在切换器中查找引用`、`返回工作台`；
- 悬浮球 → `打开平台`、`打开工作台`、`打开片段实验室`（端侧能力允许时）和已有快捷动作；
- 保存/刷新/导出完成后 → 统一 footer 回执，并恢复触发来源焦点。

首个跨表面动作只注册安全的 `openSnippetStudio` 导航动作，声明 `surfaces=desktop`、`sideEffect=navigation` 和 `fallback=switcher`；先不要把每一条 CSS/JS 片段塞进 quick-action 目录。

不把“固定、收藏、最近、首层、场景绑定”压成一个排序字段；它们仍然是不同关系，只在统一 Action Panel 中以清楚的操作表达。

## 7. 悬浮球的统一角色

悬浮球视觉上只保留平台品牌和当前状态，不给每个面板做一套球：

1. 轻触：进入 `PlatformShell` 的上次表面；失效时回退到切换器。
2. 长按或拖动：显示有限的首层动作槽；槽内可以有三个表面入口，但首层不展示完整目录。
3. 更多：打开与平台 Action Panel 相同的动作目录、搜索、分组、能力和失败状态。
4. 从平台执行动作后：成功回到来源表面，失败留在当前表面并给出重试/回退。
5. 移动端继续遵守 touch slop、safe-area、上滑分流、滚动隐藏和真实 Android 验收要求；浏览器响应式不能代替真机证据。

悬浮球的系统级回退入口“打开小驴雷切”不可被用户配置删除。自定义主点击可以覆盖默认动作，但动作失效时必须自动回退到平台，而不是出现无响应的球。

## 8. 实施顺序和边界

### P0：冻结设计合同（本任务）

- 定位、命名、外壳、表面关系、对象/动作/状态模型写入设计文档和 ADR。
- 确认片段实验室继续遵守 ADR 0078 的原生列表、安全预览、手动 AI 接受和桌面入口边界。

### P1：平台级视觉原语

- 增加平台 token 和公共 class；为现有第一/第二/第三面板写适配层。
- 先改头部、状态徽标、动作行、预览框、空/错/加载态，不碰搜索和组件业务逻辑。
- 保留旧 class 作为过渡别名，完成桌面、侧栏、窄屏主题截图后再删除重复样式。

### P2：共享外壳和表面导航

- 让第一、第二、第三面板由同一 `PlatformShell` 装配，先保留现有 Dialog 和动态 chunk。
- 加入路由栈、返回来源、焦点恢复、脏草稿守卫和关闭回执。
- 第一面板工具栏、工作台入口、片段入口和悬浮球都走同一 surface action。

### P3：跨表面对象和动作

- 将片段目录、组件卡、内容结果投影为统一对象描述。
- 第一面板增加片段/组件/工作现场的类型分区；Action Panel 复用同一执行和回执管线。
- 从工作台和片段实验室返回时恢复查询、卡片焦点、目录筛选和滚动位置。

### P4：真实宿主验收

- 桌面：宽弹窗、最窄侧栏、明暗主题、宿主菜单层级、AI/片段真实回包。
- 移动端：第一/第二面板和悬浮球实机；片段实验室先验证能力状态和隐藏策略，不在没有证据时开放编辑。
- 每一阶段独立门禁；涉及门禁或契约测试时按 `docs/gate-audit-checklist.md` 做违规注入的负向验证。

### 不做

- 不一次性重写 `src/index.ts`，不把现有实现强行改成新框架。
- 不把第一面板变成完整文件树或第二套全文搜索，不把工作台变成泛化主页。
- 不让片段实验室执行任意 JavaScript，不伪造 AI 能力探测或远程投稿服务。
- 不用统一外壳掩盖端侧能力差异；没有真实 Android/SiYuan 证据就不宣称移动片段编辑可用。

## 9. 评审验收矩阵

| 维度 | 通过条件 |
| --- | --- |
| 统一感 | 三个表面共享品牌、表面导航、上下文栏、状态徽标、动作行、焦点环和动效刻度；片段不再出现独立的颜色体系 |
| 可理解性 | 用户能从标题、类型、主动作和状态看懂“这是打开、查看、执行、编辑还是恢复” |
| 连续性 | 面板之间切换保留当前对象、筛选、滚动和返回来源；脏草稿和布局编辑不会丢失 |
| 键盘 | 搜索/结果、网格、编辑器、目录和 Action Panel 的 Enter、方向键、Escape、Tab、保存语义无冲突 |
| 触控 | 普通按钮 44px 命中区；浮球手势和移动面板不阻塞宿主滑动；真实 Android 结果单独记录 |
| 安全 | JS 运行能力仍明确受限；AI 只产生待审核草稿；片段保存有冲突、另存为和回读回执 |
| 性能 | 打开切换器不等待远程请求；片段工作室继续动态加载；路由切换不重复安装全局监听 |
| 主题 | 明暗、宿主主题变量和 reduced-motion 下三面板仍使用同一层级和焦点对比度 |

## 10. 本轮结论

统一设计的核心不是给三个弹窗涂同一种颜色，而是让它们成为同一条工作路径的三个表面：**切换器负责“去哪儿”，工作台负责“看什么”，片段实验室负责“改什么和验证什么”，悬浮球负责“从哪里进入”。**

下一步先实现平台 token、公共原语和外壳适配，再把片段工作室迁入同一结构；功能扩展要服从这套对象、动作、状态和上下文合同。
