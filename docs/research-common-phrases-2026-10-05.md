## 结论

这个方向值得做，产品命名为**小驴常用**，定位为基于思源文档和块的常用内容快速调用器，而不是独立的文本剪贴板或密码管理器。

推荐采用：

1. 单独开发一个“**小驴常用**”插件，负责内容库、搜索、复制、插入、来源回链和媒体处理。
2. 以思源文档/块作为内容唯一来源；插件自己的数据只保存内容库范围、最近使用、收藏和界面偏好等侧车元数据。
3. 小驴雷切只做可选的发现和快捷入口，通过已有 `registerQuickAction`/provider registry 接入；不把完整的常用内容管理器并入切换器首屏。

这样既吸收 Quicker 的实时搜索、标签/文件夹、连续调用和混合内容能力，也保留小驴雷切“统一切换与工作上下文平台”的边界。

## 参考动作带来的产品启发

Quicker 页面把常用语定位为本地内容库，覆盖短语、模板、电话、地址、文本、代码、网址、图片、链接和附件，并支持实时搜索、拼音模糊搜索、标签/文件夹、批量复制、连续发送和本地编辑。

对思源来说，真正有价值的是“任意常用内容快速找到并调用”这条工作路径：

- 搜索标题、正文、标签、别名和类型；
- 一次操作复制到系统剪贴板；
- 在当前思源编辑器插入；
- 打开原文档或定位原块，保留可追溯性；
- 从当前选区、当前块或剪贴板反向保存为常用内容。

“发送到任意应用”不能作为思源插件的默认承诺。浏览器/WebView 只能可靠地复制，跨应用粘贴仍由用户完成；思源内部的插入可以由宿主编辑器 API 负责。

## 为什么不直接并入小驴雷切

小驴雷切已经有三端切换器、共享快捷动作 registry、快速捕获、模板插入和剪贴板入口。现有能力足以承载一个“打开常用内容插件”的动作，但不适合继续承载完整的内容库管理：

- 切换器首屏的职责是找到并打开内容；把编辑器、标签管理、媒体预览和批量操作放进去会挤压导航路径。
- 常用内容需要独立的数据生命周期、来源文档配置、资源失效处理和移动端编辑器适配，和代码片段实验室也不是同一内容域。
- 独立插件可以单独安装、迭代和停用；雷切只保存可序列化的 provider/action 元数据，提供方卸载后已有入口能够安全降级。

若只做一个极简的“保存/复制几条文本”，可以先作为雷切的局部动作；一旦加入图片、附件、块结构、来源回链和编辑，应该拆成独立插件。

## 与思源的深度融合方案

### 数据来源

- 用户选择一个笔记本、文档或文档树作为“常用内容库”；每条内容对应稳定的文档根 ID 或块 ID。
- 分类优先复用文档树和思源标签，不新建第二套文件夹/标签真源。
- 收藏、最近使用、排序、内容库入口等属于插件侧车元数据；内容正文、资源引用和块结构仍由思源保存和同步。
- 内容库中的条目失效时保留一个可恢复的“来源失效”状态，不静默删除；用户可以重新绑定或移除。

首版不依赖自建全文索引，也不把完整正文复制进插件数据。搜索优先走思源已有检索/文档读取能力，在配置范围内做有界投影；临时结果只放内存缓存。

### 内容类型与动作

| 类型 | 思源保存方式 | 首版动作 | 说明 |
| --- | --- | --- | --- |
| 纯文本/富文本 | 段落、列表、引用等块 | 复制纯文本、插入块结构、打开来源 | 插入时保留 Markdown/HTML 语义，明确当前模式 |
| 网址/链接 | 链接块或带 URL 的段落 | 打开网址、复制 URL、插入链接 | 不把外链正文抓取到插件本地 |
| 代码 | 代码块 | 复制代码、插入代码块、打开来源 | 语言信息跟随代码块 |
| 图片 | 图片块 + 思源资源 | 插入图片块、打开来源、复制可用引用 | 不承诺 WebView 一定能把二进制图片写入系统剪贴板 |
| 附件 | 文件/资源块 | 插入附件块、打开资源、复制资源引用 | 资源失效时显示明确错误 |
| 块/文档模板 | 根块或文档子树 | 以块结构插入、打开来源 | 需要保留 ID 映射和嵌套结构边界 |

“密码”可以作为用户自行存入的普通内容，但产品不应把它宣传为密码管理器，也不应默认提供明文导出、跨应用自动发送或凭据同步能力。

### 两种调用模式

1. **复制**：适合浏览器、聊天软件、终端等外部场景。复制失败要有回执，不能假报成功。
2. **插入当前文档**：优先使用思源活动编辑器的官方插入能力；没有活动编辑器、宿主 API 不可用或移动端行为未经验证时，显示“仅支持复制/打开来源”的能力状态。

两种模式必须独立声明能力。图片、附件和块结构不能因为系统剪贴板不可用就被误判为内容不存在。

## 推荐的 MVP

### 第一期：文本与网址

- 配置一个常用内容根文档/文档树；
- 搜索标题、标签、正文摘要和类型；
- 复制纯文本/URL；
- 插入当前思源编辑器；
- 打开来源文档/块；
- 当前选区或剪贴板文本保存为新条目；
- 最近使用、收藏和失效来源提示。

### 第二期：块结构与媒体

- 复制/插入列表、引用、代码、任务等块结构；
- 复用思源资源路径插入图片和附件；
- 处理资源不存在、文档删除、同步冲突和移动端降级；
- 增加条目预览和来源回链。

### 第三期：雷切和生态接入

- 常用内容插件注册一个 `open` 快捷动作到小驴雷切；
- 可选注册“保存当前选区”“插入最近一条”等动作；
- 只通过 provider registry 传递可序列化 ID/value，不保存函数、不模拟 DOM 点击；
- 提供方卸载、禁用或版本不兼容时，雷切入口显示不可用并可恢复，不删除用户配置。

## 需要先验证的宿主问题

在写生产代码前，应单独取证以下合同：

1. 桌面和 Android 思源活动编辑器是否都能稳定获得，`protyle.insert` 对文本、HTML 和块结构的行为是否一致；
2. 图片/附件资源的创建、引用和失效检查是否有稳定的官方 API；
3. 选区读取、系统剪贴板读写在 Android WebView 的权限和失败表现；
4. 文档/块删除、同步和跨设备后，原 ID 是否能可靠判定失效；
5. 通过宿主搜索获取配置范围内结果时的上限、排序、取消和错误回退；
6. 移动端插入失败时是否能安全退化为复制或打开来源。

真实 Android 思源验收不能由桌面响应式、设备模拟或浏览器 mobile 模式替代。

## 成功标准

- 用户能在 1 次入口操作后搜索到文本/网址条目，并在 2 次操作内复制或插入；
- 在思源原文档中编辑条目后，常用内容列表能读到最新内容，不产生第二份正文；
- 来源文档/块始终可回链，失效来源有可理解的恢复路径；
- 文本、URL、图片、附件分别展示真实可用动作，失败不假报成功；
- 雷切卸载常用内容插件后不阻塞切换器，重载后入口和用户配置可恢复；
- 不引入自建全文索引、任意 SQL/JS 执行、云端账号服务或自动跨应用发送。

## 已确认的产品决策

用户已确认“**小驴常用独立插件 + 小驴雷切可选接入**”作为产品方向。独立插件先按完整功能开发，同时保留与小驴雷切、小驴打卡及其他小驴系列插件联动的版本化协议口子。
