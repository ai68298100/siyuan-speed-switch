# 组件面板 · 插件作者邀请与沟通手册（维护者内部文档）

> 本文档供小驴速切维护者使用，包含：
> 1. 邀请 issue 的标准流程与语气要点；
> 2. 通用邀请模板（完整版）；
> 3. 针对具体插件的定向草稿（task-horizon / docktomato / calendar / sireader 等）。
>
> **外发规则：任何 issue 必须经维护者确认后才能通过 `gh issue create` 发出。**

## 一、标准流程

1. **分析**：拿到目标插件链接后，用 `gh api repos/<owner>/<repo>/readme` 拉取 README，评估三件事——
   - 插件管理着什么数据（哪些数据适合做成面板组件）；
   - 数据面（有无公开命令、是否落在思源文档/属性里、还是私有 storage）；
   - 尺寸与交互适配（列表型 / 指标型 / 网格型）。
2. **出稿**：按下方通用模板生成定向草稿，填入「组件设想」「数据来源」「推荐型号」「代码示例」四项定制内容。
3. **确认**：草稿交维护者过目，经明确允许后用 `gh issue create -R <owner>/<repo> --title "..." --body-file <file>` 发出。
4. **跟进**：作者有任何协议诉求，回填到 `docs/widget-protocol.md` 的演进记录；接入完成后更新协议文档的「已知适配示例」。

## 二、语气要点（checklist）

- [ ] 先真诚赞赏对方插件（点名具体功能，不空泛）；
- [ ] 说明自己是小驴速切维护者、也是对方插件的用户；
- [ ] 讲清楚「为什么来找你」：数据互补，不是竞争；
- [ ] 强调接入成本很小（约 30 行、一次注册）、全部可选；
- [ ] 承诺平台承担超时/缓存/退避/渲染/配置表单，作者只写一个 read 函数；
- [ ] 明确「不接入也完全没问题」「协议按反馈演进」；
- [ ] 全文用「邀请 / 希望 / 如果方便」，不用「请务必 / 应该」；
- [ ] 结尾留沟通渠道（本 issue、思源社区、邮件均可）。

## 三、通用邀请模板（完整版）

**标题建议**：`[邀请] 小驴速切「组件面板」× {插件名}：把{数据能力}变成桌面小组件`

**正文**：

---

{作者称呼}你好！

先表达一下感谢——{插件名}的{具体功能点名，如"四象限任务视图 / 块绑定 / 历史记录"}一直是{我/我们}日常使用思源时最顺手的部分之一，看得出来在细节上花了很多心思。

冒昧打扰，是想代表另一个思源插件**「小驴速切 (LvSpeed Switch)」**向你发出一个接入邀请。

### 我们在做什么

小驴速切最初是一个页签快速切换器，现在逐步长成了一个**导航工作区**：除了切换器本体，我们还提供了一个「组件面板」——一个 iPad 式的小组件主页。用户可以把各种数据组件（最近打开、今日待办、日历、第三方插件数据……）自由添加到 12 列网格画布上，支持固定尺寸型号（迷你 2×3 到全幅 12×6 共 7 档）、拖拽布局、自动归位，桌面与手机端数据独立记忆。

组件商店对**所有插件作者开放**：只要按协议注册一个只读数据函数，插件就会出现在商店里，由用户自行添加到面板。

### 为什么找你

{插件名}管理着{数据描述}，这正是组件面板用户最希望"一打开就能看到"的信息。以我们对这个领域的理解，{插件名}的组件可以做成：

- **组件形态**：{形态描述，如"今日到期任务清单，大尺寸型号附带完成率汇总"}
- **尺寸建议**：{推荐型号，如"高 4×6（长列表）与全幅 12×6（看板式汇总）"}
- **点击行为**：{如"点击条目直达任务所在文档"}

### 接入方式（约 30 行代码）

在你的插件 `onload()` 里调用小驴速切的公开 API 即可：

```ts
const switcher = this.app.plugins.find((p) => p.name === "siyuan-speed-switch");
if (!switcher?.registerHomeModule) return; // 未安装时安静降级

const unregister = switcher.registerHomeModule({
    moduleId: "{插件前缀}-summary",       // 全局唯一
    title: "{组件标题}",
    icon: "iconCheck",                     // 思源图标 id
    category: "plugin",
    supportedDevices: ["desktop", "sidebar", "mobile"],
    sizes: ["medium", "large"],            // 支持的尺寸型号
    description: "{一句话描述}",
    read: async (config, device) => ({
        items: [
            {label: "{条目文本}", value: "{思源块 ID 或约定值}"},
        ],
    }),
    open: () => { /* 可选：读取失败时"打开插件" */ },
});

this.addUnload(() => unregister.unregister());
```

平台会替你处理**超时（800ms）、快照缓存（3s）、失败退避、条数截断、错误态与重试渲染**——你只需要尽快返回一个小体量数组。配置项可以用 `configSchema` 声明（面板自动渲染配置表单），自动刷新用 `refreshOn` 声明，条目点击支持思源块跳转或执行插件命令（`command: "插件名::命令key"`）。

完整接入指南（含全部字段说明与示例）：
https://github.com/ai68298100/siyuan-speed-switch/blob/main/docs/widget-protocol.md

- 不想接入、或暂时没时间，**完全没有关系**，这条 issue 不构成任何压力；
- 如果你更希望由我们直接提交接入 PR，也非常欢迎——把仓库开放给协作者或告知分支约定即可；

## 四、定向草稿

### 1. task-horizon（任务管理器）

- 仓库：https://github.com/5kyfkr/siyuan-plugin-task-horizon
- 设想组件：**「今日任务」**（高 4×6 / 全幅 12×6）——今日到期与逾期任务清单，条目点击直达任务所在文档；可选完成率汇总头。
- 数据面：任务聚合自多文档（块任务 + 自定义属性），有既有的跨插件查询经验（与底栏番茄钟的专注统计接口）。
- 定制点：`read` 返回今日/逾期任务清单；`refreshOn: ["switch-protyle", "loaded-protyle", "destroy-protyle"]`；`sizes: ["tall", "large", "full"]`；条目 `value` 用任务块 ID 即可跳转。
- 附加话题：协议 v2 的 `configSchema` 可让用户在面板里直接选择筛选条件（笔记本、四象限象限等），无需你再做面板侧设置。

### 2. docktomato（底栏番茄钟）

- 仓库：https://github.com/5kyfkr/siyuan-plugin-docktomato
- 设想组件：**「今日专注」**（迷你 2×3 / 小 4×3）——今日番茄数、专注分钟数，条目列出最近的专注记录；点击通过 `clickCommand` 或 `open` 打开计时。
- 数据面：专注记录有历史存储，且已对 Task Horizon 暴露统计查询接口——组件面板是这条数据链路的天然展示端。
- 定制点：`sizes: ["xs", "small"]`；`refreshOn` 暂不需要（计时结束由插件侧刷新或用户重开面板）。

### 3. calendar（日历面板）

- 仓库：https://github.com/gradypark86/siyuan-plugin-calendar
- 设想组件：**「日历」**（中 4×4 / 宽 8×3）——当月月历网格，点击日期创建/跳转对应周期笔记。
- 数据面：周期笔记通过文档属性定位，面板条目可返回块 ID 供跳转；月网格渲染超出当前协议的列表契约，**协议路线图已把"自定义视图类型"列为演进方向**，届时优先支持。
- 定制点：先行接入「近期周期笔记」列表组件（`sizes: ["medium", "wide"]`），月网格等自定义视图协议就绪后升级。

### 4. sireader（电子书阅读）

- 仓库：https://github.com/mm-o/siyuan-sireader
- 设想组件：**「最近阅读」**（小 4×3 / 中 4×4）——书名 + 阅读进度百分比，点击续读。
- 数据面：书架与进度在插件 storage 中；条目 `value` 若非思源块，可用 `open` 回调接管点击（面板会以"打开插件"兜底展示）。
- 定制点：`sizes: ["small", "medium"]`；建议返回最近 3~5 本，避免列表过长。
