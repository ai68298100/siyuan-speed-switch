# T-7168 五条主路径可用性任务脚本

日期：2026-10-06

任务：T-7168「五条主路径可用性与反馈闭环」
状态：脚本已准备，尚无真人反馈

本脚本用于在隔离工作区中观察新用户能否完成高频任务，以及失败、取消和回到现场时是否有可理解的恢复路径。它是走查工具，不是产品已通过的证明，也不替代真实宿主、Android、读屏或自动化验收。

相关依据：

- [当期开发计划](dev-plan-2026-10-06.md) 中 T-7168 的完成条件；
- [产品评审](product-review-2026-10-06.md) 第 8 节的五条主路径和记录要求；
- [README](../README.md) 中四个入口、搜索回退、收藏/最近关闭、文档集、片段实验室和组件商店的公开语义；
- [桌面验收记录模板](desktop-acceptance-template.md) 与 [验收流水边界](acceptance-log.md) 的脱敏规则。

## 1. 目标和边界

本轮观察以下问题：

1. 用户能否切换到目标文档；
2. 查找没有命中时，用户能否继续找到目标或理解下一步；
3. 用户能否把文档留作以后使用、关闭后再次找到；
4. 用户能否预览、执行或取消文档集恢复，并理解部分失败；
5. 用户能否修改片段后放弃改动，或安全保存并确认结果；
6. 用户第一次添加工作台组件时，是否能理解来源、可用条件和添加后的结果。

“成功”只表示本次任务达到脚本所列的结束状态，不表示产品整体易用，也不预测其他用户的表现。不要预设成功率、改善百分比、平均耗时或满意度目标；先保存原始观察，再由实际记录决定是否需要下一项工程任务。

真人反馈必须与脚本分开。没有参加者时，结论只能写“脚本已准备”或“未执行”，不能以演练、自动化测试、维护者判断或预期行为冒充用户反馈。

## 2. 参加者、环境和材料

### 2.1 参加者与同意

- 目标为 3～5 名此前没有使用过本插件，或仅进行过很短试用的参加者；人数是执行计划，不是通过门槛。
- 参加者编号使用 `P01`、`P02` 等，不记录姓名、账号、邮箱、联系方式或可识别的职业信息。
- 开始前说明：这是观察产品，不是考核人；可以跳过任何任务、随时停止；需要帮助时可以直接说；没有“正确操作步骤”。
- 录屏、录音或截图须另行取得同意。默认使用文字记录，不把含有文档正文、标题、路径、账号或令牌的媒体提交到仓库。
- 招募、联络和报酬不属于本文件；不要从仓库向外发送招募消息。

### 2.2 环境记录

每次仅记录足以复现差异的粗粒度信息：

- `SiYuan` 版本、插件版本或提交标识；
- 桌面/侧栏/手机端、操作系统类别、窗口缩放类别（例如“默认/高 DPI”）、明暗主题；
- 是否已认证（只写“已认证/未认证”），不要写令牌或认证响应；
- 任务开始前后是否发生重启、网络断开或宿主 API 明显失败。

真实桌面与移动设备证据仍按验收模板填写。浏览器模拟只能作为辅助观察，不能写成真机通过；片段实验室在移动端只观察能力边界提示，不把移动端伪装成可编辑实验室。

### 2.3 隔离夹具

使用一次性或可恢复的隔离工作区，避免触及参加者真实笔记。主持人在参加者到来前准备以下夹具，并把具体标题、正文和 ID 留在主持人手边，不写入记录：

- 至少 3 篇无敏感内容的练习文档，覆盖“已打开”“可搜索但未打开”和“故意无命中线索”三种状态；
- 一个已打开的目标文档，以及一条可用于收藏/关闭/再次打开的独立练习文档；需要测试最近关闭时，先在夹具中制造一条最近关闭记录；
- 一个包含 2～3 篇有效文档的已保存文档集；另准备一个含 1 个不可用项的副本，用于观察预览、缺失计数和部分恢复。不可用项由夹具造成，不记录真实路径；
- 一个可丢弃的 CSS 练习片段，默认不启用且不含脚本；需要保存和取消时各使用独立副本，或在每个分支之间恢复夹具；
- 工作台至少保留一个本地可用组件和一个需要配置、插件或外部服务的组件状态。不要预先告诉参加者哪个组件“应该”可用。

组件、文档集和片段夹具应能在任务后恢复。若宿主能力或环境与夹具不符，标记“未执行/环境不符”，不要临时编造成功状态。

## 3. 主持人规则

### 3.1 读题和中性提示

- 按任务卡逐字朗读参加者提示；不要先演示入口、控件、快捷键或术语。
- 任务卡中的尖括号内容由主持人替换为夹具线索；参加者记录中不写出真实标题或正文。
- 参加者问“该点哪里”时，先回答：“请按你认为最自然的方式继续，我只记录过程。”如果对方仍要求帮助，记录为直接帮助，并在任务结果中降低独立性等级。
- 参加者连续约 20 秒没有动作时，只能使用以下中性提示之一：“你接下来想尝试什么？”或“可以继续说出你正在找什么。”不得说“试试收藏/最近关闭/清除筛选/点击预览”等功能名。
- 发现将要改动真实数据、删除非夹具对象或暴露隐私时，立即停止该动作并切回隔离夹具；这类保护不算任务帮助，但要记录为环境事件。

### 3.2 计时和步骤

- 任务开始：主持人读完任务提示，参加者第一次操作时记 `t0`。
- 任务结束：达到成功标准、参加者主动停止、主持人因安全原因停止，或达到软性 5 分钟上限时记 `t1`。5 分钟只是避免单项占满会话，不是性能目标；超时仍保存实际耗时和停止原因。
- 记录相对耗时（例如 `02:14`），不必记录绝对时间；步骤写成动作类别（如“打开平台→输入查询→清除条件”），不要抄录正文或敏感搜索词。
- 误点、返回、取消、重试、换入口和向主持人求助都算恢复事件；不把参加者的犹豫或口头猜测直接判为失败。

### 3.3 结果等级

每个任务只选一个结果代码，并附一句证据：

| 代码 | 含义 |
| --- | --- |
| `I` | 独立完成：未接受功能提示，达到成功标准 |
| `N` | 中性提示后完成：只接受了 3.1 的中性提示 |
| `A` | 直接帮助后完成：主持人指出入口、控件或具体步骤 |
| `P` | 部分完成：达到部分结束状态，但仍有关键项未完成 |
| `F` | 未完成：在软性上限或参加者决定停止时仍未达到结束状态 |
| `X` | 参加者主动跳过或撤回，不评价能力 |
| `NA` | 因环境、夹具或设备条件未执行 |

`A`、`P`、`F`、`X`、`NA` 都是有效观察，不要为了凑成功数改写成 `I` 或 `N`。主持人帮助后仍可记录参加者最终动作和恢复方式，但必须保留帮助发生的事实。

## 4. 任务卡

### U1：切换到目标文档

**参加者提示**：

> 请在当前工作区找到并打开与“`<目标主题线索>`”有关的练习文档。请自己决定从哪里开始，完成后告诉我。

**夹具与结束状态**：目标文档已在一个页签或分栏中打开；参加者最终激活正确根文档。可以使用任何入口、鼠标或键盘，但主持人不先介绍入口。

**记录重点**：首次动作；是否先看已开页签；搜索、预览、分栏、数字直达或面板切换的选择；错误文档后的返回；焦点、滚动或表面是否丢失；达到目标所用相对时间和动作类别。

### U2：查找无命中后的继续完成

**准备**：在隔离切换器中预置一个故意无命中的查询或筛选状态，同时让目标文档处于已打开页签或可通过受限全文回退找到的状态。无命中词和目标标题只在主持人夹具表中保存。

**参加者提示**：

> 请找到与“`<目标主题线索>`”有关的练习文档并打开。当前界面保留了一些已有条件，请从这里继续，按你认为合适的方式完成。

**结束状态**：只有参加者打开目标文档才算完成；若无法继续，记录为 `P`、`F` 或 `X`，并另外记录其是否能指出可理解的下一步。若标题 API、全文或外部依赖在夹具中失败，保留实际失败状态；不得把错误状态改写成“没有这篇文档”。

**记录重点**：是否注意到无命中、是否清除/修改条件、是否回到已开页签或原生搜索出口；失败提示是否被理解；旧结果是否保留；参加者如何恢复以及恢复后是否验证了目标。

### U3：收藏或最近关闭后再次找到

本主路径分为两个可互换分支。为覆盖“收藏”和“最近关闭”两条语义，每位参加者原则上都完成两个分支，并在两个已重置的练习文档上交替顺序；如果会话时间或环境只允许一个分支，另一个标记为 `NA`，不要把未执行当成失败或成功。

**U3-A 参加者提示**：

> 这篇练习文档之后还会用到。请把它放到你认为适合以后快速找到的位置，关闭它，再把它重新打开。

**U3-B 参加者提示**：

> 请关闭这篇练习文档，然后把刚才关闭的那一篇重新打开。完成后告诉我。

**结束状态**：U3-A 要求文档被重新打开，并且参加者选择的“以后快速找到的位置”仍可用；U3-B 要求通过关闭后的历史或其他可理解路径重新打开正确根文档。主持人用夹具 ID 检查结果，不以参加者念出的标题作为证据。

**记录重点**：是否区分仍打开、最近打开和最近关闭；收藏分组、顺序和重复条目的理解；关闭后的回退路径；找错条目后的恢复；是否需要提示才能确认文档已重新打开。

### U4：恢复文档集

使用两个已经重置的分支，分别观察正常恢复和有缺失项时的判断。不要把“恢复前预览”或“取消”说成必经步骤，除非该分支的主持人指令明确要求观察它。

**U4-A 正常恢复提示**：

> 请把之前保存的这个工作区场景恢复到当前工作区。完成后告诉我。

**U4-B 缺失项提示**：

> 请把之前保存的这个工作区场景恢复到当前工作区；其中可能有项目当前不可用，请按你认为安全的方式处理。

**可选取消观察**：当参加者已经打开恢复预览但还没有最终执行时，主持人只说：“如果你还不准备执行，可以在这里停止；如果准备执行，请继续完成任务。”不指出取消按钮。若参加者选择停止，记录其是否能确认没有发生恢复；若选择执行，记录预检、跳过、失败和最终计数。

**结束状态**：U4-A 按保存顺序恢复可用文档，已打开项不重复，参加者能确认恢复完成；U4-B 能看见或理解缺失/跳过/失败，并在可用项仍可恢复时完成可用部分，或明确安全地取消。若宿主跨端行为未取证，标记环境限制，不扩大结论。

**记录重点**：是否先查看影响范围；恢复、取消、确认和重试的词义；缺失项如何被发现；成功、失败、已打开跳过和缺失跳过计数是否被理解；恢复后是否回到预期文档和现场。

### U5：片段修改后取消或保存

片段实验室只在桌面夹具执行，使用两个独立的禁用 CSS 练习片段；不启用脚本，不调用在线 AI 或 Gist。取消分支和保存分支的顺序在参加者之间交替。

**U5-A 取消分支提示**：

> 请在这个练习片段上做一个小的外观修改并预览，然后让这次修改不写入保存结果，回到可以继续工作的状态。

**U5-B 保存分支提示**：

> 请在另一个练习片段上做一个小的外观修改并保存；完成后重新查看它，确认保存结果仍然可以找到。

**结束状态**：U5-A 原保存内容保持不变，草稿被取消、放弃或安全离开，且没有误启用；U5-B 保存请求完成并能回读同一修改，参加者能区分草稿、保存结果和是否启用。主持人通过夹具的保存前后快照核对，不把“看起来变了”当作写入成功。

**记录重点**：新建/选择片段的入口；预览与保存的顺序；脏稿守卫和取消文案；保存失败、重试或冲突时的理解；是否误以为预览等于启用；是否需要主持人解释 CSS 近似、实际主题和 JS 不执行边界。

### U6：首次添加一个工作台组件（补充观察）

本项不计入五条主路径的独立成功数，用来观察首次接触组件商店和工作台的理解成本。不同参加者可从同一组夹具中自由选择，主持人不指定某个组件。

**参加者提示**：

> 请在工作台添加一个你认为有帮助的组件；完成后停下并告诉我。

如果参加者问“选哪个”，只回答：“请选你认为合适的；如果某个组件当前不可用，可以换一个或停下，我会记录你的决定。”

**结束状态**：参加者添加了所选组件并能在工作台看到它，或正确识别当前条件不足而停止。组件确实需要配置、插件或外部服务时，保留实际状态，不要求参加者绕过前置条件。

**记录重点**：首次入口是否可发现；是否查看来源、隐私、联网或前置条件；预览和尺寸选择是否可理解；“添加”后的反馈、布局位置和回到工作台的路径；不可用状态是否被误解为故障或被当成已添加。

## 5. 单次任务记录表

主持人每项任务单独填写一行或一张纸。`Pxx`、任务代码和序号可以进入仓库；标题、正文、路径、查询原文和任何账号信息不得进入仓库。

| 字段 | 填写方式 |
| --- | --- |
| 参加者 / 任务 | `P01 / U1`；必要时加 `A/B` 分支 |
| 环境摘要 | 版本、端侧、OS 类别、缩放类别、主题、认证状态 |
| 结果 | `I/N/A/P/F/X/NA` + 一句可核验结束状态 |
| 相对耗时 | `t1 - t0`；超时写实际值和停止原因 |
| 首次动作 | 只写动作类别，不写标题或正文 |
| 动作序列 | 以箭头连接 3～10 个主要动作；更多动作写“继续操作”并保留原始纸笔记录 |
| 卡点 / 误点 | 参加者停顿、走错入口、重复操作或主动询问；尽量使用参加者原话但先脱敏 |
| 恢复 | 清除、返回、重试、取消、换入口、放弃或主持人帮助；标明是否恢复到目标 |
| 观察证据 | 夹具 ID、界面状态或脱敏截图编号；不得附敏感内容 |
| 参加者原话 | 仅在同意记录时逐字摘录，去除人名、标题、正文和路径；没有原话写“未记录” |

每个会话结束后另记：参加者主动提到的最不确定一步、最容易确认的一步、期待的恢复动作，以及仍未理解的词。不要要求打分，也不要把主持人的解释写成参加者观点。

## 6. 会话结束和匿名汇总

结束时询问以下开放问题，顺序可调整：

1. “刚才哪一步最需要你停下来想一想？”
2. “你如何判断任务已经完成、保存成功或没有发生恢复？”
3. “如果刚才再遇到一次失败，你希望界面下一步告诉你什么？”
4. “哪些词、状态或入口让你不确定？”

不要把“你是否喜欢这个功能”“是不是应该有某某按钮”作为默认问题；这类问题会把主持人的方案带入反馈。参加者没有意见时写“未提及”，不要补写推断。

只在会话结束后汇总脱敏事实：每项任务的结果代码分布、耗时原始值、动作序列、卡点和恢复方式。汇总前保留每一项原始记录，以便区分独立完成与接受帮助后的完成。样本不足时写“样本不足”；没有真人记录时写“脚本已准备，尚无真人反馈”。不计算或发布没有实际样本支撑的成功率、改善幅度、平均值、p50/p95 或“用户普遍认为”。

## 7. 与自动化验证的关系和建议

自动化只能证明代码契约或夹具状态，不能证明参加者看懂了入口、状态或恢复文案。执行真人会话前建议在同一提交上按改动范围运行现有定向测试，并把命令和结果放在会话旁证中：

- 切换、键盘、搜索和失败回退：`tests/keyboard-navigation-contract.test.cjs`、`tests/doc-search-fetch-behavior.test.cjs`、`tests/doc-search-state.test.cjs`、`tests/search-orchestration.test.cjs`；
- 收藏、最近打开/关闭：`tests/favorite-actions.test.cjs`、`tests/recent-history.test.cjs`、`tests/recent-closed.test.cjs`；
- 文档集预览、顺序、跳过和取消：`tests/document-sets.test.cjs`、`tests/document-set-diff.test.cjs`、`tests/agent-outline.test.cjs`；
