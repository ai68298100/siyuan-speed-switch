# 调研-吸收循环 · 第 2 轮报告（2026-09-23）

> 三路并行：CJK/拼音搜索专项、导航交互复扫（Obsidian 新星/Notion/Craft/Tana/Android 搜索中心启动器）、思源生态增量复查。许可纪律：GPL（omnisearch）不移植；tiny-pinyin（MIT）允许 vendor 进源码自维护。

## 1. 最重要的发现：拼音搜索是速切的差异化空白

- 思源官方 2024-03 关闭了 issue #10489"搜索支持拼音首字母查询"（结论"实现不了"），官方建议手工写拼音进文档别名——**内核层无拼音，插件层是唯一路径**。
- Notion/flomo/微信公开资料均未见拼音首字母检索——做了即是差异化。
- 选型：**tiny-pinyin（MIT，~300 行 + 6763 常用字小字典，gzip 3.5KB）** vendor 进源码自维护（上游 2021 年后停更，消除供应链疑虑）；pinyin-pro 全量 gzip 157.8KB（仅 match 也要 80.9KB）必爆 960KiB 预算，不进 bundle，仅允许 CDN 动态加载形态作为可选增强；fuse.js 的 bitap 对 CJK 退化不用；WASM/原生一律不用。
- 多音字策略：tiny-pinyin 不支持多音字——L0 朴素子串层天然兜底（输入汉字仍直接命中），接受纯拼音下极少数漏召并在设置说明。

## 2. 分层匹配设计（全部客户端过滤层，内核查询不动）

- **L0**：现有朴素子串（汉字输入直命中，兜底多音字）。
- **L1 首字母**：查询为纯 ASCII 时，标题逐字取拼音首字母拼接做子串匹配（`cp` → 产品）。
- **L2 全拼/混合**：纯 ASCII 查询同时用全拼串匹配（`chanpin` → 产品）。
- 接入点：`search-model.js filterOpenTabs`（本地页签）与标题过滤路径；运行时转换 + Map 缓存（signature 失效：rootId+title+updated），不做持久化索引；20000 篇规模一次性转换在几十 ms 内且只算一次。
- 工具链拼音索引：待 T-6805 落地后评估是否需要。

## 4. 生态与竞品态势

- **番茄工具箱 v5.15.2 起 MIT 转专有许可**（个人免费、禁再分发/商用需授权）——开源速切在生态位上出现差异化窗口；其"悬浮球绑定文档窗/最近在读/保留悬浮球"交互与速切悬浮球正撞，交互文案与设置分组值得审视借鉴。
- 熊猫导航 0.9.2 无 open issues；书签+ 休眠（7 个月未动）；Cursor Focus 安静；官方 v3.8.5 无文档导航/搜索/悬浮球新功能，不构成冲突。
- R1 后新上架 11 个插件与速切零重叠；速切在榜 v0.30.1、2★、窗口内 0.19.0→0.30.1 正常迭代。
