# 设计原型审查报告（2026-09-27，T-6929）

> 审查对象：`docs/design/platform-ui-redesign-r2-2026-09-26.html`（R2 三表面全屏基线，现行布局准绳）、`docs/design/platform-ui-redesign-2026-09-26.html`（R1 26 屏：设置 11 标签 / 对话框 6 组 / 移动端 3 屏 / 明暗对照）、`docs/floating-ball-ui-spec.md` 及 `docs/design-system-v1-2026-09-27.md`（规范 v1）。
> 审查维度：① 信息层级与布局 ② 交互流程 ③ 跨页视觉与交互一致性 ④ 控件与文案易用性 ⑤ 异常与边界状态覆盖。
> 优先级口径：**高** = 误导用户、语义冲突或核心流程的异常态缺失；**中** = 一致性、可发现性、文案可信度；**低** = 抛光与补全。
> 结论先行：原型整体质量高（状态语言、卡片层级、设置三元组、kbd 可见性均达标），但有 **4 个系统性缺口**：数字 kbd 直达语义冲突、异常态屏幕成片缺失、主色胶囊纪律在列表/AI 场景被打破、跨表面控件（关闭/尺寸模式/回执条）不齐。共 **38 条建议：高 11 / 中 18 / 低 9**。

---

## 0. 做得对、应保持的部分

1. 六态徽标 + 回执条的状态语言在三表面与设置页同形出现（ADR 0079 落地）。
2. 设置页"组卡 + 行三元组（标题/描述/控件）"与枚举分段化，是全部标签页的统一骨架。
3. kbd 提示从文档走进界面（上下文栏、行尾、对话框底部），符合键盘优先原则。
4. 层级靠边框 + 留白、hover 才浮起，阴影纪律执行良好；明暗两主题仅靠 `--b3-*` 派生即成立。
5. R2 全屏布局的取舍（已开页签占主视野、组件完整渲染、预览为主区）方向正确，符合"高频内容给足位置"的用户反馈。

### 9.2 建议的落地顺序

1. **第一批（设计补屏，无生产代码）**：S4 + W1 + W2 + L2 + L3 + M2 的**异常态屏幕包**（约 10 张状态屏，补进 R2 基线原型或单独 `docs/design/states-*.html`），同步把 G3 例外条款、L1 文案、S1 数字 kbd 规则写进规范 v1.1。
2. **第二批（原型对齐生产）**：F2（三手势设置屏）、S3（过滤 chips）、P1（组件面板标签取舍）、G1（关闭按钮）、G2（尺寸模式统一）——这些是"原型落后于生产/互相打架"的修正，成本低、防漂移收益高。
3. **第三批（交互补强）**：S1 数字 kbd 语义、P3 收藏选择器、P4/D2 确认屏、F1 拆行——涉及小量生产改动的随对应功能批捎带。
4. 全程纪律：任何规范修订走 ADR；涉及契约的改动按 `docs/gate-audit-checklist.md` 负向验证；真机观感继续按 B-004/B-005 后置。

### 9.3 须用户裁决的两处方向

- **P1**：设置页是否补第 11 个"组件面板"标签（原型有、生产无）？建议补实现（三行设置已有原型，成本低），否则改原型。
- **S1**：行级条目是否保留数字直达？建议不保留（数字只属于页签网格），若希望行级也可直达，需接受修饰键方案（Alt+数字）。
