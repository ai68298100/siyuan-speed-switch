# R18 面板与组件商店交互调研（2026-10-09）

本轮把用户反馈中的“第三面板片段选择、第二面板质感/商店层级、无限画布参考”拆成可验证的交互问题。参考资料只用于提炼交互模式，不把竞品能力当成本插件已经实现的功能。

## 结论

1. 第二面板的高级材质并非在合并时丢失，而是后加载的 `_11-ui-polish.scss` 为了统一三面板外观把工作台单元格的阴影、景深和大圆角归零。此次恢复为 token 化的圆角、阴影和景深，并保留组件自己的色彩层。
2. 组件商店原本在右侧实时预览后再挂一张完整详情卡，形成双预览和重复动作。详情现在只抽取标题、元信息、唯一实时预览和尺寸/动作区，移动 sheet 也复用同一层级。
3. 片段选择器已有编辑区启停按钮，但目录条目只能先选中再到下方操作。参考 [TCOTC/snippets](https://github.com/TCOTC/snippets) 的启用/禁用、搜索和 CSS 预览路径，目录原生片段增加并列的就地“启用/停用”按钮；按钮复用原生整表写入和回读确认，不嵌套在选择按钮内，脏稿存在时明确阻止绕过保存守卫。
4. 未找到可靠的官方仓库或市场条目证明有正式名为“ObsidianArchive”的无限画布插件。可核验的相邻模式是 [Obsidian Canvas](https://obsidian.md/help/plugins/canvas)、[JSON Canvas 规范](https://github.com/obsidianmd/jsoncanvas/blob/main/spec/1.0.md)、[Visual Notes](https://community.obsidian.md/plugins/visual-notes) 和 [Advanced Canvas](https://community.obsidian.md/plugins/advanced-canvas)。因此本轮不把第二面板贸然改成自由画布，而是先修复网格工作台的可读层级和商店拖入/动作基础；自由编排、小地图、归档恢复作为独立后续任务。

## 可借鉴的交互模型

| 来源 | 借鉴点 | 当前落点 |
| --- | --- | --- |
| TCOTC/snippets | 目录内直接启用/禁用、搜索后保持状态、CSS 预览 | 第三面板目录原生条目并列启停按钮、失败回执和脏稿守卫 |
| Obsidian Canvas / JSON Canvas | 节点、边、分组、缩放、只读演示和可恢复文件格式 | 先保留现有 12 列网格；未来以场景数据和只读预览逐步增加自由编排 |
| Visual Notes | 归档/恢复、标签筛选、卡片化笔记和小地图 | 组件归档/恢复、聚焦与小地图列为 P1，避免本轮引入未验证的持久化格式 |
| Miro / Milanote | 拖入工作区、模板、上下文工具条、视觉分组 | 商店详情动作区与工作台层级先落地；模板/拖入动作待独立契约 |

## 取舍与后续

- 默认工作台继续使用 12 列网格，保证组件信息密度、滚动和现有撤销/重做语义。
- 后续若实现自由编排，必须与网格模式共存，并具备场景保存、只读预览、聚焦选中、键盘移动和窄屏降级；不得直接替换现有布局数据。
- 组件商店后续优先补“拖到工作台”“选中上下文操作条”“归档/恢复”和“空态模板场景”，每项单独记录最终状态回执。
